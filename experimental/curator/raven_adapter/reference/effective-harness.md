# Understanding the effective harness

## One current instance

Plain Raven, a prepared product and a generated revision use the same inspection. Read the current effective composition; do not reconstruct it by replaying all historical plans. A previous plan states intent. Assembly, invocation and observed effects are separate evidence.

`native_modules` identifies Raven's concrete runtime components. `mechanisms` connects current component paths and registered sources to semantic responsibilities and interaction channels. A native Planning component that passes messages through does not imply that no tool or hook maintains a plan. Public Strategy implementations, native modules and responsibility coverage are distinct.

## References and authority

A mechanism's component path uses the same sections and path elements as read_fact. Its source keys identify registered, digest-checked materials. In workflow curation, source reads return snapshot paths that native file and search tools can follow into supporting packages. The exploration description lists the actual material roots. Missing or unclassified behavior stays an explicit gap; inspect affected mechanisms before designing around it.

Mechanism target links refer to the current declaration. They are not additional permissions. Current behavior and state remain understandable even when their modification is not granted. New capabilities that the host supports may be selected even when they are not yet installed.

## Composition and revision

Generated strategies may coexist with native tools, hooks and resources. State ownership, execution order and consumers determine whether they cooperate or conflict. Adding a PlanningStrategy does not automatically replace code-flow's todo mechanism or provide access to its session store.

An omitted target preserves its existing authored binding. Artifact.remove explicitly retires selected, currently authored bindings; it does not remove arbitrary native components. Plugin operations use the declared configuration contract and may affect every contribution of a plugin. Managed content retirement restores the value captured before its first curation change; conflicting outside edits cause refusal. Task state and external side effects are not implicitly erased.

Inspect the new effective instance after successful installation. A failed candidate remains diagnostic history. New task facts or feedback start a fresh curation input; resuming a budget pause requires the original input identity and source snapshot.

## Prepared product modes

Product rendering prepares configuration, resource seeds and plugin roots. It does not make an experimental Worker equivalent to an ACP server. A selected mode is resolved by the native catalogue and applied through session policy. Its cap, effort and overlay can override connection defaults. Use turn_profile and execution observations when reasoning about these settings.
