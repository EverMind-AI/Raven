# 编辑与演示领域模式

只读取当前合同需要的章节。本文件保存编辑结构与检查模式，不拥有共享治理、工具事实、通用渲染或 release。模式是候选，不是必须凑齐的页面清单。

## 1. 媒介合同卡

先为每个消费者填写：

| 字段 | 问题 |
| --- | --- |
| `contract_id` | 这是分页出版、现场演示、连续长文、报告自动化还是可访问 PDF 叠加合同？ |
| `consumer_task` | 消费者需要跟随、查找、引用、携带、重建还是用辅助技术读取？ |
| `context` | 观看距离、时间、设备、纸张、装订、网络和协作环境是什么？ |
| `content_authority` | 哪个 owner 决定文案、数据、来源和资产状态？ |
| `layout_authority` | 哪个原生母版决定此消费者的排版？ |
| `required_capabilities` | 需要哪些母版、样式、notes、reflow、引用、构建或标签能力？ |
| `deliverables` | 原生源、派生输出和交接包分别是什么？ |
| `claims/non_goals` | 本合同要证明什么，明确不证明什么？ |

混合交付必须逐消费者填卡。两个消费者若编辑者、阅读任务、导航或信息密度不同，就不能用“同一画布”合并合同。

## 2. 内容 authority 模式

### Claim/data ledger

每项可核验内容至少记录：

`id / exact value or text / unit / definition / source locator / version-date / status / owner / allowed transformations / target modules`

状态只使用合同已定义的有限集合，例如 `verified / provided / estimate / simulated / missing / restricted`。视觉强调不得改变状态；缺失值不得被占位数字、生成图片或“合理推测”填充。

### Asset/rights ledger

每项图片、插画、图表源或字体至少记录：

`asset id / semantic role / source / author / license or consent / allowed media / crop-focus / resolution / alt-text need / status`

图像职责分为证据、说明、比较、定位、情绪和节奏。合成或生成图像若可能被读作真实人物、地点或事件，不得承担事实证明职责。

### Authority 分层

- `content authority`：拥有文案、数据、引用、版本和缺失状态。
- `asset authority`：拥有原始资产、权利和允许的处理。
- `layout authority`：每个消费者各自的原生母版。
- `derived outputs`：PDF、PNG、静态站、讲义、截图与 Gallery 预览。
- `review index`：contact sheet 或对照板，只帮助检查，不拥有内容或布局。

## 3. 编辑脊柱

### 判断 → 证据 → 决定

用于决策简报和方案推荐：界定决定，建立影响对象，逐项证明关键差异，说明限制与取舍，最后绑定责任、资源、时间和下一次复核。

### 问题 → 发现 → 重构

用于观点演讲和调查长文：从具体矛盾进入，让证据改变原先理解，设置真正改变判断的转折，再以新理解返回开篇对象。

### 时间／过程推进

只保留改变状态的节点；标出因果、等待、分叉与并行。若删除一个时间点不改变理解，则合并而不是继续添加刻度。

### 对照 → 取舍

先冻结共同基线、单位、范围与缺失规则；每次只比较可比变量；说明收益、代价、不可比项与建议，不让颜色替作者下结论。

### 浏览／查找

按读者的真实查找问题组织互斥分组；稳定字段顺序和返回路径；允许重要条目获得更多篇幅，不用线性戏剧覆盖查找任务。

## 4. Flatplan 与页／屏职责

每个自然单位记录：

| 字段 | 内容 |
| --- | --- |
| `unit_id` | 稳定引用、顺序及所属合同 |
| `primary_job` | 提出、证明、解释、比较、导航、查找、转折或决定 |
| `claim/question` | 第一眼必须理解的主张或问题 |
| `evidence_object` | 承担证明的正文、图像、图表、表格或引语 |
| `before/after` | 承接什么，把消费者送往哪里 |
| `density/time` | 阅读密度或讲述时间预算 |
| `visible/notes` | 屏上、正文、讲者备注、附录分别承载什么 |
| `source/status` | 来源、事实状态、权利和限制如何出现 |

检查：只读标题和导航能否复述主线；相邻单位互换是否无损；主张是否由同页/邻近证据支持；物理页面是否被错误强迫成每页一个戏剧转折。

常见职责候选：封面、目录/导览、章节门、主张、场景、图像证据、数据证据、方法/限制、对照、行动、附录/来源。只为真实职责建立母版。

## 5. 分页出版模式

- 从成品尺寸、方向、装订、出血、正文行长、脚注和图表宽度推导网格，不默认十二栏或屏幕比例。
- 用 parent/master page、段落/字符/对象/表格样式、文本串流、自动页码、目录与交叉引用建立系统；逐页复制不算母版。
- 对页同时检查中缝、翻页前后关系、单页被截取后的定位信息和跨页对象风险。
- 信息册先制作纸张或页序 dummy；高频查找字段保持稳定位置，封面、目录、索引和返回路径共同工作。
- 先排最长标题、最密正文、复杂脚注、宽表、横图/竖图和缺图状态，再扩全书。
- contact sheet 检查页型节奏；高密、低密、图像、表格和转折的变化必须来自职责。
- 印刷输出检查实际成品尺寸、页数/书帖、装订、安全区、字体、链接资源、有效分辨率、色彩/输出意图及供应商合同。

## 6. 现场演示模式

- 一页可以承载一个主张或一个不可拆比较；“一页一个观点”不是禁止必要共视。
- 记录每页预计时间、必须口述、可略过、转场句、讲者备注和必要附录。
- 远距第一层是主张与主要对象；限定、来源和模拟状态仍须可见，不得依赖会后微字修复现场误读。
- slide master/layout、theme、placeholder、notes 和阅读顺序属于原生结构；复制幻灯片或图片化导出不是可编辑母版。
- 代表 proof 覆盖最远座位、最差投影、最密数据页、长标题、必要媒体和一次跳页/回退。
- 讲义或会后报告承担独立阅读时，另立合同；不要向投影页继续添加正文来同时满足两者。

## 7. 连续长文模式

- 语义顺序写入内容结构，不依赖某一画幅中的左右位置才能理解。
- 章节标题、目录/锚点、当前位置和返回路径服务连续阅读；sticky、snap 与滚动动效不得阻断自然阅读或打印。
- 图注、边注、比较和表格在窄屏重新确定邻接关系；不能只把多栏纵向堆叠或缩小成截图。
- 对最长标题、最密图表、复杂表格、脚注和来源执行最窄/典型/最宽检查。
- 若任务包含持续发布、栏目发现、搜索、订阅或 CMS 编辑工作流，停止并路由内容网站领域。

## 8. 报告自动化模式

- 权威 bundle 包含可执行文档、数据、引用库、模板、字体/资产和锁定环境；生成的 HTML/PDF/DOCX 是 derived。
- 计算值、正文引用、图表和表格必须从同一数据 authority 派生；禁止复制结果到版面后独立维护。
- 每种输出拥有格式专属配置；共享内容源不授权共享同一密度、导航或图表注释。
- capability proof 至少替换一个 claim、数据值和引用后重建，核对所有依赖消费者、交叉引用、页码和 hash。
- 自动构建稳定不证明编辑取舍、视觉质量或统计结论正确；分别检查编辑结构、最终画面和数据证据。

## 9. 可访问 PDF 叠加合同

- 上游语义母版应拥有标题层级、段落、列表、表格、语言、图像替代文本、阅读顺序和 artifact 标记；优先在源中修复后重导出。
- 自动标签、机器 validator 或 Acrobat 修复均不能单独证明语义正确；机器检查与人工阅读顺序/替代内容检查分别记录。
- 验证书签、目录、链接目的、页码、metadata、Unicode 映射、表格表头、图形描述及颜色之外的冗余表达。
- 复杂图表需要文字等价物；装饰对象应从语义树排除；图片文字不能替代活字内容。
- 只在实际导出和验证了约定标准时声明 PDF/UA、PDF/A 或 tagged PDF；“PDF 可搜索”不是可访问证据。

## 10. 图文与排版判断

为每个视觉对象回答：`回答的问题 / 第一眼对象 / 与哪段内容相连 / 来源与权利 / 所以呢 / 各消费者如何变化`。回答不全则删除、补证据或后移。

- 层级先使用尺度、字重、位置、对齐和空间；必要来源、状态和限定不得被降成低对比微字。
- 字体角色从媒介、语言、距离和内容产生；用真实最长/最密内容测试，不为“编辑感”制造多余角色。
- 图表一图一问，保持尺度、单位、范围、直接标签、来源和不确定性；演示与报告可改变注释密度，不能改变事实。
- 表格服务精确查找与比较；跨页保留表头和续表语义，窄屏重组时保留字段对应关系。
- 空白、装饰和表现性可以承担停顿、情绪、文化或识别；只有职责不可观察或与核心任务竞争时才删减。

## 11. Representative proof 选择

按风险选择最小充分纵切片，不按固定页数：

- 能证明入口与总体语气的单位；
- 最常见的典型单位；
- 文字、图表、脚注或资产最密的单位；
- 最容易暴露工具能力或母版传播问题的例外单位；
- 每个额外合同中最能证明其不是机械缩放的片段。

Proof 必须使用真实内容或明确状态的 fixture，并在目标消费者中检查。只有 hero 或封面不能晋升多页系统。

## 12. 症状与失败返回

| 症状 | 常见根因 | 回到哪一步 |
| --- | --- | --- |
| 同一画布声称兼任演示、报告和另一种消费环境 | 消费者合同未分开 | 自然媒介 |
| 结论、数字或图片来源互相矛盾 | 内容来源分裂 | 内容状态 |
| 页面互换无损、章节门只放大编号 | 内容脊柱或页面职责未设计 | 内容脊柱 |
| PDF/截图被当作编辑源 | 母版或工具选择错误 | 专业工具 |
| 页面一致但只能逐页手改 | 没有真实母版/样式绑定 | 专业工具 |
| 每页都是大标题、卡片或同一模板 | 代表页型没有覆盖真实风险 | 代表页型 |
| 灰色微字承载来源、限制或下一步 | 层级通过隐藏信息伪装成立 | 编辑视觉 |
| 另一消费环境只是缩小页面或纵向堆叠 | 消费者没有原生适配 | 媒介派生 |
| 内容更新后部分输出仍是旧值 | 派生关系没有统一来源 | 母版与派生 |
| PDF 机器检查通过但阅读顺序错误 | 把 validator 当成语义判断 | 最终消费者检查 |
| 自检被描述成专业视觉通过 | 证据措辞越界 | 完成检查 |

返回最早被证伪的假设并保留无关的已通过证据；不要通过增加页面、装饰或说明文字修补治理标签。
