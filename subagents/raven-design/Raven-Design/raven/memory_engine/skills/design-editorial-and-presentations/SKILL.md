# 编辑与演示设计

## 核心目标

把材料编辑成可讲、可读、可定位、可引用并可继续维护的发布物。质量来自内容顺序、字体关系、
图像职责、版面节奏和媒介适配，不来自更多卡片、边框或模板。

按以下顺序工作：

```text
读者任务 → 自然媒介 → 内容脊柱 → 视觉系统与专业工具
        → 代表页型 → 完整序列 → 各媒介终态
```

本 Skill 决定编辑结构、自然媒介、出版工具和领域质量。最终由浏览器消费时，与
`$build-polished-visual-frontends` 组合；它负责 Web 实现和视觉系统，本 Skill 继续拥有内容顺序、
页型和出版语义。通用安全、渲染、review 与交付沿用 `$visual-artifact-design`，不在这里重复。

## 1. 先选择自然媒介

按读者如何使用内容选择主合同，不按文件扩展名选择：

| 主合同 | 用户行为 | 自然母版 |
| --- | --- | --- |
| 分页出版 | 翻阅、查找、携带、引用或印刷 | 分页源、母版、样式和文本流 |
| 现场演示 | 在限定时间和观看距离内跟随讲述 | slide master、layout、notes 和放映状态 |
| 连续长文 | 在屏幕上阅读、定位、返回和重排 | 语义内容源、长文布局和稳定锚点 |
| 自动化报告 | 从数据、引用和参数反复重建 | 可执行文档、模板、数据和锁定环境 |
| 可访问 PDF | 使用辅助技术读取结构化 PDF | 上游语义母版与验证/修复管线 |

混合交付可以共享内容模型，但不能强迫共享同一布局。印刷跨页、连续阅读和投影演示分别设计，
只保持内容事实、顺序关系和视觉身份一致。

持续栏目、搜索、订阅或 CMS 运营转内容网站；自由筛选和数据发现转数据可视化；持续编辑、审批和
持久状态转产品工具；单张传播转营销图形。

## 2. 开工前写一张编辑卡

只记录会改变成品的决定：

```yaml
读者与场景: 谁在何时阅读、观看或查找
主要任务: 读完或看完后应理解、找到或决定什么
媒介: 主合同、尺寸、页数或时长、设备和交接格式
内容脊柱: 论证、时间、对照、过程或浏览结构
内容状态: 已提供、可核验、缺失、受限和不得推断的部分
视觉方向: 真实参考、字体关系、图像角色、密度和节奏
专业工具: 候选、选择理由、原生母版和明确不用的方案
代表页型: 最能暴露方向、密度、资产或跨媒介风险的画面
```

来源、权利、版本、工具比较和构建记录属于内部 evidence，不是默认的版面内容。成品只显示读者为
理解当前内容所需的来源、状态和限制；详细账本放入交付说明、附录或按需展开，不把治理过程做成
横幅、卡片墙和灰色微字。

## 3. 分别选择视觉系统与专业工具

先确定编辑视觉系统：字体家族和角色、网格、版心、图像裁切、标题节奏、颜色职责、页码与导航。
再选择能原生承担媒介能力的工具。两者必须在代表页型中共同成立，工具默认模板不能自动成为设计。

| 任务与约束 | 优先考察 |
| --- | --- |
| 精细分页、品牌出版和专业印前交接 | Adobe InDesign、Affinity Publisher；开放格式可考察 Scribus |
| HTML/CSS 同源并同时需要分页 PDF 与 Web 阅读 | Vivliostyle；具体能力不足时再比较 Paged.js |
| 纯 PDF、结构化技术文档或高度可复现排版 | Typst |
| 数据、引用和多格式周期报告 | Quarto + Pandoc |
| 连续阅读的静态长文 | Astro/MDX 或现有内容系统 |
| 组织现场演示与可编辑交接 | PowerPoint、Keynote；浏览器技术演示可考察 Slidev |

这不是强制清单。先检查现有项目、接收方格式、语言与字体、自动化、许可、离线、印前和目标设备，
再查看真实样张（环境提供本地 visual catalog 时以其图版为准，可联网时看官方样张）并对最难页型
做最小能力验证。商业或 GUI 工具当前不可调用时，选择可用替代方案或
明确人工交接；不要声称使用了未实际运行的工具。

选定工具后采用它的原生结构：母版、段落/字符样式、文本流、notes、内容 schema、分页规则、交叉
引用和导出路径。不能只借它导出一次 PDF，再在另一套手写布局里维护真正的页面。

## 4. 先编辑内容脊柱

选择最适合读者任务的主结构：

- **判断 → 证据 → 决定**：决策简报、方案建议；
- **问题 → 发现 → 重构**：调查长文、观点演讲；
- **时间／过程推进**：历史、教程、项目复盘；
- **对照 → 取舍**：方案、产品或政策比较；
- **浏览／查找**：目录、指南、手册和图录。

为每个自然单位写一句职责：它提出、证明、解释、比较、导航、转折还是促成决定。只读标题和导航
应能复述主线；交换相邻单位若毫无损失，说明顺序还没有被设计。图表、地图、摄影和插画分别由相邻
领域保证真实性，本 Skill 决定它们在序列中的职责和邻接关系。

## 5. 先制作决定成败的代表页型

不要从封面一路机械铺到末页。先用真实内容或明确标记的占位状态制作最小充分纵切片：

1. 入口或封面，证明总体语气与识别；
2. 最常见页型，证明阅读节奏；
3. 最密页型，证明长标题、正文、图表、脚注或复杂资产；
4. 资产缺失、来源待补或其他真实例外；
5. 每个额外消费者中最能证明不是机械缩放的一段。

在真实纸张、投影距离、合同宽度或目标阅读器中查看最终像素。代表页型方向稳定后，再用母版和样式
扩展全序列；不要逐页复制和修补。

## 6. 编辑视觉质量

- 层级优先来自字号、字重、位置、对齐、空间和内容长度，不靠大量边框、底色和标签。
- 线条、色条、栏线、边框和角标必须服务网格、顺序、分组、导航或已锁定的出版身份；一次性标题
  竖线若删除后阅读关系不变，就是装饰。“强调重点”不构成编辑职责。
- 字体数量少而关系明确；用最长标题、最密正文、数字、标点和实际语言覆盖测试。
- 图像必须承担证据、说明、比较、定位、情绪或节奏；没有职责就删除。
- 页型差异来自内容职责。不要把每一页都做成大标题加三张圆角卡片。
- 不因“文化感、纸张感或生活方式感”自动采用米色、纸纹、细线框或低对比灰字。
- 必要来源、状态和限制贴近受影响内容并保持可读；不能缩小、变灰或塞进页脚，也不自动把它们放大
  成压过正文的横幅。视觉面积与叙事重要性相称，不与需求清单逐项等权。
- 连续长文保持语义顺序；合同环境变化时重新安排图文邻接和导航，不把印刷跨页机械纵向堆叠。
- 现场演示让主张和主要对象适合观看距离；讲义承担独立阅读时另立布局。
- 图像背景只在承担封面、章节开场或作品世界职责时使用；后续由同源图像、排印和网格延续，不把每页
  做成“背景图 + 半透明文字板”。CSS/版式工具负责排印、网格和必要分隔，不凭伪元素另造装饰资产。

## 7. 内容、资产与缺失状态必须真实

文案、数值、图像、字体和引用应有明确来源与状态。缺少事实、照片或权利信息时保留语义化缺口，
说明谁需要补什么；不要编造数字、来源、人物、地点或版权。占位状态也要服从编辑系统，不使用巨大
虚线框、图库图标和重复警示把缺失变成视觉主体。

自动化报告中的正文数字、图、表和引用必须从同一数据来源派生。PDF、截图、Gallery 缓存和网页预览
都是派生物，不能反向成为内容或版式母版。

## 8. 完成检查

- 内容顺序能支持读者任务，页面或屏幕不是可任意互换的模板；
- 视觉系统和专业工具都真实使用，并在字体、颜色、间距、图像和输出上形成一种语言；
- 完整序列覆盖典型、密集、缺失与例外页型，没有逐页漂移；
- 每种合同媒介在自己的最终消费者中验证，浏览器预览不替代印刷、放映或 PDF 结构检查；
- 最终输出晚于最后一次可见修改，并可从母版重新生成；
- 没有独立 reviewer 时只标记 `SELF_REVIEW_ONLY`，不声称编辑、视觉或无障碍已获外部通过。

需要更细的页型、叙事和媒介检查时读取 [领域模式](references/patterns.md)；需要比较工具能力时读取
[工具能力档案](references/tool-profiles.md)，只加载当前任务相关章节。
