# 构建游戏与趣味体验

本 Skill 拥有二维游戏的玩家合同、领域 gate、专业 claim ceiling 与失败返回；通用 authority、
tool-use、渲染、review、promotion 与交付规则沿用共享视觉底座。

成功不是页面会动或测试全绿，而是玩家通过公开输入改变规则状态、看懂因果、获得下一次有意义行动，并能按合同停止、恢复或返回。工程证据只能证明其实际覆盖的技术事实。

## 1. 路由与合同

先声明任务模式。**Create** 建立新的玩家合同、原生母版与交付；**Edit** 只改变授权范围并重跑受影响 gate；**Diagnose/Audit** 只复现、读取和归因，不把诊断默认为修改授权。

选择一个主子型；混合形态要说明主从关系：

- **二维规则/动作/益智**：价值来自决策、执行、发现约束或掌握。
- **互动玩具**：价值来自持续介入、材料反馈、组合和表达，不强造胜负。
- **叙事探索**：价值来自移动、观察、选择及世界回应，不是被动翻页。
- **节奏体验**：价值来自输入与统一时间基准的关系。
- **生成体验**：价值来自受约束变化、种子、定格或可比较结果，不是随机噪声。
- **本地多人**：价值来自共享设备前的轮流、同时操作或协商；线上权威状态不在本版能力范围。

主要价值若是理解模型，转交交互解释器；若是编辑、管理或导出工作结果，转交产品工具界面；若是观看场景，转交插画与视觉场景。积分、徽章、动画和开始按钮不构成游戏。

本版只覆盖二维。三维只可路由到 `unity-3d-runtime-future`、`unreal-engine-3d-runtime-future`、`godot-3d-runtime-future` 或 `blender-3d-content-future`：这些 profile 尚未验证，必须停止三维能力声明并返回工具选择或人类交接，不能用二维证据外推。

动手前同时锁定两份合同：

- **玩家合同**：受众与真实设备、主要动词、核心循环、最低完成/主动停止、失败与恢复、返回价值、输入方式、内容规模、音频职责、可访问性风险、平台预算、目标 claims 与明确非目标。
- **交付合同**：最终消费者、真实消费设备/渠道、目标 renderer 或运行时、权威母版、交付格式、来源与许可、重建入口、最终像素或最终验收方法，以及各自不支持的 claims。

保持介质中立：由最终消费者决定浏览器、原生运行时、安装包、街机/展陈设备或其他二维媒介，不因可网页预览就预设 HTML、Canvas、固定比例或应用外壳。非网页媒介必须在目标 renderer、设备或物理环境中验收；浏览器截图、DOM、Gallery 和网页 wrapper 不能冒充其最终消费者证据。

只有最终消费者明确是 Web 时才加载 `$build-polished-visual-frontends`，由它补充 Web 技术栈、响应式和最终网页视觉执行；非 Web 主交付不加载该 Skill。本 Skill 始终拥有玩家合同、规则和领域 gate。

验证计划按 claim 和风险生成，不设固定人数、轮数、视口或阈值。音频启用/解码仅在合同包含声音时检查；存档/迁移仅在承诺持久化时检查；离线边界仅在承诺离线运行时检查。未触发项写明可验证的范围理由，不把未知、未实现或工具不可用写成 N/A。

## 2. 工具与 authority 接口

先从 [工具能力档案](references/tool-profiles.md) 将“子型 → 所需能力 → 具体工具 profile”写清。有 Registry canonical ID 时按其查询共享 Tool Registry；仅有 candidate ID 时按原 ID 查询并如实保留缺项。每次任务读取当前 Registry 与环境 probe，不在 Skill 缓存“已登记”或“可用”状态；Registry 缺项、未安装或需商业 GUI 时，分别记录 `candidate_unavailable`/治理记录中的 `unavailable` 或 `human_handoff`。

选定工具后，让其原生场景、显示树、资源、时间、输入、关卡、图层、轨道或导出模型成为实现结构；不要只借一个控件，其余重新手写。每个 concern 只能有一个权威 owner，至少区分规则/状态、内容/关卡、视觉资产、音频、输入映射和自动测试；截图、构建包与 Gallery 均为派生物。

工具只有具备版本与许可、真实调用、可编辑母版、重建/导出和当前 consumer/像素证据时才是 `used`。工具不可用只触发替代或交接，不证明它缺能力。

手写运行时、编辑器、渲染器、输入层或资源管线前，必须实际执行成熟候选的 capability probe；仅当结果为 `fail` 才记录 gap、最小自定义边界及数据/交互/视觉/导出一致性证据。偏好手写或环境未安装都不是 gap。

Create/Edit 若为证明专业工具的打开、编辑、导出或 round-trip 能力而必须写入，只允许在用户授权 workspace 内创建一次性验证副本；不得覆盖权威母版、最终交付或现有证据。记录原输入 hash、验证副本输出 hash、工具版本、调用、差异和保留/清理结果；正式交付另记母版与最终输出 hash。proof 只证明其覆盖的能力，不改变 canonical、release、promotion、lifecycle 或 positive pool。

Diagnose/Audit 一律零写入：只使用现有母版、构建、日志、hash 和最终证据，不创建验证副本、临时导出、截图或新报告，不修改源码、配置、派生物或治理记录。需要写入才能继续时，停止并请求 Create/Edit 授权。

## 3. 八个领域 gate

每个 gate 按共享格式记录 trigger、inputs、actions、evidence、claim ceiling 与 failure return；未知、未实现和工具不可用不得写成 `not_applicable`。细查项见 [领域模式](references/patterns.md)。

### `games.core-loop`

- **输入**：玩家合同、主子型、工具/authority 路线。
- **动作**：用公开输入做一条 `意图 → 判定 → 状态变化 → 反馈 → 下一行动 → 收束/恢复` 的代表纵切片。
- **证据**：最终消费者可消费的构建、公开输入轨迹、前后状态，以及来自目标 renderer/设备的对应最终像素或验收记录。
- **Ceiling**：只可声称该纵切片机械可玩；**失败返回**玩家合同或工具路线。

### `games.mechanics`

- **输入**：纵切片、规则模型、输入/时间/随机/存档边界。
- **动作**：验证合法与非法转移、暂停/失焦、终态锁定、重置、适用的种子/存档和重复事件。
- **证据**：规则测试、状态测试、公开输入自动化、只读事件日志和确定性快照。
- **Ceiling**：可覆盖机械与协议型 `internal-positive`；**失败返回**规则、状态、输入或时间 owner。

### `games.feel`

- **输入**：动作因果、目标设备、反馈与运动职责。
- **动作**：分开检查输入确认、规则结果、世界变化和收束；记录延迟、节奏、镜头、动画及降级。
- **证据**：输入到反馈时序、关键帧/录屏、当前像素；体验性措辞另需合格玩家或独立角色。
- **Ceiling**：自审只能证明反馈已实现且时序一致，不能声称“爽、灵敏、满足”；**失败返回**反馈映射或循环。

线、色条、边框、图标框、粒子和闪动必须属于世界规则、反馈、状态或导航，并与真实变化同步；删除后
玩家判断与行动不变，就是装饰，不能靠装饰 UI 制造“游戏感”。视觉面积、对比和运动按当前目标、
危险与反馈时机分配；限制说明邻近受影响机制，但不遮蔽游戏对象。CSS 只承担宿主布局、必要分隔、
真实状态反馈与成图裁切，不用渐变或伪元素伪造场景、角色或精致图标。

开场背景可以建立游戏世界，后续场景和 UI 通过同一资产家族、色光、形体与反馈延续；不要求每个
界面重复铺同一背景，也不把玩法压进“背景图 + 半透明文字板”。系列场景和表现型 icon 优先由同一
生成母图经 image edit 派生，不能改用手写 SVG/CSS 占位。

### `games.content`

- **输入**：关卡、规则数据、叙事、生成或难度 claim。
- **动作**：验证内容 schema、可达性、约束、种子及母版到运行时映射；宣称可迭代时用新增内容证明无需改核心规则/输入代码。
- **证据**：权威内容母版、验证结果、导入轨迹、代表内容与重建 hash。
- **Ceiling**：只证明内容管线和已测范围，不证明学习曲线、丰富度或复玩价值；**失败返回**内容模型或作者工具。

### `games.audio`

- **输入**：声音职责、时间模型、静音和替代通道；合同无音频时可有范围化 N/A。
- **动作**：验证音频母版、cue 映射、启用/解码、混音/循环、暂停恢复、节奏同步和关键信息替代。
- **证据**：可编辑工程或无损源、导出映射、运行记录、静音与失败路径。
- **Ceiling**：自审只证明技术映射，不证明音质、情绪效果或节奏感；**失败返回**音频 owner、时钟或反馈。

### `games.accessibility`

- **输入**：玩家合同中的输入、感知、运动、时间、认知和文本风险。
- **动作**：按风险验证替代输入、焦点/播报、非单一感官编码、reduced-motion、字幕/声音替代和可调压力。
- **证据**：公开替代路径、语义/状态检查、当前像素；有效性 claim 需要具相关需求的独立参与者。
- **Ceiling**：自审只能声称功能存在且机械可达，不能声称对目标人群有效或“完全可访问”；**失败返回**对应输入、反馈或合同。

### `games.platform`

- **输入**：目标设备、交付渠道、性能和生命周期预算。
- **动作**：验证生产构建、真实输入、显示缩放/像素密度、暂停/后台/失焦生命周期、资源失败、长期运行和适用的手柄/本地多人设备；只有 Web 才检查 resize、DPR 与页面隐藏。
- **证据**：最终消费者环境的运行轨迹、性能与故障记录、压力状态最终像素或设备验收，以及资源清理结果。
- **Ceiling**：只覆盖已测环境和路径；**失败返回**运行时、资源管线或平台范围。

### `games.player-value`

- **输入**：价值 claims，如理解、公平、乐趣、表达、发现、节奏感、共同玩耍、精通或复玩。
- **动作**：按 claim/risk 选择与目标玩家和真实设备相称的方法，观察首次进入、关键决策、受阻/恢复及承诺的返回行为。
- **证据**：绑定当前 build、claim、参与者角色、方法、行为观察和结果的独立 coverage。
- **Ceiling**：作者、自动化与 `SELF_REVIEW_ONLY` 均不能通过本 gate；无真人证据时只阻断对应价值 claim，**失败返回**合同、循环、教学、难度或反馈。

## 4. Claim ceiling 与交付

- `SELF_REVIEW_ONLY` 可支持当前 build 的机械、工具、重建和协议 claims；不得冒充视觉成熟、领域外部验证、好玩、公平、直觉、节奏感、可访问性有效或复玩价值。
- `internal-positive` 只容纳已通过 gate 的限定 `component` 或 `protocol` claims；缺少玩家证据时把价值事项写入 `not_evidence_for` 和 `excluded_claims`。
- `externally-validated` 只覆盖由合格且独立 reviewer/玩家对同一 build 明确通过的 claims；不得把一项体验结果推广到整个 artifact。
- 工程、内容、音频、可访问性和玩家价值互不代偿；一个 gate 通过不提升其他 gate、lifecycle、release、canonical 或 Gallery 状态。

交付时对账来源/许可、authority graph、输入与输出 hash、目标交付和最终消费者；从同一 build 在目标 renderer、真实设备或渠道取得最终像素/最终验收，不能以编辑器预览、早期帧或不匹配媒介的浏览器证据替代。每个可独立流通的交付都携带适用范围、限制与来源说明。

引用共享 promotion record，而不是另建游戏 maturity。Changed build 重新运行受影响 gate；保留未失效证据。proof、副本或新 hash 都不自动改变 canonical/promotion。即使普通原型可以带限制交付，也只有精确 scope、identity、pool、`positive_for`、`not_evidence_for`、`excluded_claims` 和 claim ceiling 均有证据时才能晋升。
