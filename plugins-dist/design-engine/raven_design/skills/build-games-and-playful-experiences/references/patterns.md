# 二维游戏与趣味体验模式

只读取与当前子型、风险和 claim 有关的章节。本文件提供领域模式与检查，不规定题材、美术皮肤、固定状态数、固定参与人数或统一阈值。

## 1. 子型路由

| 主子型 | 核心价值 | 最小闭环 | 主要风险 |
| --- | --- | --- | --- |
| 规则/动作/益智 | 决策、执行、发现约束或掌握 | 观察 → 行动 → 规则解决 → 局面改变 → 再决策/收束 | 隐藏规则、输入不可归因、难度只涨数值 |
| 互动玩具 | 介入材料并形成表达或发现 | 介入 → 即时变形 → 组合 → 定格/重置 | 只是背景动画、随机效果没有因果 |
| 叙事探索 | 方向、线索、选择与世界回应 | 发现 → 选择方向/关系 → 世界回应 → 新问题/节点 | 对话翻页冒充探索、卡住且无恢复 |
| 节奏体验 | 输入与统一时间基准的关系 | 预期 → 输入 → 时序判定 → 分层反馈 → 保持/恢复 | 多套时钟、无法校准、静音后丢失规则 |
| 生成体验 | 受约束变化、组合和可比较结果 | 设定/介入 → 生成 → 判断/编辑 → 定格/变体 | 无约束噪声、种子不可复现、结果不可保存 |
| 本地多人 | 同处玩家之间的轮流、竞争、合作或协商 | 建立共享局面 → 玩家行动 → 所有权/冲突结算 → 继续/离开 | 串控、身份含糊、假网络状态、离开后锁死 |

混合子型只保留一个主循环。若移除挑战、发现、表达、掌握或共同玩耍后，剩余价值仍是理解模型或完成工作，应返回领域路由。

## 2. 玩家合同

按实际范围记录：

```text
主子型 / 次要形态：
玩家、环境、设备与会话边界：
体验承诺与目标 claim：
主要玩家动词：
核心循环：意图 → 判定 → 状态 → 反馈 → 下一行动
最低完成 / 主动停止 / 失败与恢复：
返回价值：固定掌握 / 变化复玩 / 表达回访 / 叙事延续 / 社交复玩 / 无
规则、难度和公平风险：
内容规模、随机/种子、存档和隐私：
输入、音频、运动、文本与感知风险：
目标平台和性能风险：
明确不做与 excluded claims：
```

- 不强迫所有体验拥有分数、生命、关卡、失败或复玩。
- 若承诺复玩，写清再次进入会产生哪种新决策、技巧、内容、表达或社交关系；只刷新分数或重复固定答案不够。
- 若主题是体验承诺的一部分，执行机制换皮检查：移除名词和皮肤后规则若完全不变，返回合同，让空间、材料、角色或关系真正影响规则。纯抽象体验无需硬造主题。
- 把价值假设写成可观察行为，不把“好玩”“高级”“上瘾”当需求说明。

## 3. 核心循环、状态与输入

### 状态模型

- 规则模型拥有真实状态；场景树、HUD、粒子、声音和文本只投影它。
- 显式区分准备/教学、活动、暂停、设置/帮助、结果或等价停止状态；名称服从项目，不机械复制 `won/lost`。
- 当前状态拒绝不允许的事件；重复事件不得重复奖励、扣除、播音、保存或结算。
- 暂停、失焦和页面隐藏要说明规则时间、物理、生成、动画判定与音频调度如何冻结和恢复。
- 重置返回确定快照；随机体验记录种子和约束；存档只拥有合同承诺的进度并声明版本迁移。

### 输入模型

| 输入风险 | 设计边界 | 机械检查 |
| --- | --- | --- |
| 离散动作 | 按下边沿产生一次语义意图，区分真实连按和系统重复 | 多入口得到等价状态，不漏记、不重复结算 |
| 连续运动 | 每帧采样意图，以固定步进或受限时间差更新 | 降帧、失焦和恢复不瞬移或穿透 |
| 指针/拖拽 | 统一坐标、捕获、取消和 resize 映射 | 拖出舞台、多指针和取消后状态安全 |
| 触摸 | 声明滚动冲突、长按、多点和安全区 | 目标设备可完成主循环且关键动作不误触 |
| 节奏输入 | 单一高精度判定时钟，记录校准偏移 | 音画路径、刷新率和设备延迟假设可追踪 |
| 手柄/本地多人 | action map、玩家槽位、设备归属和热插拔 | 不串控；加入、离开、重连和暂停权限明确 |

自动化只能读取探针或事件日志，动作必须走公开输入；直接写内部状态只可用于规则单元测试，不能作为可玩路径证据。

## 4. 手感与反馈

把一次动作的反馈拆开检查：

1. **输入确认**：设备动作被系统接收。
2. **规则结果**：有效、受阻、失误、时序偏差或资源不足可区分。
3. **世界变化**：位置、关系、能力、内容或作品真实改变。
4. **收束反馈**：结算或庆祝发生在规则结果之后，不遮挡下一行动。

- 记录输入采样、规则生效和首个可见/可听反馈的时间链；不要只以动画看起来顺滑作为响应证据。
- 关键运动用预备、动作、接触和恢复表达因果；震动、闪白、粒子和慢动作只放大已存在的规则信息。
- HUD 只保留下一决策需要的信息，不能让指标和说明框占据主要游戏舞台。
- 降低特效、静音或 reduced-motion 后，状态、时序和结果仍必须可辨。
- 作者自审可证明反馈映射和时序实现；“灵敏、沉重、爽快、紧张、满足”等感知 claim 需要相称的独立玩家证据。

## 5. 内容、难度与迭代

| 内容 concern | 权威结构 | 检查 |
| --- | --- | --- |
| 规则参数 | 有 schema 的数据或引擎原生 Resource | 范围、默认值、迁移和非法值处理 |
| 关卡/地图 | 原生关卡母版、实体/对象/碰撞层 | 可达性、边界、对象语义和导入映射 |
| 叙事 | 节点、选择、变量、条件和存档映射 | 分支覆盖、不可达节点、恢复与本地化边界 |
| 生成内容 | 种子、约束、分布和停止条件 | 同种子复现、不同种子有结构差异、极端输入不死局 |
| 难度 | 知识、组合、速度、精度、信息、资源、风险或协作轴 | 玩家能读出变化；不要同时改变互相混淆的轴 |

- 声称“可制作/可迭代”时，用一份新内容从权威母版经过导入与构建进入游戏；不得修改核心状态、输入或运行时才能完成。
- 内容 schema 和第二内容集只能证明生产路径，不能证明内容有趣、学习曲线合理或值得复玩。
- 教学应在安全行动中暴露规则，再要求迁移；长说明被读完不等于玩家理解。
- 隐藏目标、谜底和随机结果不得经 DOM、可访问名称、预加载样式或调试层泄露。

## 6. 音频

- 为音乐、环境、效果和语音分别声明职责；无音频合同可以范围化 N/A，但要保留理由。
- 音频 authority 是可编辑工程或无损源及 cue/导出映射，压缩文件不是上游母版。
- 处理首次手势启用、加载/解码失败、暂停恢复、循环点、并发和静音；关键规则信息必须有视觉、文字或触觉替代。
- 节奏体验让谱面、tempo map、音频和判定共享可追踪时间基准；记录校准与设备延迟假设。
- 技术检查可证明音频按规则触发；音质、情绪、音乐性和节奏感需要合适 reviewer 或玩家 coverage。

## 7. 可访问性

按合同风险选择检查，不以一组万能开关代替：

- **输入**：替代入口、可重映射、保持/切换、组合键简化、灵敏度或吸附。
- **感知**：颜色、声音、文字、位置、形状和纹样不让关键信息依赖单一通道。
- **运动**：镜头、震动、闪烁和连续运动可调；reduced-motion 不改变规则。
- **时间**：时限、重复频率和节奏窗口按体验价值提供合适调节，不默认要求无时限模式。
- **认知/文本**：控制可发现，错误和恢复明确，文本在真实舞台缩放后可读。
- **Canvas/WebGL**：提供可聚焦舞台、邻近说明、状态播报和必要 DOM 控件；无法等价线性化的空间信息如实披露。

静态扫描、API 存在和作者走通只能证明实现事实。声称对某类使用需求有效时，需要具相关需求的独立参与者在当前 build 完成对应路径。

## 8. 玩家价值验证

验证计划从 claim 与风险反推参与者角色、设备、方法和覆盖，不使用固定人数：

| Claim | 需要观察 | 不能替代 |
| --- | --- | --- |
| 初次理解 | 从干净状态进入后能否形成正确行动与规则预期 | 开发说明、作者演示、脚本通关 |
| 公平/可归因 | 成功、失败或受阻后能否说明原因并找到恢复路径 | 确定性单测、无崩溃 |
| 乐趣/表达/发现 | 行为与访谈是否支持玩家合同中的具体价值 | 漂亮截图、粒子、完成率 |
| 节奏感/手感 | 实际设备上的输入、反馈、校准和恢复体验 | 帧率、延迟日志单独通过 |
| 复玩/精通 | 返回时是否出现新决策、技巧、内容、表达或社交变化 | 再来一次按钮、分数变化 |
| 本地多人 | 真实玩家间的所有权、协作/竞争、离开和恢复 | 两个自动化 client、单人代按 |
| 可访问性有效 | 相关参与者使用替代路径能否完成合同任务 | 自动扫描或设置项存在 |

记录当前 build hash、目标 claim、参与者角色与作者独立性、真实设备、方法、观察、结果和限制。未获得相称 coverage 时将对应 gate 保持 blocked，并把结论写入 `not_evidence_for`/`excluded_claims`；不要阻止不依赖这些 claim 的普通原型交付。

## 9. 失败诊断

| 症状 | 首个失效假设 | 返回位置 |
| --- | --- | --- |
| 页面会动但玩家不能改变结果 | 没有核心循环或能动性 | 玩家合同 / `games.core-loop` |
| 自动化通过但真人无法开始 | 测试绕过公开输入或已有答案 | 输入模型 / 教学 / `games.player-value` |
| 输入有动画但世界不变 | 反馈取代规则结果 | `games.feel` / 规则模型 |
| 难度只靠更快、更多或更久 | 没有可学的新关系 | 内容/难度模型 |
| 随机体验像噪声或会死局 | 缺少约束、种子或停止条件 | 生成内容 authority |
| 新关卡必须改核心代码 | 内容与运行时没有分离 | `games.content` / 工具路线 |
| 音频关闭后规则不可读 | 声音承担唯一真相 | `games.audio` / 反馈 |
| 辅助设置存在但路径仍不可完成 | 实现存在不等于有效 | `games.accessibility` / 玩家合同 |
| 多人设备串控或离开后锁死 | 身份、所有权或会话状态错误 | 输入/session authority |
| 工具只出现在依赖或文案中 | 没有真实调用与母版链 | 工具选择 / tool-use evidence |
| 框架接入后仍无法扩内容 | 使用了 API，却没采用原生模型 | 工具路线 / authority graph |
| 测试全绿却宣称好玩、公平 | 工程证据越过 claim ceiling | `games.player-value` / promotion record |
