# 设计品牌识别

## 核心目标

让用户在看到产物的三秒内相信：这个品牌已经存在，做出来就是这样。交付两样东西：一组**品牌示例**
（官网首屏、门店、包装、名片、社媒帖等最终效果，看不出是效果图）和一个**品牌工具包**（文件夹，
里面是这套品牌的方向与工具：标志方向、色表、字体建议、图像调子、信息要素、参考设计、指南）。
示例给人看效果做决定，工具包让人能接着把它做成正式生产文件。我们做的是示例与方向，不是印刷厂
文件；但示例必须像真的一样，不打水印、不标"示意"、不用占位。

遵循四个原则：

1. **最小系统。** 从一个主要标志载体、少量颜色、有限字体、一种图像调子和一种语气开始。这里的数量是
   默认探索上限，不覆盖用户已有的品牌规范、既有生产系统或明确的交付要求；超出默认上限时，记录每个新增
   颜色或字体的职责与消费者。
2. **同一个世界。** 全部示例与工具包文件必须像同一家公司在同一天拍的：同一主色、同一字体口吻、
   同一光线与材质、同一标志。一帧飘了整组判不合格。
3. **触点由用户决定，基础工具由本 Skill 决定。** 用户列出的触点逐个做成示例；用户没列的标志、色、
   字、语气照样交付。
4. **像真的一样。** 场景是真实的场所与光线，材质可信，文字拼写正确，标志清楚；效果图里出现的一切
   都应该能在现实中被这样做出来。

本 Skill 只拥有品牌领域判断。品牌触点保持介质中立，必须在各自的目标媒介和最终消费者中验证，并记录最终像素或等价终态。
流程与证据服从共享 `$visual-artifact-design`。只有最终消费者是 Web，或合同明确要求 Web 交付时，才组合
`$build-polished-visual-frontends`；该 Skill 负责 Web 实现，品牌 Skill 继续负责身份系统。每个使用的字体、图像、
商标或生成资产都要记录来源、许可与替换边界。完整字体家族转交
字体领域；单个功能含义转交图标领域；一次性传播转交营销领域；产品工作流转交产品界面领域。

什么算好，七条判据（后文以代号引用）：

- **B1 一个颜色世界**：示例帧被一个主色统治，其余色只做点缀或功能；不是"色板有五个色"。
- **B2 一种字体口吻**：标题与正文的字面、字重关系在所有帧里相同，能用一个词说出它的性格。
- **B3 一种图像调子**：光线、背景、道具、裁切、有无人物一致，能用一句话描述。
- **B4 标志与文案在场景里**：标志出现在真实载体上（网页、包装、招牌、名片），语气随之出现；孤立的
  标志放大页不算示例。
- **B5 可溯源一致**：示例里每个可见元素能指向工具包里的一项；工具包里每项工具至少在一帧示例中被使用。
- **B6 近邻可分**：示例帧与两个真实近邻并排缩略时，一眼能分出是谁；靠的是结构关系，不是更亮的颜色。
- **B7 像真的**：没读过任务的人把示例帧当成真实品牌的照片或网页；场景、材质、光线可信，文字无
  乱码，标志无变形。

## 1. 先读懂任务，再决定做什么

新建或大改前，先在 `BRAND-BRIEF.md` 写一张品牌决策卡：

```yaml
主体: 正式名称、简称、语言读序、所有权或背书关系
身份任务: 谁在什么重复场景认出它，与哪些真实近邻区分，认错的代价是什么
任务触点与范围: 记录用户或主代理提出的触点，区分示例清单与明确范围限制；有子任务分工时，记录当前任务负责和不负责的内容
交付档位: logo_kit | basic | full | social_kit | packaging_kit
示例帧清单: 每个触点一帧 + 一帧定调帧（官网首屏 | 产品图 | 平铺 | 空间实景）
表达强度: quiet | editorial | expressive
硬约束: 用户禁忌、既有资产、语言、接收方
未知与阻断: 名称未定阻断什么、关系未定阻断什么
```

硬约束只来自用户要求、既有资产、语言和接收方；模型偏好的气质、色相、"想做得更完整"都不是硬约束。
`mode` 分 `create / edit / govern / diagnose`：`create` 与改变核心的 `edit` 走完整流程；主体已有标识（按 `$visual-artifact-design` 的既有身份盘点）时，`create` 默认为**延展**：既有标识按 `$visual-artifact-design` 的三档阶梯取用后作为 `logo/` 母版，新工作落在色、字、应用层，`reference_route` 即 `accepted_system`；只有用户明说"重新设计 / 换标"才重做标识。窄 `edit`
只从最早失效的一步进入；`govern` 先核验已批准资产与消费者；`diagnose` 只读复现与定位。品牌架构、
焕新迁移、动态识别的专项模式按需读取[品牌模式与检查](references/patterns.md)。

### 第零步：把触点翻译成档位（选载体前必做，不许跳过）

用户提需求的方式是列触点、说禁忌、提一句谁要用，不会写交付清单。翻译是本 Skill 的责任：

| 档位 | 用户通常怎么说 | 示例帧 | 工具包里必须有 |
| --- | --- | --- | --- |
| `logo_kit` | "做个 logo"，"换个标" | 定调帧 + 标志在两种载体上 | `logo/ color/ type/`、README |
| `basic` | 明确要求基础版或精简品牌工具包 | 定调帧 + 数字、印刷各一帧 | `logo/ color/ type/ voice/ imagery/`、≤ 6 页指南 |
| `full` | 默认档位；未限定范围、没列具体触点，或要求完整品牌系统 | 定调帧 + 用户每个触点一帧 + 补足数字/印刷/空间三种情境 | 全部目录、≤ 12 页指南 |
| `social_kit` | 明确只要社媒套件（头像、封面、帖子模板） | 定调帧 + 头像、封面、帖子三帧 | `basic` + 社媒三类 |
| `packaging_kit` | 明确只要包装套件（包装、标签、快递箱） | 定调帧 + 包装正面、货架、开箱三帧 | `basic` + 包装三类 |

规则：默认采用 `full`，尽可能完整地交付品牌示例与工具包。用户或主代理未列触点、仅举例列出部分
触点或未点名某项基础工具，不构成缩小范围的依据；未限定范围时按品牌任务选择数字、印刷、空间三种情境的代表应用。
但用户或主代理明确限定当前任务范围时，应遵守该边界，采用对应的 `logo_kit`、`basic`、`social_kit` 或
`packaging_kit`，不扩展到其他子任务负责的内容，也不要求提供用户逐字原话。
窄 `edit` 仍按任务模式只修改受影响部分，不重做完整工具包。`logo/ color/ type/ voice/
README.md` 与定调帧在任何档位都存在。"供应商之后要能继续用"翻译为方向要清楚到别人能接着做，不
翻译为交付印刷文件。骨架与各档位裁剪见[工具包骨架](references/kit-skeleton.md)。

### 参考路线 gate

支撑层剥离与回退鲁棒性是两项独立检查：前者去掉提案包装后仍要看见身份关系，后者只验证真实媒介会遇到的单色、反白、极小尺寸、替代字体或受限材料。`N/A` 只表示已接受范围外，并记录原因。

在形成方向之前，锁定一条且只锁定一条 `reference_route`：

- `accepted_system`：用户已有资产、已接受的参考或既有品牌系统能约束当前任务；保存实际可查看的来源
  画面，名称、印象和模型记忆不算证据。
- `observed_neighbours`：没有可沿用系统；先按身份任务找到 2–3 个真实近邻的当前画面（官网首屏或
  产品图），记录它们各自靠什么被认出、哪些结构已经拥挤，写出本主体必须避开的碰撞和可以占据的空位。

研究问题，不收集风格：只在有未决结构问题时看案例，先写问题再选最小参考集；每项记录实际看到的帧、
主要载体、不变量、可迁移原则和不可复制的资产，绘制前写 anti-copy 边界，禁止复制名称、字形、图形、
色板、构图或签名机制。路线与近邻证据未写入 `BRAND-BRIEF.md` 前，不得生成任何标志或示例。

无论走哪条路线，都要把参考落成 `REFERENCE-CONTRACT`，每条关系一行，写进 `BRAND-BRIEF.md`：

```yaml
- fact_id: R1
  source_frame: 实际看过的画面（文件名或 URL + 帧）
  observed_relation: 看到的结构关系（如"字标与主色块的面积比约 1:6，字标永远落在空白面"）
  protected_axis: 迁移时不能动的轴（层级 / 面积 / 位置 / 读序）
  target_object: 本任务里承接这条关系的对象（哪一帧、哪个触点）
  representative_frame_evidence: 定调帧里它成立的像素证据（截图 + 位置）
  final_frame_evidence: 终态里它仍成立的证据
  deviation_constraint: 允许偏离到哪里为止
```

至少一条宏观结构或读序、一条层级或面积关系、一条图像角色或标志载体关系；只写颜色关系不算完成。
先例阅读（第 2 节）的两页图也按同样格式记：读了哪一格、学了哪条关系。引用名称、描述气质或只写进
brief 是假设，不是已执行的参考。

## 2. 立意与方向，再落到最小系统

在本节做出任何方向决定之前，完成三次阅读，顺序固定：

1. **示例**：先读 `references/brand-examples/INDEX.md`，按第零步的档位找到命中的格，再读取
   `references/brand-examples/page-1.jpg`。四个品牌各一帧，看的是 B1–B4、B7 在一帧里
   同时成立是什么样：Mount Lai 的白底细衬线与玉石道具，Glossier 的浅粉与字标在瓶身，Noted 的木桩
   松果与素标签，Hero Bread 的金色包装在大理石上。学一帧怎么定调、怎么像真的，不学任何一家的颜色、
   字体或道具。
2. **工具包**：读取 `references/brand-kits/page-1.jpg`。看的是文件夹里的工具铺开是什么样：Spotify 的
   色点、标题字规格、图标集、照片处理排成一版；LUVEU 与 EcoAvenue 的平铺里同一套东西落在包装、
   名片、招牌、杯子上；Water Lily Pops 的网站与包装并排一致。学"同一个世界"在实物上什么样。
3. **风险**：按 `$review-against-ai-patterns` 第 1 节读取图鉴索引与标本。品牌任务常命中 P 配色模板、D 插画
   画风、G 灰色小字、B 表达块；命中即读，不为凑页数多读。

然后在工作区根目录（`submission/` 之外）建立两份工作证据，随做随记，只记会改变文件、像素或验收
的决定：

**`BRAND-BRIEF.md`**——正面：要什么。包含决策卡、参考路线与近邻证据、最小系统合同、候选与淘汰、
定调帧证据、`KIT-MANIFEST`、生成链记录、终检段。

**`ANTI-SLOP-CHECK.md`**——负面：避什么。内容、格式与结账规则见 `$review-against-ai-patterns`；交付前对全部示例帧做一次全局扫描。

### 最小系统合同

方向候选与示例帧都从这份合同出发，写进 `BRAND-BRIEF.md`：

```yaml
标志载体: 字标 | 图形标+字标 | 字标+图形元素；不变量（轮廓、负形、读序、关系）
色: 主色 1（HEX、职责）；辅色 ≤ 2；中性色 ≤ 2；深浅两种背景下的文字色
字体: 标题字（字面、字重）；正文字（同上）；字重关系；中西文配对
图像调子: 光线 / 背景 / 道具 / 裁切 / 有无人物，一句话可述；这句话就是所有生成图的共同 prompt 骨架
语气: 使命一句、价值主张一句、标语一句、语气三词、样句 3 条
图形元素: 图案或表现型图标是否需要、用在哪；没有去处不建
近邻区分: 与 2–3 个近邻并排时靠什么关系分出
世界设定: 示例帧共用的场所、时段、季节、人群；所有 mockup 都发生在这个世界里
生成层: 按下方标志生产路线填写新增标志概念图张数 + 场景示例底图张数；复用标志另记来源，不冒充生成图，场景生成要求不因此豁免
```

"高级、克制、年轻、科技感"不是合同内容。颜色不能来自题材联想（茶就绿、海就蓝、儿童就彩虹），
必须能说出主色在近邻中的位置与它承担的职责。

### 结构候选

候选数量为 `1 + 未决高影响分叉数`，最多三个。方向只有在改变标志载体、轮廓逻辑、名称与字形关系、
语言关系或层级机制时才不同；换颜色、字体、圆角或 mockup 不构成新方向。候选用中性编号 `A / B / C`，
不先写概念名和品牌故事；统一尺寸、面积、颜色条件，连同近邻盲排；分别记录可见指纹、碰撞、失败
条件和淘汰理由；用成对比较和明确取舍，不用加权总分。若区别主要来自颜色、材质或解释，全部返回。
标志按资产逐项选路线，不能因已有一个字标就把所有新增符号视为既有资产：

- **既有标志**：复用官方母版，或按三档阶梯从来源图提取、描摹；不为满足生成次数重画它。
- **字标派生头像**：可以直接提取现有字形、等比缩放并适配画布，记录原始字形来源；不得增造圆环、横线或其他轮廓。
- **缺失且需要新形状的品牌符号**：保留已有字标，以它和相关品牌资产作为 `image_generate(images=[...])` 的参考，
  生成／编辑 2–3 个候选（`output_dir=<任务目录>/assets/generated`）；不得借用出品方标志替代主体身份。
  没有既有品牌资产的新标识先文生图，再以选定概念为参考迭代。检查品牌关联、单色及小尺寸辨识度后，
  从选定母图用描摹工具建立矢量，不能用代码另造形状。新增符号不授权替换已有标志。

品牌 Logo、头像和产品标识承担身份识别，不是搜索、关闭等标准功能图标；几何简单或用户要求 SVG 都不改变这一归属。

### 字体选型（中西文都必须显式选型）

合同的字体行必须写明标题字、正文字的具体字面与理由；HTML 排版的示例帧与指南优先用真实字体文件
（有网时按下表取），取不到时用最接近的可用字体并在 BRIEF 记一句。裸用系统默认字体而不做选型，
等于没有字体口吻。

| 品牌气质 | 中文标题 / 正文 | npm 包 | 拉丁配对 |
| --- | --- | --- | --- |
| 文化、手作、档案、安静 | 思源宋体（标题用足字重） | `@fontsource/noto-serif-sc` | `EB Garamond` / `Libre Caslon` |
| 人文、温度、手记 | 霞鹜文楷 | `lxgw-wenkai-webfont` | `Inter` / `Source Serif 4` |
| 产品、工程、直接 | 思源黑体（Bold/Black 当标题） | `@fontsource/noto-sans-sc` | `@fontsource/space-grotesk` / `Inter` |
| 编号、数据、点缀 | — | `@fontsource/jetbrains-mono` | 同左 |

标题的性格来自字重与字号的极端对比，不来自加粗默认黑体。

### 帧探针 gate（生产任何素材前）

选定字体后、生成任何图之前，先用 HTML/CSS 在真尺寸画板上写一张只有标题、正文与色块的空帧，用 `render_file`
（`output_dir=proof/probe`，`motion_mode=static`）出图并用 `preview_file` 查看：证明所选中西文字体真的被加载（不是回退到
系统黑体）、字号比例成立、`pages/` 像素等于规格。探针失败就停下修字体或环境，不允许"先用系统字体做完再说"。探针帧
不是定调帧，bundle 留在 `proof/probe`。

### 图像来源纪律与清单

示例帧里每一张非代码绘制的图像都走同一条阶梯，高档可得时禁止用低档，理由写进 `BRAND-BRIEF.md` 的
**图像来源清单**（按帧逐行：位置、档位、真实性边界、一句为什么是这张）：

1. **用户提供的真图**：既有标志（位图、README banner 里的字标、组织头像都算）、产品照、门店照、既有物料；动手前穷尽搜索任务材料并逐张查看；
2. **可运行对象的真截图**：用户产品能跑起来时先截真画面；
3. **生成图像**：其余场景、产品、平铺、人物、材质全部由 `image_generate` 出；无真图时生成是默认动作，
   不许留白或改用 CSS 渐变、手写 SVG 模拟质感；
4. **精确图形**：色表、字体样张由 HTML 按数值绘制；干净标志矢量用描摹工具从既有来源图或选定的生成概念图描出（`potrace` /
   `vtracer`，见 `$visual-artifact-design` 的 `references/svg-and-vector.md`「Vectorization tools」），SVG 只是它的资产格式；
   不许用圆弧公式或坐标在代码里重建标志形状。

**生成失败不退回手绘**：出图全黑、乱码、构图不可用时重生成或用 image edit 修正，最多两轮再换 prompt 骨架；探索图
（标志概念板、方向草图）不是资产，不能当"已生成"的证据；任何情况下不许改用代码画标志、图形或场景来顶替。

### 素材层 gate（示例帧开始前）

`assets/generated/` 里至少有一张将进入场景示例的生成底图；新增品牌符号还必须有选定的生成概念图，各附 `prompt.txt`。
复用标志或直接提取字形的头像提供来源图与派生关系，不要求另生成标志概念图；这一豁免只适用于该标志资产。`BRAND-BRIEF.md` 合同的
`生成层` 一行已填数字，图像来源清单有对应的 `generated_visual` 行。没有这一层不许开始定调帧与示例帧，也不许以"先做矢量
后补场景"跳过。下列理由**不合法**：「可维护矢量源」「这是精确图形」「用户没提供真图」「怕被误认成真实照片」「任务书只要
SVG」——任务书规定的是触点与内容，实现基底由本 Skill 决定。唯一例外是用户明确禁止生成图像：记入 `BRAND-BRIEF.md`，
并在 `README.md` 说明。

生成图不得冒充用户真实产品照或真实门店；成品里不出现任何制作过程话语（"示意""生成""mockup"）。
**分辨率账**：位图物理尺寸 ≥ 帧内显示尺寸的 2 倍；生成尺寸按最终帧选择，不许把小图拉满；交付前做一次
2 倍缩放的截图对比。生成前的艺术指导与生成后的像素检查清单，读取
`../build-polished-visual-frontends/references/assets-and-imagegen.md` 第 4、5 节，不重写。

### 工具清单

新建方向或更换主要工具时，在 `BRAND-BRIEF.md` 写工具清单，只回答七件事：能力与最难状态 / 候选与各一条
可观察理由 / 选择与为何例外最少 / 气质是否匹配 / 职责边界 / 如何服从最小系统合同 / 最终产物中如何证明它真的
工作。任何自建实现（自写抠图、自写排版引擎）必须先写调研过哪些现成工具与不用的一句理由；写不出就不许自建。
有网时外采字体、模板与素材是被允许且被期待的，来源记入 `THIRD_PARTY_NOTICES.md`。

## 3. 让成熟工具承担成熟能力

`image_generate` 是本 Skill 的主生产工具：标志概念、定调帧的场景与产品、门店与招牌、包装与货架、
平铺、人物与环境全部由它产出。`images=[...]` 有两个用途：同一世界靠参考帧链维持；标志、产品与文字实体进场景
靠**多图融合**——底图、标志 PNG、参考帧一次输入（最多 6 张），让标志成为场景里的实体（招牌、刺绣、烫印、印刷）
而不是贴上去的一层。HTML/CSS 加 `render_file` 负责排版类的帧（官网首屏、社媒帖、名片版式、指南页）；不把矢量
标志贴到生成场景上。Inkscape 与 librsvg 用于处理官方母版，或从既有来源图、选定生成母图描出干净的标志矢量。详细命令与验证见
[实现技术路由](references/implementation-routing.md)，本节只给路由结论：

| 交付物 | 技术 | 不这样做 |
| --- | --- | --- |
| 标志方向图 | 既有标志复用；直接字形派生保留来源；新增符号以品牌资产为参考用 `image_generate` 出 2–3 个概念 → 选定后用 `potrace` / `vtracer` 描出干净标志矢量并在 Inkscape 清理，标准字组合在 HTML/CSS 出图 | 只有一张模糊的生成图当标志；概念图失败后改用代码画标志；用圆弧公式重建形状 |
| 定调帧与场景类示例（门店、包装、货架、平铺、人物） | `image_generate`，合同里的"图像调子"与"世界设定"作 prompt 骨架，参考图链保持同一世界 | 各帧各自抽卡、光线材质互不相干 |
| 排版类示例（官网首屏、社媒帖、名片、海报） | HTML/CSS 排版，图像来自生成场景，`render_file` 定尺寸出图 | 用生成图画界面文字；用 SVG 坐标排版面 |
| 标志与文字进场景 | 底图 + 标志 PNG + 参考帧一起送 `image_generate(images=[...])` 融合，标志作为实体生成；融合后逐字核对，拼写错再做一次 edit；仍错才允许一次登记进 `KIT-MANIFEST` 的最小叠加 | 用 HTML / ImageMagick / PIL 把矢量标志贴到生成场景上；留着乱码或变形交付 |
| 色表与字体 | `palette.md` 唯一色值来源，`tokens.css` 由它生成；字体按选型表 | 在帧里另写色值 |
| 图像调子样张与图案 | `image_generate`，同一 prompt 骨架；派生用参考图模式 | CSS 渐变、留白 |
| 指南 | HTML 分页母版（同一 tokens）→ Chromium 出 PDF | 另起一套排版、超页数 |
| README 与一致性 | 脚本枚举文件与 HEX 核对；一致性以并排缩略目检为准 | 人工声明"已一致" |

用户明确要求印刷厂或供应商可直接使用的生产文件时，才读取路由文档末尾的"生产级附录"。

## 4. 先完成决定成败的定调帧

在生产任何其他文件之前，先做一帧定调帧：官网首屏、产品图、平铺或空间实景，用真实名称与真实文案，
标志、主色、标题字、合同调子的图像和一句标语同时在场，像一张真实品牌的照片或网页截图。

按以下顺序查看实际像素：

```text
像不像真的：场景、材质、光线可信，文字无乱码，标志无变形（B7）
→ 主色是否统治画面（B1）
→ 标志是否在真实载体上、大小是否相称（B4）
→ 标题与正文的字面、字重关系是否成立（B2）
→ 图像调子是否一句话可述（B3）
→ 文案语气是否与画面一致
→ 与两个近邻首屏缩略并排，能否一眼分出（B6）
```

B7 与 B1 不成立时重生成或回到最小系统合同，不用阴影、材质、渐变或更多元素掩盖。定调帧未通过之前，
不得生产其他示例帧与工具包文件。通过的定调帧存入 `examples/`，作为后续所有帧的参考图链起点。

## 5. 从定调帧铺开：示例组与工具包

定调帧稳定后，两条线并行推进，都记在 `BRAND-BRIEF.md` 的 `KIT-MANIFEST`：

```text
path / 类型（示例帧 | 工具）/ 对应触点或工具 / 生成方式与参考图 / 状态 planned → built → verified / 证据
```

**示例组**：用户列出的每个触点各一帧，再补足数字、印刷、空间三种情境；每帧都以定调帧或上一帧为
参考图生成，用真实内容与文案，尺寸按平台或实物比例。每帧过 B7 与 B1–B4 才进入 `verified`。用户没
点名的情境做到三种为止，不为"显得系统"扩张。

**工具包**：从示例组里把工具抽出来落成文件：标志方向图与干净版、色表与 tokens、字体建议与样张、
图像调子样张、语气、图形元素（若有）、参考设计（示例帧按触点归档）、指南、README。工具包里出现
的每一项都必须在某帧示例里被用到；示例里的每个元素都能在工具包里找到。

一致性在本节执行，不留到终检：所有帧并排缩略像同一家公司同一天拍的；色值只在 `palette.md` 定义
一次，HTML 类文件只引用变量；标志在所有帧里是同一个形状；某个触点若需要新的字体、网格或图像家族，
返回最小系统合同。

`guide.pdf` 最后做：系统一页（定调帧 + 七条判据的落点）、标志、色、字、图像、语气、应用样张、禁忌，
不超过档位页数；内容全部来自已 `verified` 的文件。`README.md` 核对清单与文件夹一致，写明档位、每个
文件给谁看、正式生产时由设计师按此方向制作。

## 6. 看见这些迹象就停下来重构

制作中出现下列任一项，立即停下并更新 `ANTI-SLOP-CHECK.md`：

- 像效果图不像真的：假光、塑料材质、悬浮物体、生成图常见的水印感、"示意""mockup"字样（B7 失败）；
- 生成图里文字乱码、标志变形、同一标志在不同帧里形状不同（B5、B7 失败）；
- 每个触点各说各话：首屏一种字体、名片另一种、包装第三种（B5 失败）；
- 身份只存在于材质、阴影、摄影氛围，去掉包装后认不出（第 7 节支撑层剥离失败）；
- 题材直译的图形：海就是浪、茶就是叶、儿童就是彩虹与卡通牙齿、数据就是节点连线；
- 渐变球、发光弧线、双色阵营、抽象 swoosh 一类可以贴在任何公司上的标志；
- 定调帧只是标志放大或一张纯色底加标志，没有真实载体（B4 失败）；
- 场景示例里的标志是贴上去的：无厚度、无光影、透视不贴合、边缘锐利（B7 失败，route 违规）；
- 生成出图失败后改用代码画标志、图形或场景（route 违规）；
- `assets/generated/` 为空，或标志本体与场景示例是手写几何 SVG、生成图只当底纹（素材层 gate 失败，图鉴 D 组）；
- 工具包里只有图没有值：色表没有 HEX，字体没有名字，语气没有句子。

品牌专项标本已回填进共享图鉴：B7 生成场景上压纸色参数卡、G4/G5 免责小字、D4 示意图当主视觉。上述信号按组对应：
贴图叠加与纸卡压图→B、题材直译配色→P、代码画标志与几何图形→D、"示意 / mockup"字样→G。

## 7. 按风险检查，不制造审查循环

- **方向检查**：定调帧完成时，只看 B7、B1–B4、B6 与近邻并排。
- **系统检查**：示例组第三帧完成时做一次并排缩略，之后只在共享规则变化时再做。
- **上限测试**：把定调帧与所读标杆并排，问"这像一张让客户看到上限的品牌效果图，还是像一份矢量资产清单"；像清单就
  回素材层 gate 补生成层。
- **最终检查**：最后一次可见修改后，打开全部示例帧与 `guide.pdf`；先以首次观看者身份写下"没读过
  任务的人 3 秒内看到什么，认为这是谁，信不信它是真的"，记入 `BRAND-BRIEF.md` 终检段；再把定调帧与
  所读先例格并排，写出"它仍强于本产物的三点"，每点指到一个可改的对象。
- **Diagnose / Audit**：只读复现和定位，不进入制作轮次。

执行五个返工测试：

- **真实感测试**：任选三帧给没读过任务的视角，会不会被当成真实品牌的照片或网页；被识破的原因逐条
  修，不解释。
- **支撑层剥离**：去掉概念故事、材质、摄影氛围与装饰，只留标志、色、字、语气；关系仍可见、可复述、
  与近邻区分，才成立。失败返回结构候选。
- **溯源测试**：从定调帧任取五个可见元素，逐个回查到工具包里的一项；查不到的元素删除或补文件。
- **换标测试**：遮住标志，示例帧还能被认出，说明系统成立；只留标志遮住其余，仍能被认出，说明标志
  成立；两者至少一个必须强。
- **多触点并排**：全部示例帧缩略并排像同一家；把标志换成近邻的标志后画面明显违和，说明身份不只在
  标志里。

reviewer 与 `SELF_REVIEW_ONLY` 规则见 `$review-against-ai-patterns` 第 3 节。

## 8. 完成条件

交付前确认：

- `BRAND-BRIEF.md` 含决策卡、档位翻译、`reference_route` 与近邻画面证据、`REFERENCE-CONTRACT`（每条有代表帧
  与终帧证据）、帧探针记录、最小系统合同、候选与淘汰、定调帧证据、`KIT-MANIFEST`、图像来源清单（逐帧）、
  工具清单、生成链记录与终检段（含首见描述与并排三点）；无"待回填 / 待检查"；
- 定调帧通过 B7 与 B1–B4、B6，原图在 `examples/`，且早于全部其他帧；
- 示例组覆盖用户全部触点与三种情境，每帧 `verified`，并排缩略像同一家；
- `submission/brand-kit/` 与档位骨架一致，`KIT-MANIFEST` 每行 `verified`；`color/palette.md` 有 HEX，
  `type/type-spec.md` 有字面与理由，`voice/messaging.md` 有五项；
- 五个返工测试有真实结论，真实感测试没有未修的识破点；
- `assets/generated/` 含场景底图；新增符号含选定的标志概念图，复用／直接字形派生的标志含来源证据；合同 `生成层`
  与图像来源清单一致，干净标志矢量能追到对应的官方母版、既有来源图或生成概念图；
- `guide.pdf` 页数在档位内，内容全部来自 `verified` 文件；`README.md` 与文件夹一致；
- 探针帧、定调帧与 `guide.pdf` 首页的 `render_file` bundle 在工作区根目录 `proof/`（含 `pages/` 与 `document.pdf`），成品
  位图能追到这些 bundle；每个场景类示例帧至少一次 `/images/edits` 融合记录在 `KIT-MANIFEST`；新建 inline SVG 与 `.svg`
  逐项登记（标志资产除外）。harness 核查 proof bundle、HTML 来源与 edits 次数；
- `ANTI-SLOP-CHECK.md` 已按 `$review-against-ai-patterns` 的完成条件结账；
- 只报告真实完成、检查范围、`SELF_REVIEW_ONLY` 与已知限制。

品牌架构、焕新迁移与动态识别的最小契约见[品牌模式与检查](references/patterns.md)；专业软件的能力
边界按需读取[专业工具能力档案](references/tool-profiles.md)。
