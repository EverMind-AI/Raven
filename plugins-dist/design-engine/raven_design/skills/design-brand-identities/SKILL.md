# 设计品牌识别

## 0. 目标、边界与共享接口

品牌识别的目标是稳定归属：受众在重复出现的真实环境中能判断“这是谁”，并与近邻区分。身份可由
名称、字标、图形、排版、色彩、构图、图像、材料、声音、运动或关系语法承担；Logo 不是默认唯一核心。

本 Skill 只拥有品牌领域判断：路由身份问题、定义身份载体与不变量、比较结构、批准核心、限制系统扩展并判断品牌母版。事实/假设、来源许可、通用工具证据、最终像素、review、release 与 promotion 服从共享 `$visual-artifact-design`，不要在这里建立第二套定义。只有 Web 是真实消费者或合同交付时才组合 `$build-polished-visual-frontends`；Web 只能消费已经成立的身份，不能反向证明身份成立。

完整字体家族转交字体领域；单个功能含义转交图标领域；一次性传播转交营销领域；产品工作流转交产品界面领域。品牌可以规定这些消费者继承哪些身份资产，但不替代其专业实现。

## 1. 用四维元组路由任务

一次任务写成 `mode × scope × entity × behavior`，只选择一个主要身份问题：

| 维度 | 可选值 |
| --- | --- |
| `mode` | `create / edit / govern / diagnose` |
| `scope` | `mark / core_identity / application_system / architecture / migration / dynamic_identity` |
| `entity` | `organization / product / service / place / cultural / personal / portfolio` |
| `behavior` | `static / responsive / dynamic / generative` |

再写一句可检验的身份任务：`谁在什么重复场景认出哪个主体，与哪些真实近邻区分，认错的代价是什么。`

- `create` 或改变核心的 `edit` 走完整领域 gate；
- 窄 `edit` 只继承带 owner、版本/hash、适用条件和当前证据的上游结论，从最早失效 gate 进入；
- `govern` 先核验批准母版和消费者，若改变核心则转 `edit`；
- `diagnose` 只读复现、定位和返回，不修改源、资产、配置或权威状态。

`N/A` 只表示已接受范围外；`INHERITED` 只表示当前范围内已有可追溯结论。未知、不可用、未实现和未测试不能冒充二者。

## 2. 建立一份身份决策记录

在共享任务记录中追加品牌字段，不为每个阶段生成一份表演性报告：

```yaml
route:
identity_task:
facts: []
assumptions: []
unknowns: []
external_checks: []
identity_carriers: []
invariants: []
must_pass: []
compare: []
action_permission: EXPLORE | BUILD_REPRESENTATIVE | EXPAND | DELIVER
brand_gates: []
failure_return:
claim_ceiling: []
```

事实至少覆盖本轮会改变设计或结论的主体、正式名称、简称、多语言读序、所有权/背书、既有批准资产及权利、重复识别场景、近邻、目标媒介、维护者和生产条件。未确认项逐项写明阻断范围：名称未定可以探索长度与关系，不能批准最终字标；实体关系未定不能批准品牌架构；许可未定不能进入批准资产包。

选择 1–3 个有优先级的主要身份载体，说明各自职责、不可丢失的不变量、失效时回退方式和真实消费者。把判断标准分开：

- `must_pass`：失败就不能继续，例如名称读序、所有权关系、目标尺寸、既有资产保护；
- `compare`：在合格方向中做整体设计判断，例如结构集中度、近邻区别、主体相称和扩展潜力；
- `external_checks`：作者不能证明，例如商标、真实记忆、母语文化、材料量产和组织采用。

## 3. 用领域 gate 授予动作权限

动作权限只限制下一步制作，不替代共享 work status、artifact lifecycle、release 或 promotion。

| 领域 gate | 通过证据 | 授予权限 | 失败返回 |
| --- | --- | --- | --- |
| `brand.strategy` | 路由、事实/阻断项、身份任务、载体、不变量与三类标准明确 | `EXPLORE` | 事实或身份策略 |
| `brand.structure` | 问题驱动参考、真实结构分叉、同条件候选与具体淘汰理由 | `BUILD_REPRESENTATIVE` | 参考或结构探索 |
| `brand.core` | 幸存方向通过支撑层剥离、核心工艺、近邻和适用回退检查 | `EXPAND` | 结构或核心工艺 |
| `brand.system` | 请求范围内的资产族均有消费者、继承规则、风险证据和停止条件 | 保持 `EXPAND` | 核心载体或系统边界 |
| `brand.master` | 唯一 authority、可编辑母版、批准输出映射、依赖和交接证据成立 | `DELIVER` | 工具、母版或系统 |

当前最好、唯一幸存、文件齐全、作者能解释、完成轮数多或技术测试通过都不是 gate 证据。所有候选可以同时失败；失败时返回最早能解释问题的 gate，不得靠增加页面、mockup 或故事取得权限。

## 4. 研究问题，不收集风格

只在有未决结构问题时研究真实可查看案例。先写问题和初始假设，再选择能改变决策的最小参考集合：类别近邻用于看拥挤，跨类别类比用于看同构问题，耐久/迁移案例用于看保留与弃用，失败案例用于看系统失控。

每项记录实际查看的帧或实物、约束、主要载体、不变量、允许变化、可迁移原则和不可复制的资产。知名度、奖项、模型记忆和品牌印象不算视觉证据。研究结果只保留决策摘要；绘制前为每项写 anti-copy 边界，禁止复制名称、字形、图形、色板、构图或签名机制。

近邻与候选使用相同背景、视觉面积、颜色条件和真实目标尺寸；顺序随机、编号中性。先记录轮廓、字形、负形、关系和类别隐喻的碰撞，再读作者解释。详细模式见 [品牌模式与检查](references/patterns.md)。

## 5. 先探索结构，再完成代表性核心

候选数量由高影响结构分叉决定，通常为 `1 + 未决高影响分叉数`、最多四个；若现有资产和关系已经批准，可以只发展一个方向，但必须做一次轻量反事实挑战。

方向只有在改变主要载体、轮廓逻辑、名称/字形关系、语言关系、品牌层级或变化机制时才不同。换颜色、字体、圆角、切口、故事标题或 mockup 不构成新方向。

进入 `brand.structure` 比较时：

1. 用真实名称或明确标记的 provisional 内容制作等完成度结构探针；
2. 只用 `A / B / C` 等中性编号，不先写概念名和品牌故事；
3. 统一尺寸、视觉面积、颜色与展示条件，连同预先固定的近邻盲排；
4. 分别记录可见指纹、优势、碰撞、失败条件和淘汰理由；
5. 使用成对比较和明确取舍，不用加权总分或“原则完成率”；
6. 若区别主要来自颜色、材质、动效、解释或案例包装，全部返回探索。

通过结构 gate 后只精修一个代表性核心。优先解决轮廓、负形、曲线、端点、光学中心、黑白面积、字距、基线、语言读序和各载体关系；特色应是少量、可见、可复述且与主体相称的结构关系，不是任意制造怪异点。若必须不断增加切口、装饰、渐变或隐喻才能显得独特，返回结构阶段。

## 6. 分开执行两类剥离测试

### 支撑层剥离

去掉概念故事、方向标题、设计师理由、mockup 材质、摄影氛围、阴影、三维包装和无职责装饰，但保留已经声明的主要身份载体。检查没有提案包装时，身份关系是否仍可见、可复述并与近邻区分。

### 回退鲁棒性

仅测试真实媒介会遇到的能力丢失：单色、反白、静态首帧、极小尺寸、低精度复制、替代字体或受限材料。它检查是否存在诚实的回退版本，不要求一个依赖颜色、运动或材料的身份假装在剥掉自身核心后仍完全等价。

两类测试不能互相代替。支撑层剥离失败返回结构；回退失败先修核心工艺，若必须改变载体或不变量则返回结构。外部商标、记忆、文化和生产结论仍保持未验证。

## 7. 以品牌完成度否决扩展

`brand.core` 只有在以下四层判断均无 blocker 时才能通过：

- **正确性**：名称、读序、比例、曲线、间距、对齐、变体和目标尺寸没有明显工艺失败；
- **区别度**：核心不能被当前近邻的常见结构无损替换，拥有稳定可复述的结构指纹；
- **记忆潜力**：一到三个识别线索集中、显著且一致，不靠故事和效果才能发现；
- **长期生命力**：不变量能承受请求范围内的媒介、内容、语言、层级和回退变化，不必为每个触点重造身份。

后面三项是整体设计判断，使用成对比较、取舍、反证和不确定性，不伪装成客观数字。视觉惊喜来自一个必要而准确的关系、比例、节奏或行为，不来自额外贴纸、强调线、粒子、渐变和概念文案。整洁只是正确性的下限；默认字体、默认几何或常见形式必须说明在当前身份任务中的具体作用，不能因类别本身自动通过或自动失败。

色条、边框、角标、背景场或图标容器只有在被明确选为身份载体、拥有可复述不变量，并跨真实消费者
重复成立时才属于品牌语法；一次 mockup 上的彩色竖线不是身份。CSS、材质和展示背景只能呈现已成立
的关系，不能凭实现效果替核心制造区别度。

作者自审时先写 blocker 和反证，再写优势；maker 的故事不进入比较输入。`review_assurance=SELF_REVIEW_ONLY` 只说明审查来源，不能写成 `PASS`、完成、release 或 promotion，也不能支持法律、市场、文化、母语或现场生产 claim。

## 8. 只扩展有消费者的最小系统

通过 `brand.core` 后才扩展非核心的字体、色彩、图像、版式、材料、动态、模板或治理资产。每个资产族写明消费者、要解决的信息或生产风险、继承的不变量、authority、维护者和停止条件；没有消费者就不建。

系统按触点重要性与身份任务分配视觉权重，不让法律说明、制作备注或装饰包装压过核心；必要限制应
邻近受影响应用。大背景可承载某类品牌开场，但后续消费者可以通过构图、字体、图像家族或行为延续，
不要求所有触点重复铺图。

用性质不同的真实任务证明系统，而不是把同一锁版贴到多张漂亮 mockup。应用不得比核心拥有更强的新身份语言；不同触点若各自发明字体、网格、图像或色彩，返回载体和系统边界。Web、包装、空间、产品或传播只作为真实消费者接受相应 companion/专业领域验收，不能用宿主完成度给品牌核心加分。

各范围的最小契约、架构/动态模式和失效信号见 [品牌模式与检查](references/patterns.md)。不要自动制作长篇指南、门户、完整模板库或无消费者的资产宇宙。

## 9. 建立母版、诚实降级并停止

最终状态必须有唯一可编辑 master-of-record、明确依赖与权利、可复现导出，以及母版到批准输出的映射。详细工具选择和能力证据按 [专业工具能力档案](references/tool-profiles.md) 执行；主 Skill 只定义品牌 concern，不维护软件候选的第二份清单。

无法证明原生可编辑母版时，降级为“可继续发展的候选”或“视觉示意”；生成图、不可编辑导出、软件名称、截图和文件后缀不能冒充生产母版。图像生成只可用于研究、视觉世界和草图种子，不能直接成为最终 Logo、字标、商标证据或权威矢量母版。

交付只包含本轮合同需要的决策记录、来源与近邻证据、可编辑母版、批准输出、必要变体、最小系统证明、限制和 handoff。最终解释按“可见形式 → 承担的身份任务 → 当前证据 → 尚未验证”书写。适用 gate 和共享最终像素证据成立后立即停止；不要为案例页完整感继续增加资产、说明、灰色微文案、装饰网格或 mockup。
