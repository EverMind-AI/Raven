# 字体与字形领域模式

本文件保存四条路由的构造与检查模式；共享证据字段、工具事实和晋升 schema 以 `$visual-artifact-design` 为准。数值由文字系统、用途、消费者和风险决定，不设跨项目固定阈值。

## 1. 路由与输出模式

| 路由 | 常见子型 | 权威母版 | 最小交付 |
| --- | --- | --- | --- |
| `font_family` | 静态家族、变量字体、正文/UI/display、多书写系统 | 原生字体工程或 UFO/designspace；合格参数源亦可 | 母版、样式/轴合同、构建、范围清单、消费者 proof |
| `finite_charset_font` | 设备标签、展陈标题、数字/符号闭集、图形文字 | 可逐字编辑的字体源或合格参数源 | 闭集清单、字体源、构建字体、输入与缺字行为 proof |
| `wordmark_lettering` | 字标、标题字、包装固定短语、一次性手写组合 | 原生矢量/绘图工程中的完整词形 | 校核原文、可编辑轮廓、生产尺寸版本与输出 |
| `font_selection` | 品牌/编辑/UI/数据字体选型、替换或迁移 | 选择矩阵、许可记录和部署配置；候选字体保持外部来源 | 受控比较、使用权、目标消费者结果、fallback 与决定 |

共享执行模式固定为 `Create | Edit | Diagnose`，且只改变动作、不改变 route：扩展/修复是 `Edit` 子型，必须先证明合法源与基线可重建；审计映射 `Diagnose/Audit`，只交可复验诊断且零写入，不强迫改源。

### 易混边界

- 字标的长期身份策略、命名与应用系统归品牌领域；本领域负责固定字形与生产可行性。
- 现成字体在页面中的层级与排版归对应内容/UI 领域；本领域负责字体候选、授权、覆盖、渲染和技术采用。
- 主要传达对象或动作语义的独立图形归图标领域；类似字母的图形不因此自动成为字体。
- 校样查看器只索引证据；其 UI 质量与字形本体质量分别评审。

## 2. 控制形模式

### 选择控制形

控制形来自声明文字系统和真实语料，不套固定拉丁字母表。选择能同时暴露以下问题的最小集合，再随发现扩展：

- 直、圆、斜、交叉、端点、接合、开口、字腔和 overshoot；
- 高频字符、低频但高后果字符、标点、数字、附标、连接或重排；
- 语料中的易混组，如 `O/0/Q`、`I/l/1`、`S/5` 仅是拉丁示例；
- 最窄/最宽、最黑/最亮、最密/最疏及最易在目标工艺中退化的形态；
- 家族极值和中间值，或多个候选在相同条件下的对应形。

对每个控制组记录：骨架差异、负形差异、退化后仍保留的线索、依赖 feature 及其默认状态、目标尺寸的失效方式。核心辨识不得只依赖默认关闭或消费者不保证启用的特性。

### 按路由处理

- **家族/闭集字体：** 在 authority source 中修曲线、节点、轮廓方向、组件、极值、端点和局部光学校正；自动描摹与模板部件只作初始素材。
- **Lettering：** 先锁完整词形的骨架、总宽、基线、倾角、首尾和重复字符关系，再进入单字轮廓；不要把字体式均匀 spacing 强加给一次性组合。
- **字体选型：** 不改候选轮廓；用相同内容、字号、字距、feature、rasterizer 和容器比较结构及失效，无法满足即换候选。
- **参数源：** 共用原语不能吞掉逐字判断；任何人工修正必须回写 recipe/override，或正式切换到字体工程为唯一真源。

## 3. Spacing 与 composition 模式

### 可输入字体

1. 用适合该文字系统的直、圆、斜、连接和标点参考类建立 sidebearing。
2. 先在重复、交替和真实词句中稳定基础节奏，再建 kerning class。
3. 仅为基础间距无法解决的例外加 kerning；检查 class 冲突、异常值和未导出字形。
4. 需要 mark/mkmk 或 cursive attachment 时，先建锚点与 glyph class，再测多层附标、大小写、斜体和连接。
5. 区分 advance、视觉居中和全局 tracking；等 advance 也需要逐字字面定位。

垂直度量单独处理：UPM、基线、关键高度、上伸/下伸、`hhea`、OS/2 typo/Win、line gap、附标与斜体边界必须在目标应用中无非预期裁切或跳变。需要竖排时另建竖向度量与替代，不从横排推断。

### Lettering 与选型

- Lettering 在完整词形和生产尺寸中做光学间隔、连接、重叠和首尾平衡；单字拆开好看不代表词形成立。
- 选型比较锁定文本、字号、行长、行距、字距、feature、颜色和渲染器；候选不得各用有利参数。
- 正文用连续段落和真实标点看灰度；UI 用真实控件文案、数字、截断与行框；数据用金额、时间、负值、单位和列对齐。

## 4. Coverage 与 shaping 模式

### 范围账本

为字体或选型候选维护同一份可机器读取账本：

- Unicode codepoint、未编码 glyph、默认字符与明确不支持项；
- script、language、direction、normalization、地区变体和 fallback；
- feature 标签、默认状态、触发文本、期望 glyph 序列与定位；
- 组合附标、连接、重排、数字形式、标点和双向混排；
- 许可允许的安装、嵌入、网页、自托管、修改和再分发范围。

字体路由对账声明清单、编译 cmap、非空轮廓、GSUB/GPOS 可达字形与实际 shaping。标签存在不等于行为正确；记录输入文本、方向、script、language、features、轴值、输出 glyph 和 positions。

字体选型在目标消费者中验证真实文本、fallback 与 feature 支持；网页或系统 fallback 不得冒充候选覆盖。字符覆盖也不自动等于某种语言完整可用。

陌生书写系统需要可信资料与合格母语/文字审阅。没有相关审阅时可通过工程检查，但 claim ceiling 必须排除语言文化正确性。

## 5. 家族、样式与插值模式

每个样式或轴先写用户职责、范围、默认值、目标内容和消费支持；实例数量不能替代职责。

- 字重变化重新分配黑度、交汇、字腔、开口、端点和 spacing，不以统一描边膨胀代替设计。
- 字宽变化保护骨架和关键负形，不只水平缩放轮廓与 sidebearing。
- 斜体承担真实强调与节奏；是否共用罗马结构由设计命题和目标文本决定。
- 光学尺寸改变小尺寸易损细节、开口、对比和 spacing，不是等比缩放。
- 多母版核对节点数/顺序/方向、组件、锚点、轮廓顺序、度量和需要的 hinting 兼容。
- 插值取样按轴数、非线性和故障风险选择极值、默认、命名实例、内部风险点和离轴组合，不为固定数量凑样本。

发现非线性时调整源、轴映射或增加有职责的中间 master；不得用更多命名实例掩盖坏插值。静态导出另核 family/subfamily、typographic names、PostScript name、weight/width class、STAT/fvar 与实际坐标。

## 6. Build 与 delivery 模式

### 字体路由

从干净环境用唯一源构建，保留：

- 源修订/hash、依赖/工具版本与许可、完整命令和构建日志；
- glyph order、features、实例/轴、命名、版本及目标格式配置；
- OTF/TTF/变量字体/WOFF2 中合同要求的输出 hash；
- 解析、轮廓/组件、表、命名、插值和差异检查；
- 安装、导入、输入、嵌入或网页加载的真实消费者结果。

不得直接修补二进制形成第二真源。构建器只证明输出生成和结构检查，不证明字形审美、阅读或文化正确性。

### Lettering 与选型

- Lettering 保存原生可编辑源、轮廓清理、生产色/反白/尺寸变体以及工艺需要的 SVG/PDF/EPS/位图；导出必须能追溯到同一修订。
- 选型保存候选文件 hash、来源、许可文本/凭据、版本、受控比较、部署映射、CSS/应用设置和 fallback；选择决定不得改写外部字体 authority。

## 7. 真实消费者 proof

消费者矩阵只覆盖合同需要的环境，并按风险增减：

| 任务 | 必看行为 |
| --- | --- |
| 桌面字体 | 安装/卸载、样式菜单、命名冲突、输入、复制粘贴、打印/导出 |
| Web 字体 | WOFF2、subset、`unicode-range`、feature/axis、fallback、加载失败与离线 |
| UI/嵌入式 | 目标 OS/rasterizer、缩放、最小字号、状态词、数字、截断和行框 |
| 编辑/出版 | 真实段落、语言、脚注/数字、导出 PDF、印刷或目标排版软件 |
| 字标生产 | 原生矢量导入、轮廓保真、最小细节、切割/刺绣/压印/标牌流程 |

最终证据必须来自最后一次源修改后的构建。截图需保留原始比例或明确换算；放大图用于诊断，不能替代真实尺寸像素。

## 8. 现场条件 proof

先区分四层，避免把模拟升级为现场结论：

1. **结构 preflight：** 轮廓、表、shaping、插值、目标 raster 导出。
2. **消费模拟：** 模糊、对比、像素密度或颜色 sweep；只能发现风险。
3. **实体复现：** 实际设备、材料、尺寸、工艺、光照、距离或视角。
4. **观察/现场确认：** 目标任务、真实或代表用户、原始响应与环境记录。

只有第 3/4 层能支持相应实体、观察者或现场 claim。样本量、条件和停止规则由风险、效应大小、误判后果与领域标准制定，不用固定人数或通用百分比。

安全或高后果任务应让人因、设备/工艺和责任方共同定义可接受标准；设计 self-review 只能作为 preflight。

## 9. Claim 与 few-shot 模式

| 可用证据 | 可以进入 `positive_for` | 必须进入 `not_evidence_for` / `excluded_claims` |
| --- | --- | --- |
| 可重复构建 + 结构 QA | 构建协议、特定表/格式、范围内工程事实 | 审美、可读性、语言、现场适用 |
| 控制形 + spacing 自检 | 特定组件或诊断方法的 internal-positive | 整体字体质量、独立专业认可 |
| 真实消费者通过 | 具名版本/设置下的技术行为 | 未测平台、跨平台普遍性 |
| 实体/观察证据 | 已测介质、条件、任务下的结果 | 未测人群、条件、安全认证 |
| 非作者领域审阅 | 审阅覆盖的当前 build 与 claim | 审阅未覆盖的范围或后续 build |

whole、component、protocol、diagnostic、negative 可并存于不同 scope。展示完整不意味着 whole-positive；先为每个 claim 绑定 build、scope、gate 和 assurance，再决定进入 `internal-positive` 或 `externally-validated`。

## 10. 诊断与返回位置

| 症状 | 先查 | 返回 |
| --- | --- | --- |
| 字符易混、小尺寸塌陷 | 骨架、负形、默认 feature、工艺退化 | `type-control-forms` |
| 段落黑块/亮洞、字标散乱 | sidebearing、advance、局部重量、完整词形 | `type-spacing-composition`，必要时退控制形 |
| feature 存在但不工作 | script/language、lookup、应用设置、fallback | `type-coverage-shaping` |
| 缺字被系统字体遮蔽 | 清单、cmap、subset、fallback | `type-coverage-shaping` |
| 字体不能安装或家族菜单错 | 表、命名、版本、构建配置 | `type-build-delivery` |
| 变量中间值扭曲 | master 兼容、轴映射、内部风险点 | 控制形或 build，按 authority 定位 |
| 校样页正常、目标应用异常 | consumer 版本、shaper/rasterizer、映射 | `type-real-consumer` |
| 屏幕清楚、实体失败 | 尺寸、材料、打印/加工、光照和距离 | `type-field-conditions`，必要时退控制形 |
| 选型比较无法复核 | 候选版本、许可、同条件参数与内容 | route contract 或 selection authority |
| 生成器和编辑源不一致 | 双重真源、未回写修正、重建差异 | `type-tool-authority` |
