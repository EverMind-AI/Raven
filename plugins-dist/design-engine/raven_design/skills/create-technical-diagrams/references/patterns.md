# 技术图解领域模式与检查

本文件只补充子型模型、专业语法和检查方法。共享证据格式、工具使用、review 与 promotion 含义服从治理契约；工具选择读取 [tool-profiles.md](tool-profiles.md)。

## 用途与验证计划

按目标 claim 和误用风险选择检查，不以固定页数、节点数或 review 次数代表覆盖。

| 用途 | 领域事实 | 原生要求 | 读者验证 | 独立复核 |
| --- | --- | --- | --- | --- |
| L0 说明草案 | 对象、主关系、边界、假设/未知 | 可编辑且不夸大格式能力 | 能定位并复述主关系 | 可保持 `SELF_REVIEW_ONLY` |
| L1 复核培训 | 术语、顺序、条件、警示与省略范围有来源 | 关键对象和关系可追踪 | 目标受众不产生关键误读 | 对应领域 SME 覆盖培训 claims |
| L2 维护辅助 | 指定配置、端口/端子/信号/代号、正常与失败状态 | 可查询原生字段、引用、清单和受控往返 | 能追设备、接口、反馈和故障路径 | 领域工程师与维护/调试角色按 claim 复核 |
| L3 受控工程 | 设计依据、计算/危害、标准、变更和批准范围 | 受控专业项目、标准库、revision 与交付包 | 按组织/法规的验证和确认 | 授权设计、独立校核、文控及适用批准角色 |

未知、未实现、工具不可用和未复核都不能写成 `not_applicable`。一个视图可低于整包其他视图的 ceiling；消费者必须显示各自限制。

## 说明图与培训图

- 先写读者要回答的问题，再选择总览、局部、步骤、接口或对比视图；不要用卡片数量代替关系。
- 至少保真对象身份、主关系、方向、边界和有意省略；空间、外形、时间或比例被压缩时就近声明。
- 教学步骤区分状态、命令、完成反馈和转换条件。安全相关动作的许可必须出现在动作之前；省略异常路径时明确写出。
- 图例展示实际使用的“符号 + 线型 + 箭头/端点 + 标签 + 状态”组合；颜色只能冗余编码。
- 说明图可以使用矢量或结构化 diagram，但只能声明其模型真正保存的关系；视觉像工程图不提升用途等级。

## 系统、架构与网络

先区分逻辑、部署、物理连接、数据/信号流、责任和信任视图。容器必须表示真实归属或边界，端口表示接口，关系记录方向、类型和来源。

最小 canonical 字段：

```text
object: id, kind, name, parent, responsibility, source
port: id, object_id, role, direction, medium_or_protocol, source
relation: id, from_port, to_port, kind, direction, mode, source
boundary: id, kind, members, crossing_rules, source
view: id, purpose, included_ids, abstraction, claim_scope
```

- 网络连接使用真实端点；junction 与纯交叉必须在模型和画面中都可区分。
- “依赖、可达、控制、数据、物理链路”不能共用一条未标关系。
- 冗余、容量、协议、故障域和恢复只在有来源且与任务相关时加入。
- 多层架构需要跨层稳定 ID、接口分配与可追溯性时，优先 MBSE；一次性低风险图不强建重型模型。

## 流程、SFC 与时序

业务流程、工业控制顺序和消息时序是不同语法：BPMN 不冒充 SFC，流程图不冒充可执行控制，序列图不暗示物理连接。

适用的状态/顺序模型至少记录：

```text
state_or_step: id, initial, entry_action, continuous_action, source
transition: id, from, to, event, guard, timeout, priority, source
command: id, target, precondition, expected_feedback, failure_target
safe_state: id, prohibited_actions, entry_reason, recovery_condition
```

- 步骤描述持续状态；命令、事件、守卫和动作放在适当关系上，不把“发命令”和“已完成”混为一词。
- 每个危险动作检查前置许可、反馈、超时、失败去向和复位；“保持当前步”必须证明该状态在相应故障下安全。
- 并行、互斥、抢占、跳闸优先级和人工模式必须显式建模；自动布局不得把并发强排成虚假顺序。
- SFC、状态矩阵、原因—结果表、接口表和说明文字由同一状态真相生成或机械对账。
- 声称维护/执行级 SFC 时，使用目标 PLC 生态的原生工程并提供编译、模拟/trace 或等价验证；静态图只能是说明。

## 电气、仪控与工艺

先声明图型和保真层级。单线图、控制原理图、接线/端子图、PFD、P&ID 和功能接口图承诺不同，资料不足时降级命名。

关键对象字段按适用性包含：

- 设备：唯一 ID、参考代号、类别、功能、配置/额定信息、来源；
- 端口/端子：内部 ID、显示号、角色、方向、介质/电气类型；
- 导体/管线/信号：唯一 ID、源、目的、类别、正常/失效状态、介质/电压/协议；
- 引用：主从元件、线圈—接点、跨页、I/O、端子排、清单或数据表；
- 文档：图号、revision、用途、状态、适用标准与偏差、编制/复核范围。

要求：

- power/material、measurement、status、permit、command、feedback 与 trip 使用不同关系类型；颜色和相邻文字不能成为唯一绑定。
- 每条关键接口有源端、目的端、方向、ID 和适用正常状态；连接点、跨线、跨页来源/去向无歧义。
- 标准库、符号族、代号和线型先选 profile；自定义符号记录标准映射、许可与偏差，不因来自软件库就宣称合规。
- 工艺图的设备、管线、阀门、仪表和回路只使用有来源数据；概念流向图不得借 P&ID 外观抬高 claim。
- 维护及以上用途从原生模型导出设备、端子/接口、导体/管线与引用清单，并与画面机械对账。

## 机械剖面与爆炸图

区分功能示意与工程剖面：前者保真层级、接口、方位和流向并声明非比例；后者必须由参数化 CAD/受控尺寸源生成。

- 工程剖面记录基准、单位、比例、剖切面、视向、装配轴、材料、尺寸/公差与来源。
- 剖面线只表示被切材料；轮廓、隐藏边、中心线、流道、线束和引线遵循所选标准 profile。
- 爆炸间距不是实际距离时标明示意；部件编号与 BOM/零件表一一对应。
- 局部放大保留母图锚点、方向和尺度；每条引线只落到一个可辨对象或界面。
- 模型修改后，关联视图、尺寸和清单必须可重建并对账；自绘透视图不能证明装配或尺寸正确。

## 科学机制图

- 记录实体、过程、输入输出、条件、时间/空间尺度、因果词、反馈、证据强度和替代解释。
- 区分观察关联、支持机制、模型假设和未知；箭头必须有关系词和适用条件。
- 方位、比例、浓度或空间位置影响结论时，使用有来源的尺度/坐标/剖面，不任意拓扑化。
- 生成图像可承担外观或氛围，不能替代技术结构、数据证据或可追踪机制。
- 出版级矢量母版保留命名分组、文本和来源映射；领域 reviewer 复核术语、方向、边界条件与遗漏机制。

## Canonical 与多视图

需要 canonical model 的触发器：同一事实进入多个视图、使用多个专业工具、存在状态/模式、要求自动清单或传播、用途达到 L2/L3、错误可能影响安全或操作。

Authority 常见分配：

| Concern | 可接受 owner | 不可接受 owner |
| --- | --- | --- |
| 事实/接口/状态 | canonical model 或字段充分的原生工程 | PDF、截图、查看器文案 |
| 电气/工艺连接 | ECAD/P&ID 原生 project | 手绘线条或浮动标签 |
| 尺寸/装配 | 参数化 CAD/受控尺寸模型 | 矢量插图或渲染图 |
| 视图几何 | 对应 native view master | 独立手改导出物 |
| 分页/标题栏/目录 | 文档发布 master | Gallery chrome |

同一 concern 不能双写。若 canonical 与 native 都允许编辑，必须选择受控双向同步并记录冲突处理；否则明确单向生成、把下游语义字段设为只读。跨视图检查至少覆盖 ID、名称、端点、方向、状态、单位、revision 和用途声明。

## 原生性、往返与发布

工具使用证据服从共享模板。领域补充以下证明：

- 原生字段非空且可查询；动态标签来自对象字段，不是旁置自由文字；
- 重命名对象后相关视图、引用和清单按 owner 规则更新；
- 移动/重排不改变连接端点；允许的关系修改能被 canonical 捕获或明确拒绝；
- 在声明环境重开后，库、字体、符号、单位、页面和引用不丢失；
- rebuild/export 使用同一 master，消费者 hash 与最终证据绑定。

文档发布工具只组合受控派生物。PDF 可以是 release consumer，永远不能因外观完整成为上游事实 owner。标题栏和 manifest 中的用途、revision、review 与限制必须一致；签名、批准和标准符合性不得留空后被当成默认通过。

## 子型断言与失败诊断

| 症状 | 优先检查 | 返回 |
| --- | --- | --- |
| 图整齐但答不出任务 | 读者任务、遗漏对象/关系、错误图型 | `td0` 或 `td3` |
| 箭头/连接无法追踪 | port、junction、方向、关系类型 | `td3` |
| 不同页面状态冲突 | canonical、生成链、手改派生物 | `td3`，再重建下游 |
| 专业代号只是旁置文字 | native 对象/端子/导体字段 | `td2` 或 `td4` |
| SFC 只有正常路径 | guard、feedback、timeout、fault、safe state | `td3` |
| 剖面像插画 | CAD model、剖切面、方位、尺寸来源 | `td2` |
| 标准符号无法证明 | library version、license、mapping/deviation | `td1` 或 `td4` |
| 工具不可用便改手写 | availability 与 capability probe 混淆 | `td2` |
| PDF/Viewer 与 master 不同版 | authority edge、export、build hash | `td4` |
| 自审被写成外部通过 | review role、claim refs、build hash | `td7` |

每次只运行主子型和 claim scope 适用的断言。失败返回第一个被证据推翻的假设，保留无关已通过 gate；不得靠增加说明框、装饰或模糊免责声明掩盖专业失败。
