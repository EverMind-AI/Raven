## 0. 模式与适用性

| 判断 | Create | Edit | Diagnose |
| --- | --- | --- | --- |
| 首要证据 | 新任务纵切片可完成 | 目标改动成立且既有契约未回归 | 问题可复现、边界可缩小、根因有证据 |
| 写入边界 | 只创建请求范围内的代码/数据 | 只修改获授权的目标，必要时迁移 | 默认零写入，不改源码、配置、权威数据或产品状态 |
| 状态要求 | 按子型建最小权威状态 | 沿用并核对现有权威状态 | 只读观察状态、事件、请求与渲染结果 |
| 停止条件 | 真实输入到结果闭环 | 新旧行为和数据均有回归证据 | 能区分事实、推断与待验证假设；修复另行授权 |

再逐项标记 `required / optional / N/A + 理由`：对象数量、selection/batch、持久化/版本、权限/审计、协作/冲突、异步作业、撤销、离线和设备转换。`N/A` 不是缺陷；伪造一个看似完整但没有真实语义的企业能力才是缺陷。

## 1. 对象—状态—命令模型

### 领域不变量，而非固定字段

| 不变量 | 至少回答什么 | 只在何时增加结构 |
| --- | --- | --- |
| 输入/对象真实性 | 当前任务处理的真实来源、内容和边界 | 多对象、跨会话或跨系统引用时才要求稳定 id 与关系 |
| 权威状态 | 哪个模型决定字段、选择、计算和输出 | 有草稿、异步或视图上下文时才拆相应状态片段 |
| 命令因果 | 哪个动作改变什么，如何知道成功或失败 | 高风险、可重放或跨系统时才增加确认、幂等和审计 |
| 结果可核验 | 即时结果、下载文件、保存记录、交接或发布物位于何处 | 只有持久化结果才要求版本、更新时间和重开路径 |
| 责任边界 | 谁或什么系统对下一步负责 | 多角色、审批或协作时才增加所有者、权限与冲突字段 |

不要把对象业务状态与界面状态合并。例如“已批准”属于对象，“正在保存”属于命令，“详情面板已打开”属于视图上下文。

### 按能力组合状态片段

```text
taskState        所有子型都要有：真实输入/对象、有效结果、错误边界
collection       多对象才需要：对象索引、顺序、筛选和当前上下文
selection        显式多选/批量才需要：选择集合与命令 scope
draft            可编辑未提交内容才需要：草稿与校验
request/job      异步或长作业才需要：阶段、revision、取消与结果
history/version  撤销、持久化或比较才需要：快照、修订与迁移
permissions      多角色或受控动作才需要：主体、能力与理由
collaboration    多人协作才需要：所有权、冲突、评论或交接
viewState        焦点、展开、缩放等非领域状态
```

字段名随项目调整。一次性单对象工具通常只需 `taskState + viewState`；不要为它硬造 `entitiesById/currentId/selectedIds/permissions`。多对象产品则必须保持当前上下文、显式选择、筛选结果和命令 scope 语义分离。

### 命令清单

每个命令记录适用字段：`name / target / scope / preconditions / effect / successEvidence / failureRecovery`，并只在需要时增加 `permission / idempotency / undo / reopenOrExportEvidence`。按钮、菜单、快捷键和触摸入口只负责发出同一命令，不各自维护副作用；验证必须断言真实状态或结果，不能止于 click、弹层或 toast。Diagnose 模式不执行写命令，只记录公开只读路径、观察量、对照与归因。

### 持久化契约（仅适用时）

- 先判断任务是否承诺跨会话继续、权威记录、版本、协作或恢复。若都没有，将持久化标为 `N/A`，明确刷新/关闭后的丢失边界；单对象工具仍可交付即时结果或下载文件。
- 需要持久化时，区分内存交互态、轻量偏好、可恢复草稿、权威对象、文件/Blob 与异步作业；为每类状态指定唯一权威存储和重新载入路径。
- 记录 schema 版本、迁移策略和 hydrate/commit 边界。提交要么产生完整的新版本，要么保留原版本与草稿，不能留下无法判定的半写入状态。
- 小型偏好可以使用轻量浏览器存储；对象、版本和文件应进入适合其容量与生命周期的持久层，或明确要求用户重新导入。配额不足、数据损坏或迁移失败时保留可恢复内容并提供安全出口。
- 对可能重放的保存、批处理和作业命令定义幂等依据。刷新/重开验收从新的页面上下文恢复对象、草稿和作业，不沿用原进程内存冒充持久化。

## 2. 状态矩阵与异步作业

### 常见界面状态

只选择适用状态。同步、单用户、无持久化的工具通常不需要 `saving/conflict/forbidden/offline/partial`；把不存在的状态演出来会形成假产品。

| 状态 | 必须可见 | 允许动作 | 离开证据 |
| --- | --- | --- | --- |
| `loading` | 正在取得什么、原上下文是否保留 | 取消、返回 | 数据到达或明确错误 |
| `empty` | 尚无内容、筛选无结果或已全部处理 | 创建、导入、清除筛选 | 对象集合变化 |
| `ready` | 当前对象、范围与可用命令 | 查看、选择、编辑 | 命令开始或字段变化 |
| `dirty` | 哪些对象、哪些字段未保存 | 保存、撤销、继续 | 保存证据或恢复快照 |
| `saving` | 提交范围与进度 | 安全取消（若支持） | 成功、冲突或失败 |
| `conflict` | 本地草稿、外部版本、差异依据 | 保留本地、载入外部、取消 | 新版本与 dirty 结论 |
| `forbidden` | 缺少哪种权限、谁能继续 | 返回、申请权限 | 权限或对象变化 |
| `offline` | 哪些本地能力仍可用 | 本地编辑、排队、取消 | 恢复连接或转为失败 |
| `error` | 原因、影响范围、保留内容 | 修正、重试、移除 | 可判定的新结果 |
| `partial` | 成功、跳过、失败的对象与原因 | 重试失败项、撤销成功项 | 范围被处理或关闭 |
| `success` | 对象版本、记录或产物位置 | 继续、打开、下载 | 新命令开始 |

### 异步作业阶段

只有任务确有跨时异步处理时，才把长作业建成可恢复实体，而不是一个 spinner：

```text
queued → validating → running → succeeded
                 ↘ failed → retrying
                 ↘ canceled
```

作业至少包含目标范围、开始时间、当前阶段、进度依据、失败原因、重试次数和结果位置。刷新后若作业仍存在，界面先恢复作业，再决定是否恢复当前面板。

## 3. 当前对象、范围与批量结果

本节仅适用于多对象或显式批量子型。一次只处理一个文件、文档、画布或输入集时，将 selection/batch 标为 `N/A`，让命令直接作用于当前权威任务状态。

| 范围 | 含义 | 适合动作 |
| --- | --- | --- |
| `current` | 当前查看或编辑的一个对象 | 编辑、保存、比较、预览 |
| `selected` | 用户显式勾选的集合 | 分派、改状态、导出、归档 |
| `filtered` | 当前筛选所得的全部对象 | 汇总、全选前预览、受控批处理 |
| `all` | 权限范围内的完整集合 | 稀有管理动作，必须确认 |

- 点击列表行通常改变当前上下文；勾选框只改变显式选择，两者不要暗中联动。字段名不构成契约，语义分离才构成契约。
- “全选当前页”“全选筛选结果”和“全选全部”使用不同文案，并在执行前显示实际数量。
- 批量结果保留原选择，逐项记录 `{id, outcome, reason}`；失败项可过滤、重试或移出范围。
- 撤销不仅反转字段，还恢复必要的筛选、选择、当前对象和滚动位置。
- 删除、发布、权限修改等高影响命令同时显示对象范围和不可恢复后果。

## 4. 输入输出与专业工作面

### 真实输入输出证明

| 能力 | 输入证明 | 输出证明 |
| --- | --- | --- |
| 文件处理 | 实际选择、读取、解析和逐项校验 | 可定位的新对象、错误项或生成文件 |
| 表单编辑 | 字段进入草稿并通过真实校验 | 保存后的版本、时间或审计记录 |
| 查询分析 | 明确数据源、范围、单位和刷新时点 | 可复现筛选、解释或处置动作 |
| 专业图形 | 与当前对象一致的原始输入、单位、尺度、变换/归一化参数和不确定性 | 与标注、检查器、计数及导出一致的可复查视图 |
| 批量管理 | 显式对象范围与权限预检 | 对象级成功、跳过、失败结果 |
| 创作编辑 | 操作命中真实文档/画布模型 | 可恢复版本、预览或发布产物 |
| 交接审批 | 责任人与前置条件真实改变 | 生命周期、通知记录或待办变化 |

### 组件与领域引擎选择

- 大数据表格需要稳定列、键盘导航、排序筛选、选择和虚拟化时，使用成熟 data-grid 能力；不要把普通表格补丁叠成半成品。
- 层级对象需要树的展开、拖动、重命名和焦点语义时，使用成熟 tree/drag-and-drop 原语。
- 富文本、代码、差异比较、空间画布、图表、地图、时间线和媒体工作面使用成熟领域引擎；自制只用于项目独有的组合与视觉表达。
- 组合框、日期时间、菜单、对话框、可调分栏和复杂表单复用现有组件系统的可访问行为。
- 产品状态是领域权威源；引擎维护必要的渲染或交互状态，并通过明确适配层同步选择、坐标、版本和撤销，避免两套真相。

### 版本、来源与输出溯源（适用时）

- 若功能承诺版本比较，双方必须是同一对象的两个明确版本；显示各自版本、输入来源与必要的时间或内容指纹，不用两块无身份的演示画面冒充比较。没有版本概念的即时工具不显示假版本号。
- 标注、检查器、计数、预览和导出从同一对象版本派生。切换版本时这些消费端一起切换，不能只改变标题或视觉工作面。
- 导出记录实际对象范围、适用的输入 id/版本、生成参数和结果位置；承诺持久化时，重新打开后能说明该产物由什么来源和哪次状态生成。

### AI 与自动化真实性

- 未被任务要求时不添加 AI dashboard、助手、洞察卡或聊天入口。需要时把推理与自动化作为异步命令或作业，而不是装饰层。
- 使用真实提供方或可说明的确定性本地能力；展示输入范围、来源、阶段、失败原因、输出版本与已知限制，不伪造置信度、评分、建议或后台成功。
- AI 输出先作为可审查结果；接受、拒绝和编辑必须作用于明确对象或任务输入。被接受的变化通过同一命令进入权威产品状态，并在适用时进入持久化、版本和审计路径，不能绕开产品状态。
- 能力不可用、离线或失败时保留原对象与用户输入，禁用不成立的主张并提供重试、手动继续或安全退出。

## 5. 错误恢复配方

### 输入校验失败

保留有效项与原顺序；在对象旁显示字段、行号或格式原因；允许修正、单项重试、移除失败项或重新选择来源。不要因一个失败项清空整个批次。

### 保存失败与离线

保留草稿和当前焦点；说明本地是否已缓存、服务器是否收到请求、再次提交是否安全。恢复后用同一命令重试，成功时给版本或更新时间证据。

### 版本冲突

暂停覆盖式保存；显示外部版本、更新时间、修改来源和可比较差异。提供保留本地、载入外部或手动合并；解决后明确当前内容是否仍为未保存。

### 批量部分失败

同时显示总数、成功、跳过和失败；保留 selection 和筛选；允许只重试失败项、撤销成功项或导出失败清单。不要用一个红色 toast 抹平对象级结果。

### 长作业或输出失败

保留作业 id、目标范围、参数与输入版本；原位展示失败阶段和可重试条件。成功后给持久结果位置，失败后不得清空当前工作上下文。

### 危险或不可逆动作

优先提供可撤销的软删除、草稿或版本历史。确实不可逆时，在确认前显示对象名称、数量、后果和权限；确认后把焦点移到结果或安全返回点。

## 6. 信息密度与视觉克制

### 三层信息预算

1. **始终可见**：对象身份、状态、责任、关键变化、主动作和下一步。
2. **一次可达**：筛选、属性、历史、比较、批量动作和诊断摘要。
3. **按需深入**：高级设置、完整审计、罕见字段和系统诊断。

### 反噪声检查

- 删除不能改变定位、判断或下一动作的 KPI、欢迎语、装饰图和导航项。
- 同一区域出现“外层卡片—内层卡片—字段卡片”时，改用标题、分隔线、表格行或共享背景。
- 状态优先用位置、文案、图标和结构表达；颜色只强化已存在的语义，不单独承担含义。
- 次要文本仍要清楚可读；不要把来源、单位、错误原因、保存状态或操作说明缩成浅灰微文案。
- 工具条按动作频率与风险分组；主要动作稳定放置，破坏性动作远离高频连续点击区。
- 只有确实需要比较的内容并列；只需顺序完成的内容使用分步或渐进披露，避免三栏惯性。

### 组件系统一致性检查（仅可视产品界面的 Create/Edit）

交付范围包含可视产品界面的 Create/Edit 才建立并执行本检查。纯对象建模、迁移报告、内部状态检查器及 Diagnose 记为 `N/A + 原因`；Diagnose 可以只读记录现有组件语言与偏差，但不得建立新合同或修改界面。

- 用组件库实际样张建立风格合同，不凭产品名或记忆猜测；记录字体、密度、间距、圆角、边界、阴影、表面、图标、反馈与运动。
- 项目 token 必须引用组件系统 token 或建立一一映射；同一职责出现第二套无依据值时合并或删除。
- 临时遮住现成控件，检查导航、面板、列表、工作面、空态和通知是否仍像同一系统；“控件精致、外围割裂”直接返回修改。
- 只在现成系统缺少领域能力时扩展自定义组合组件；扩展可以改变对象结构，不能另造视觉皮肤。
- 选中、成功、警告和错误按状态影响选择最小反馈，不把描边、浅填充、圆角和图标机械叠加。
- 无真实品牌系统时用文字标识；通用图标不得装进彩色圆角方块冒充 logo，也不得作为每个标题的固定前缀。

## 7. 合同环境任务转换

| 关系 | 空间允许并列 | 空间开始受限 | 空间或输入方式高度受限 |
| --- | --- | --- | --- |
| 列表—详情 | 可并列扫描与编辑 | 主面保留，次面抽屉或可调栏 | 列表与详情转场，保留返回位置 |
| 创作工作面 | 大画布、多属性、精细输入 | 折叠低频属性 | 查看、采集、补记或审批为主 |
| 批量操作 | 多选与持续 action bar | 保留范围摘要 | 进入显式选择模式，避免误触 |
| 导航 | 稳定但紧凑的全局入口 | 收起标签或次级区域 | 围绕当前任务的少量入口 |
| 辅助信息 | 并列比较或固定检查器 | 覆盖层且可返回 | 独立步骤、底部面板或详情段落 |
| 快捷方式 | 键盘、右键与精确指针 | 键盘和直接按钮并存 | 可见触控入口，不依赖 hover |

只有 brief 明确承诺多个目标环境或布局转换时才应用本节，并在适用的草稿、筛选、选择或进行中
作业状态测试；不存在的状态记为 `N/A`。明确限定单一环境的专业重型工作面不必伪装其他环境的
功能等价，但合同声明的尺寸与输入方式必须可用。

## 8. 行为验证矩阵

先按模式和子型选择适用场景，并用同一最终构建验证；每个跳过项记录 `N/A + 理由`：

| 模式/能力 | 场景 | 核心断言 |
| --- | --- | --- |
| Create/Edit 共用 | 首次使用、典型输入、最长与最空内容 | 首个真实动作可达；输入、状态与结果一致；身份和动作不被截断 |
| Edit | 既有数据、行为与迁移 | 目标改动成立；未授权行为、数据格式和恢复路径无回归 |
| Diagnose | 只读复现、对照与缩小边界 | 源码、配置、权威数据和产品状态零写入；事实、推断、根因与待验证假设分开 |
| 持久化 | 未保存后切换、刷新或重开 | 草稿、对象和必要返回位置按契约恢复 |
| 网络/异步 | 慢速、离线、取消、请求或作业失败 | 上下文保留；过期结果不倒灌；重试结果可判定 |
| 权限/协作 | 权限不足、并发冲突、交接 | 禁用理由、角色、版本和解决结果明确 |
