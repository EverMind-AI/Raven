# 插画与视觉场景工具能力档案

本文件按能力选择候选，不规定统一软件或表面风格。稳定 candidate id 供共享 Tool Registry
协调；Registry 未登记或未探测时只能记为未知候选，不能宣称可用。商业、GUI 或当前环境
不可运行的工具应记录 `availability.status: unavailable` 或 `human_handoff`；
任务证据仍须另行记录 `used / considered / rejected`。

“原生设计语言”指工具的编辑数据模型、组织方式和导出语义，不是品牌审美。选定候选后，
作品必须使用其原生图层、节点、相机、时间线、资产链接或参数关系；只借一个功能再把其余
关键 concern 随意手写，不构成专业工具路径。

每次声称 `used` 均须同时提供：安装或依赖、解析版本、许可、真实调用/导入、对应
concern 的可编辑母版、从母版重建/导出，以及当前最终像素或消费者证据。

额外的写入式专业 proof 只服务 Create/Edit，并且只能在授权 workspace 创建一次性验证副本；
记录原输入 hash、副本中的真实修改、重开/导出和输出 hash，禁止回写原输入。Diagnose/Audit
一律零写入，不创建副本、不保存、不导出、不重建，也不以更新缓存换取“只读”观察。
proof 只证明所测工具 concern，不改变 canonical 或 promotion；最终交付仍须单独记录权威母版、
派生输出 hash 和实际最终消费者证据。

## 1. 结构化矢量插画

- **任务子型：** 编辑/概念插画、图形化人物或物件、需要无损缩放和受控变体的场景资产。
- **需要能力：** 贝塞尔路径、布尔/复合形、语义组、画板/页面、色板/符号、链接资产、
  非破坏外观与精确导出。
- **候选工具 / stable id：** Adobe Illustrator `adobe-illustrator`；Affinity Designer
  `affinity-designer`；Inkscape `inkscape`。
- **原生设计语言或数据模型：** 图层与嵌套对象、路径/节点、共享色板或符号、画板/页面、
  链接或嵌入资产；轮廓和负形由可编辑对象关系形成。
- **权威母版：** 候选工具原生项目；Inkscape 使用保留其编辑语义的 SVG。plain SVG、
  PNG、PDF 和网页预览是 derived，除非合同另设独立 concern。
- **为何选：** 视觉价值来自清楚形状、可控轮廓、缩放、改色或有限变体，且这些关系能由
  对象模型稳定传播。
- **何时不选：** 细腻人体、表情、复杂自然材质、柔性光影或高风险透视是主要难点；
  不因交付格式是 SVG 就选择。
- **替代：** `krita`、`adobe-photoshop`；空间先由 `blender` blockout；
  动画转时间线候选。
- **真实使用证据：** 产品/包版本与许可、真实打开/导入、图层和对象树、原生母版、
  在授权副本中修改轮廓/色板后的重导出、输出 hash、目标尺寸像素。

## 2. 分层数字绘画

- **任务子型：** 人体表演、角色、自然主体、环境气氛、复杂光色和以笔触/边缘为价值的插画。
- **需要能力：** 压感笔刷、画层/组、蒙版、调整/过滤、选区与变换、透视辅助、色彩管理、
  大画布和原生像素检查。
- **候选工具 / stable id：** Krita `krita`；Adobe Photoshop
  `adobe-photoshop`；Clip Studio Paint `clip-studio-paint`。
- **原生设计语言或数据模型：** 像素画层、组、蒙版、非破坏调整、笔刷/纹理资源和颜色配置；
  形体通过绘制、遮罩、边缘与明度层级建立。
- **权威母版：** `.kra`、`.psd/.psb`、`.clip` 或对应原生项目；flattened raster
  只是消费者输出。
- **为何选：** 身体、表情、材质和光需要直接局部塑造，且目标尺寸允许以受控原生分辨率工作。
- **何时不选：** 无限缩放、精确对象复用、多尺寸参数化或复杂镜头传播才是首要合同。
- **替代：** 结构化矢量；`blender` 空间 blockout；拼贴档案处理现成摄影资产。
- **真实使用证据：** 安装/版本/许可、笔刷和纹理来源、真实 GUI/API 操作、命名图层/蒙版、
  原生母版、局部解剖或光色 sentinel edit、原尺寸重导出和最终像素。

## 3. 拼贴与摄影合成

- **任务子型：** 摄影拼贴、扫描材料、档案图像、纸材剪贴、照片与绘画混合的视觉场景。
- **需要能力：** 链接/嵌入资产、Smart Object 或等价结构、蒙版、透视变换、混合与调整、
  边缘/matte、颗粒和颜色空间管理。
- **候选工具 / stable id：** Adobe Photoshop `adobe-photoshop`；Affinity Photo
  `affinity-photo`；Krita `krita`。
- **原生设计语言或数据模型：** 来源资产实例、图层堆栈、蒙版、变换、混合模式和非破坏调整；
  每项素材保持 provenance 与替换能力。
- **权威母版：** 原生分层合成项目加版本化资产清单；源摄影/扫描各自拥有来源 concern，
  导出的扁平图不反向拥有它们。
- **为何选：** 真实影像或物理材料的痕迹不可替代，且合成关系、替换和许可能够被维护。
- **何时不选：** 素材权属不清、相机/光无法统一、合同要求纯原创绘制或纯矢量结构，
  或合成可能冒充事实现场。
- **替代：** 分层绘画、自有/委托摄影、3D 渲染或明确许可素材。
- **真实使用证据：** 工具版本/许可、每项素材来源和许可、真实导入/链接、分层母版、
  替换资产测试、重导出、边缘/光色/颗粒目标像素和披露。

## 4. 3D blockout 与场景辅助

- **任务子型：** 复杂透视、建筑/环境、重复镜头、明确体积遮挡、灯光探索和 paintover 底稿。
- **需要能力：** 场景图、对象/集合、尺度、相机、灯光、材质、约束、渲染设置和 passes。
- **候选工具 / stable id：** Blender `blender`；Autodesk Maya
  `autodesk-maya`；Cinema 4D `maxon-cinema-4d`。
- **原生设计语言或数据模型：** scene graph、对象与数据块、相机、灯光、材质和 render graph；
  画面空间由可编辑三维关系而非二维猜测维持。
- **权威母版：** `.blend` 或对应原生场景项目拥有空间/相机 concern；paintover 母版可拥有
  最终造型 concern，但必须保留从场景到绘画的派生边。
- **为何选：** 空间、机位、体积或灯光的复用收益高于建模成本，并能显著降低透视漂移。
- **何时不选：** 单一简单平面画面、无复用机位，或默认渲染会削弱所需绘画语言。
- **替代：** 绘画软件透视辅助、结构化矢量；需二维空间笔触时使用 Blender 的绘画能力。
- **真实使用证据：** 安装/版本/许可、真实场景文件、对象/集合/相机/灯光结构、来源资产、
  修改相机或对象后的重渲染、passes、paintover lineage 与最终像素。

## 5. 生成图辅助

- **任务子型：** 合同允许的概念候选、氛围、背景或表现性资产；生成结果不自动成为终稿。
- **需要能力：** 模型/版本可追踪、输入与 mask 管理、任务/seed 或等价标识、候选 lineage、
  局部可控修正、使用条款和输出指纹。
- **候选工具 / stable id：** OpenAI Images API `openai-images-api`；ComfyUI
  `comfyui`。其他 provider 必须先以独立稳定 id 进入 Registry。
- **原生设计语言或数据模型：** generation job、prompt、输入图、mask、参数、候选与任务标识；
  它描述生成 lineage，不等同于可编辑场景或分层绘画模型。
- **权威母版：** provenance bundle 拥有生成过程 concern；下游分层绘画、合成或场景项目
  拥有最终构图与修正 concern。单张生成图只可作经许可的嵌入资产或扁平合同终稿。
- **为何选：** 所需世界、气氛或素材不存在，合同允许生成且有能力检查和修正实际风险。
- **何时不选：** Logo、精确图标/文字/数据/地图/技术结构、新闻或科学证据、特定人物，
  或要求结构化可编辑母版而没有下游编辑路径。
- **替代：** 分层绘画、3D、自有/委托摄影、明确许可素材。
- **真实使用证据：** provider/模型/版本/许可、真实 API/工作流调用、输入权利、任务标识与
  输出 hash、候选选择、实际编辑链、下游母版、风险局部和整图复验、消费者披露。

## 6. 分层动效与合成

- **任务子型：** motion illustration、镜头运动、图层动画、时间性视觉层级和合成。
- **需要能力：** composition、图层/precomp、关键帧、曲线/表达式、链接素材、相机、
  帧率/时长、音画关系和渲染队列。
- **候选工具 / stable id：** Adobe After Effects `adobe-after-effects`；Cavalry
  `cavalry`；Blender `blender`。
- **原生设计语言或数据模型：** composition graph、timeline、layer、keyframe、expression
  和 linked footage；运动由时间关系而非导出视频中的不可编辑像素定义。
- **权威母版：** `.aep`、Cavalry 原生项目或 `.blend`；MP4/GIF/帧序列均为 derived。
- **为何选：** 时间变化、层级或镜头本身承担叙事，但不需要复杂角色逐帧表演。
- **何时不选：** 单张静态、复杂角色 acting，或任务真正需要用户交互状态。
- **替代：** 角色动画档案；静态任务回矢量/绘画；交互任务路由到交互解释领域。
- **真实使用证据：** 安装/版本/许可、真实项目与链接源、composition/timeline、帧率时长、
  关键动作区间、首中末帧、重渲染、最终播放与需要时的 reduced-motion 证据。

## 7. 角色、逐帧与故事板动画

- **任务子型：** 人物表演、口型、可复用 rig、逐帧动画、镜头规划和连续叙事。
- **需要能力：** drawing layer、曝光表/时间线、onion skin、peg/rig、deformation、node graph、
  camera、shot panel 和声音同步。
- **候选工具 / stable id：** Toon Boom Harmony `toon-boom-harmony`；TVPaint
  `tvpaint-animation`；Toon Boom Storyboard Pro `toon-boom-storyboard-pro`；
  Blender `blender`（其 Grease Pencil 能力）。
- **原生设计语言或数据模型：** drawing/exposure、层级或节点 rig、镜头、panel/shot 和时间线；
  动作通过帧、曝光和可编辑变形关系存在。
- **权威母版：** 对应工具的原生 scene/project bundle；视频和帧序列不拥有角色或 timing。
- **为何选：** 表演、动作节奏或连续镜头是核心，且需要逐帧或 rig 级修正。
- **何时不选：** 只有轻量平移缩放、单张终稿，或互动规则才是主要价值。
- **替代：** 分层动效；静态绘画；交互/游戏领域。
- **真实使用证据：** 安装/版本/许可、drawing/rig/timeline 或 panel 结构、真实关键帧/曝光、
  局部动作修改、重播/重导出、首中末和高风险动作帧、来源资产与最终消费者证据。

## 8. 程序化图形例外

- **任务子型：** 算法几何、参数化图案、可复现抽象构成或合同要求的批量规则变体。
- **需要能力：** 明确参数、几何/绘制原语、确定性构建、依赖锁定、可测输出和语义映射。
- **候选工具 / stable id：** Paper.js `paper-js`；p5.js `p5-js`；SVG.js
  `svg-js`。直接手写 SVG/Canvas/CSS 不自动成为候选工具。
- **原生设计语言或数据模型：** 代码、参数、场景/路径对象和确定性 build graph；
  输出 SVG/Canvas/raster 是 derived。
- **权威母版：** 版本化源码、参数与依赖 lockfile 的不可拆分 bundle；导出文件不得手改回灌。
- **为何选：** 规则和可重建变化本身是视觉命题，或成熟候选在可运行探针中缺失合同所需能力。
- **何时不选：** 多人、有机人体、手部接触、自然表情、复杂材质或高风险透视只是因为
  “代码方便”；环境未安装不构成能力 gap。
- **替代：** 结构化矢量、数字绘画、3D blockout 或 `human_handoff`。
- **真实使用证据：** 依赖/版本/许可、真实 import/build、候选 capability probe、若自定义则
  记录 fail/gap/最小边界/一致性、源码母版、参数 sentinel edit、确定性 hash 和最终像素。

## Registry 协调规则

上述 stable id 只有在共享 Registry 中存在满足 schema 的 factual profile 后，才能作为
已解析候选。跨领域共用 id 应复用同一事实档案，不按领域复制；领域差异放在本文件的
选择理由、禁用条件和 evidence 要求中。Registry 只证明能力与环境事实，不能替代某次任务的
真实使用记录。
