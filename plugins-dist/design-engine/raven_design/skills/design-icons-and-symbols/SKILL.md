# 图标与符号设计

本 Skill 只拥有符号语义、家族语法、光学尺寸、领域验证和消费边界；通用合同、工具证据、authority
graph、渲染审查与 scoped promotion 服从 `$visual-artifact-design`。文件齐备、样张精致或 Gallery
可见都不等于领域 gate 通过。

成功意味着：符号在声明的消费者、尺度和环境中传达正确对象、动作或状态；权威母版可维护，导出可追溯，证据强度与 claim 一致。不要为了系统感补造语义、尺寸、风格或应用。

## 介质中立与最终消费者合同

本 Skill 保持介质中立。进入设计前先建立 `final_consumer_record`：命名最终消费者、目标介质、实际 runtime/设备/生产工艺、尺寸或观看条件、交付格式和最终验收方式。浏览器预览、Gallery 或说明页只是查看工具；除非 Web 本身就是合同交付，它们都不是最终消费者。

只有最终消费者是 Web 时才调用 `$build-polished-visual-frontends`，由其负责网页技术栈、页面构图、响应式与 Web 最终像素；本 Skill 仍拥有符号语义、家族、光学母版和领域验证。原生平台、字体、动效 runtime、印刷、丝印、雕刻或现场标牌不得为了方便预览而加载该 Web 执行层，也不得用浏览器证据冒充目标消费者。

数字交付的最终像素必须来自合同指定的目标 renderer；物理交付的最终验收必须检查按同版生产文件制作的实体样张及声明观看条件。非最终消费者生成的截图只能诊断，不得晋升为交付证据。

## 路由主型与责任

| 主型 | 本 Skill 的责任 | 必须先确认 |
| --- | --- | --- |
| UI 图标 | 功能语义、平台适配、光学资产、稳定接口 | 真实宿主、既有图标库、平台惯例、方向与最小尺寸 |
| 公共信息符号 | 指代、观看条件、文字/箭头组合和理解证据 | 当前标准、辖区、受众与部署系统 |
| 安全与运营符号 | 误读后果、冗余通道、目标用户验证和审批边界 | 是否已有注册符号、风险责任人、法规与运行场景 |
| 设备符号 | 控件/状态/连接含义及设备落位 | 当前设备标准、面板条件、培训与维护责任 |
| 品牌相关符号 | 已批准身份语言下的微缩版与功能图标 | 身份主体、品牌母版与品牌方授权 |

状态、动效、图标字体和完整家族是主型上的交付修饰，不自动成为新主型。先记录 `route_record`：`final_consumer_record`、上下文、主型、风险、误读后果、协作领域、权威来源和最终批准角色。

- 承担组织、产品或服务主体识别的标志、字标和品牌架构转 `$design-brand-identities`；本 Skill 不自行批准身份。
- 按钮的焦点、命中区、按下、禁用和控件名称由 UI 组件或产品宿主拥有；本 Skill 只拥有图形语义与光学资产。
- 地图比例、图例和空间关系由地图领域拥有；本 Skill 可拥有其中的符号家族。
- 注册安全、公共或设备符号优先复用权威原件；未经标准与责任人授权，不以原创或品牌化改写替代。

### 生产路线

- 权威品牌、公共、安全与设备符号使用批准母版，不生成替代品。
- 搜索、关闭、菜单等标准功能 icon 优先使用真实宿主的既有系统；没有时选择一个成熟 icon 家族，
  不得由模型补画近似 SVG。
- 项目独有、低风险、插画式、空间化或有材质表现的 icon 与 feature pictogram，默认使用
  `image_generate` 创建整个家族：先生成家族母图，再用 image edit 派生变体；不得用手写 SVG、
  CSS 或 Canvas 冒充精致资产。
- 若消费者合同要求矢量母版，使用专业矢量化／图标工具从批准的生成母图建立可编辑母版并保留
  lineage；模型手工描 path 不算专业母版。
- 只有字符、数据、坐标、拓扑、光学尺寸或标准几何本身是 claim 时，才进入精确矢量工具路线。

生成 icon 不烘焙关键文字、logo 或数字；语义名称、状态与无障碍文本由宿主拥有。生成工具不可用
是能力缺口，不授权切换到手写 SVG。

图标容器、彩色底、边框、色条和命中区由宿主拥有，只有平台惯例、可触达尺寸、容器形状或真实状态
要求时才随图标出现；任意彩色方框或竖线不是家族语法。视觉权重按动作风险、频率和状态分配，不按
每个图标等权。样张背景、CSS 包装与展示说明只能提供上下文，不能替代符号本身的语义、光学和家族
证据；必要限制贴近受影响符号，但不自动成为最强视觉对象。

## Claim ceiling 与 authority

`SELF_REVIEW_ONLY` 最多支持构造、协议、矢量工程和明确标注的内部语义风险检查；它不能支持目标用户理解、法规符合、现场有效或发布授权 claim。

`internal-positive` 只覆盖当前 build 中被内部证据支持的精确机制；`externally-validated` 必须由非作者、角色匹配且绑定同一 `build_hash` 的 coverage 覆盖每项 promoted claim。release、canonical、lifecycle 与 positive pool 始终分开。

为每个 concern 指定唯一 authority owner：语义/标准原件、几何与光学母版、状态模型、生产导出、宿主行为、发布配置分别建节点；截图、样张、sprite、组件包和 Viewer 都只是 derived，除非合同明确将其原生结构设为该 concern 的权威源。

## Tool selection 接口

先列所需能力，再查 [工具能力档案](references/tool-profiles.md) 和共享 Tool Registry。选中工具后，使用其原生数据模型、组件/变量、母版与导出关系，不只借一个功能后手写其余系统。工具选择记录必须包含上述 `authoritative_master / standard_symbol / generated_visual / exact_vector` 之一；不存在 `manual_svg` 路线。

工具只有在依赖/安装、解析版本、许可、真实调用、可编辑母版、重建/导出以及当前像素或消费者证据齐备时才能记录为 `used`。GUI、商业或当前环境不可运行的候选记录为 `unavailable` 或 `human_handoff`，不得模拟使用。

自绘、自研或自建导出链前必须执行 capability probe。只有在可运行条件下对所需能力得到 `fail`，才记录 `gap / minimal_custom_boundary / coherence_evidence` 并只实现缺失边界；`unavailable` 只触发替代候选或人工交接。

专业工具的写入型 proof 服从任务模式：仅 `Create/Edit` 可在明确授权的 workspace 创建一次性验证副本，并记录输入 hash、实际操作、重开/导出结果和 proof hash；`Diagnose/Audit 一律零写入`，证据不足就降低 claim。验证副本与最终交付分别记录 hash，proof 不得改写权威母版、canonical 指向或 promotion 状态。

## 领域 gates

### G0 `ROUTE_AND_RISK`

- **输入：** 请求、最终消费者、目标介质、宿主或生产链、部署位置、误读后果、辖区与已有资产。
- **动作：** 判定主型和协作领域；先查注册符号、平台库和项目母版；绑定实际 renderer/工艺与最终验收；按伤害与可逆性确定风险。
- **晋升证据：** `route_record`，含 `final_consumer_record`、标准/平台来源、风险责任人、适用与排除范围。
- **Claim ceiling：** 只能声明路由、已知约束和待验证假设。
- **失败返回：** 主对象不属于本领域则重新路由；权威来源或责任人缺失则等待或停止，不进入原创。

### G1 `CONTRACT_AND_TOOL_READY`

- **输入：** 稳定语义名、对象/动作/状态、最近邻、禁读项、真实尺寸、方向、介质、最终消费者和交付接口。
- **动作：** 分开语义状态、视觉样式与宿主交互状态；按 claim/risk 生成验证计划；选择工具、母版 concern、导出路径和最终验收证据。
- **晋升证据：** `contract_and_unknowns`、工具比较/选择记录、authority graph 草案、介质相称的验证与冗余计划。
- **Claim ceiling：** 设计合同与工具计划；不得声称语义已理解或资产可部署。
- **失败返回：** 语义、消费者或标准事实不足则补输入；工具不可用则换候选或 `human_handoff`。

### G2 `SEMANTIC_FIT`

- **输入：** 权威原件或候选、语义证据卡、最近邻集合、风险相称的测试刺激与判定计划。
- **动作：** 先做无标签首读、指代关联和知觉检查；高风险或公共 claim 使用目标用户与当前正式方法，保留危险误读方向。
- **晋升证据：** 内部检查记录，或目标用户原始回答、编码规则、混淆矩阵、测试条件、限制和角色匹配 review。
- **Claim ceiling：** 自检只支持内部候选与协议 claim；目标用户 coverage 只支持其命名人群、环境和语义。
- **失败返回：** 回语义骨架或候选；危险误读未解除时保留文字、声音、触觉或其他冗余。

### G3 `SYSTEM_MASTER_READY`

- **输入：** 通过当前语义范围的候选、选定工具原生模型、真实消费者尺寸、家族与兼容约束。
- **动作：** 建立权威可编辑母版、受控家族语法、必要光学尺寸、稳定 ID 和确定性导出；只生产合同需要的变体。
- **晋升证据：** 工具使用证据、`master_manifest`、重开/导入、节点/布尔/负形检查、构建轨迹、输出 hash 与真实尺寸像素。
- **Claim ceiling：** 可声明指定母版、导出和光学资产通过技术检查；不推导理解、现场或发布 claim。
- **失败返回：** 几何或光学问题回母版；原生模型不适配回工具选择；语义因修形改变则回 G2。

### G4 `CONSUMER_ENV_VALIDATED`

- **输入：** 同一 build 的生产资产、真实宿主/样片、目标尺寸、主题、方向、状态、环境与任务。
- **动作：** 真实导入平台资产、组件、sprite、字体、播放器或物理生产链；按 [领域模式](references/patterns.md) 分开浏览器 DOM/SVG、computed-style、目标 renderer 和实体样张证据，并分开验证资产消费者与人类消费者。
- **晋升证据：** 最终消费者的真实接口、目标 renderer 最终像素或同版实体样张，以及适用的可访问名称/RTL/状态、目标用户任务或现场证据。
- **Claim ceiling：** 只支持已测试消费者与命名条件；非 Web 媒介不能用浏览器证据晋升，实验室成功不外推现场。
- **失败返回：** 裁切/样式/像素失败回 G3；稳定误读回 G2；环境假设错误回 G0/G1。

### G5 `RELEASE_AUTHORIZED`

- **输入：** 当前 build、通过的适用 gates、authority/tool/review 证据、许可、标准、冗余与回滚计划。
- **动作：** 由平台、工程、品牌、标准、运营或安全责任人按 concern 和部署范围签认。
- **晋升证据：** `approval_ledger`、发布 manifest、版本与 hash、适用范围、排除项、弃用/回滚和独立 coverage。
- **Claim ceiling：** 最多声明被明确批准的命名 scope；是否 released/canonical 仍由对应 registry 决定。
- **失败返回：** 返回否决 claim 的最早因果 gate，不重做无关已通过工作。

## 停止、promotion 与交付

- 已有权威符号满足语义和许可时复用，不为展示创造替代图形。
- 新颖高风险符号缺少目标用户、标准或运营批准时，止于候选并保留冗余；不得自批安全部署。
- 同一路径只被缩放不等于光学尺寸母版；触控容器尺寸也不是图形尺寸。
- 描边、填充、主题和动效只有在同条件仍同义时才可作为变体；宿主交互状态不偷塞进资产名。
- 去掉宿主色条、边框和样张背景后，符号仍须保有其语义、光学关系和家族归属；否则返回 G2/G3。
- 母版、导出、消费者和证据 hash 不一致时，旧 gate/review/promotion 不继承到新 build。

需要语义卡、光学检查、标准路由、包装和消费者矩阵时读取 [领域模式](references/patterns.md)。只为通过精确 scope 的记录创建 `whole / component / protocol / diagnostic / negative` identity，并如实填写 `positive_for / not_evidence_for / excluded_claims / claim_ceiling`。

交付权威母版、批准导出、语义/ID/状态清单、最终消费者接口、最终像素或实体最终验收和当前证据；明确工具状态、测试人群与条件、assurance、未覆盖风险和批准范围，不用预览样张或说明文字替代任何一项。
