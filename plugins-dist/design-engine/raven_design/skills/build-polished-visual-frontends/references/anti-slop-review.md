# 反模板渲染审查

按操作模式、变化范围和风险触发本文件中的适用审查门槛，不固定执行三轮。只根据真实渲染像素和可操作状态判断，不根据源码、组件名、测试数量或设计意图脑补。独立 `review` 不可用时，所有视觉结论统一标记 `SELF_REVIEW_ONLY`；这是证据来源，不是独立通过状态。

## 1. 建立证据组

从 `visual-artifact-design` 的输出合同选择实际需要的证据，不机械截图：

- **固定产物**：缩略图、目标尺寸、局部放大；
- **多目标环境页面（仅当合同声明）**：合同列出的目标视口，以及内容最密和最空状态；
- **产品界面**：初始、加载、空、错误、操作中、成功、冲突或恢复等关键状态；
- **数据、地图和图解**：全局、最密标签、极端值、图例/注释和交互选择；
- **动效与仿真**：起始、中间、结束、暂停、重置和 reduced-motion；
- **Canvas/WebGL/游戏**：非空像素、主要输入、失败/降级、典型玩法和性能状态；
- **编辑与印刷**：封面/首屏、连续内容、图文混排、导航、打印或导出结果。

每个证据标注源版本、视口、状态和生成时间。Create 与大改的方向证据必须包含代表性非空工作态，而不只有空态；测试 fixture 只用于检查状态，最终证据不得出现测试文件名、调试 UI 或临时提示。最后一次编辑之后重新生成最终证据。

长页和多页面产物同时保留两种尺度：完整页面／页面族证据用于观察节奏、重复与一致性；每个顶层
区块和页面族另有可读尺度证据，用于检查文字、图文关系、控件、边界与状态。把整页压成一张长缩略图
只能证明轮廓，不能据此宣称每一部分已经完成。

先以整图和缩略图观察，不先放大局部。整体结构不成立时，修圆角、图标和字距没有意义。

## 2. 按风险触发审查门槛

这些门槛互不构成固定顺序或固定次数。Create/大改可以依次触发多个门槛；单点 Edit 只检查受影响层和最终证据；Diagnose/Audit 使用“复现 → 根因 → 只读复核”，不为走流程制造新方向、系统或源文件修改。

### 方向门槛：方向是否成立

仅在 Create、新建视觉方向、大改，或方向存在实质不确定性的 Edit 中，于首个纵切片完成后检查：

- 三秒内能否说出产物是什么、面向谁、当前最重要的内容或动作；
- 第一视觉是否来自用户任务中的内容、数据、场景、工作对象或领域模型，而不是组件库 demo、题材 skin 或模型自创的视觉理由；
- 当前可查看的用户已接受参考所形成的受保护不变量是否保留；没有参考时不得虚构不变量；
- 外部标杆中被明确授权迁移的机制是否可见，还是只引用了名称；
- 领域特异性是否来自真实对象、数据、关系、操作或叙事机制，而不只来自标题、题材色和行业图标；
- 基础组件是否保持选定设计系统的一致 anatomy、尺寸、字体角色和状态视觉；导航、面板、工作面、列表、通知和自定义组合组件是否延续同一系统，而不是另造一套外壳；
- 若主要领域确实需要标志性表达，技术路线能否自然完成；产品、比较、治理和高密工具则以简单、清楚、任务特异的结构为准，不为满足通用层建议增加装饰。

方向不成立时停止扩展，先改构图、资产或技术路线。状态按第 6 节记录；`SELF_REVIEW_ONLY` 不得写成 `PASS`，也不能用于保留尚未修复的问题。

### 系统门槛：系统是否一致

仅在多页面、多状态、合同内目标环境、共享资产/组件或系统规则发生变化时，于完整受影响范围形成后检查：

- 信息层级、网格、间距、字体、颜色、图标、图形和动效是否属于同一系统；
- 对照组件库真实样张与系统风格合同，字体角色、密度、间距、圆角、边界、阴影、表面、图标和反馈是否有可核对的继承或映射；
- 临时遮住现成控件后，剩余页面是否仍像该设计系统自然扩展出的同一产品；若只剩一套平行皮肤，系统检查失败；
- 重复结构是否由同一 token 和数据源驱动；
- 不同章节或状态既可辨认又不会像不同项目；
- 目标环境适配改变关系与优先级，而不是缩小和堆叠；
- 内容最密、最长、最空和错误状态是否仍然有节奏；
- 适用的标志性表达是否被后续装饰稀释；不适用时，任务主线是否被包装抢走。

### 最终门槛：修改后的像素是否精致

仅在本轮实际修改了可见产物、源文件或派生输出时，于交付前检查：

- 对齐、基线、裁切、边缘、图像质量、行宽、断行和焦点环；
- 颜色和材质是否干净，没有脏灰、混乱阴影和无理由透明；
- 每个次要信息仍然清楚，不靠过小或过浅来隐藏；
- 动效起止、缓动、叠层和 reduced-motion 是否自然；
- 所有实质问题是否按影响修复并重渲染；
- 是否仍有任何不承担任务的配饰；有则删除，没有则保留现状，不为制造修改移除必要内容。

### 正向完成度门槛：不是无错即完成

反模式图鉴只回答“没有落入哪些已知病体”，不能回答“这个产物为什么值得记住”。Create 和可见大改在
最终门槛中另做一次正向完成度检查：

- `VISUAL-THESIS` 是否由具体世界、张力和记忆点构成，而不是一组风格形容词；
- 命题是否逐区进入最终产物的背景、排印／规则、内容结构、交互／运动，而不是只集中在三处亮点或首屏；
- 适用内容型／营销型 Web 时，主视觉是否在布局前真实取得与查看；每个主要页面族是否有预先锁定
  的视觉角色、资产 lineage 与开场证据，`dominant_background` 是否真的主导开场，其他角色是否有
  任务证据且没有退回默认模板；
- 主视觉的真实色域、光线、边缘、材质和空间节奏是否反向影响了页面排版与 token，而不是被塞进一套已完成的皮肤；
- 主视觉、章节图、纹理与表现型 icon 在缩略图下是否像同一家族，不只是色相相同；
- 排印中的中文标点、中西文混排、数字、字重、断行和孤行是否逐项检查；
- 边界／表面、图标家族、hover/focus/selected/empty/error/loading、有职责的运动与目标环境适配是否同属一个系统；
- 各目标画幅的主视觉是否有可用焦点或 image-edit 派生版，sticky 表面是否遮挡锚点、标题或下一步。
- `SURFACE-MANIFEST` 是否覆盖所有顶层区块和页面族，每一行都已用真实内容在可读尺度下检查；
  是否仍有默认组件、文字倾倒、模板余料或只完成工程功能而没有完成设计的区域。
- `COMPONENT-BEHAVIOR-MAP` 是否覆盖所有独特行为类和视觉交互暗示；全部实际目标是否由浏览器自动
  遍历，独特状态与例外是否产生与暗示一致的动作、状态和反馈。

必须执行两个返工测试：

- **替图测试**：若主视觉换成任意同题图库图后，版式、token、边界与细节都无需变化，返回视觉命题与母版；
- **模板距离测试**：若只替换文案、色相和图像即可还原参考模板，或身份只存在于一张背景，返回代表画面。

## 3. 分项观察

### 构图与层级

- 在 25% 缩略下标记第一、第二、第三视线；三者应与任务优先级一致；
- 检查大区块轮廓是否稳定，主角是否获得足够面积；
- 检查每个边缘和留白：是有意停顿，还是组件凑不满留下的洞；
- 检查是否因平均分栏、等宽卡片和连续居中形成机械节奏；
- 检查重要内容是否被导航、装饰、浮层或指标抢走注意力；
- 每个视图只保留与任务权重一致的主要焦点。比较、治理、资产交接和高密工具可以有多个同级对象，不为制造高潮破坏公平比较。

### 文字与信息

- 在实际观看距离阅读标题、正文、标签、日期、来源、单位、图注和错误；
- 检查中文标点、字重、数字、西文混排、长词、孤行和多行按钮；
- 检查同层文字是否承担同一种职责，不用字体变化装饰无差异内容；
- 检查文案是否从用户认识的对象与动作出发，而不是系统术语和营销填充；
- 检查灰色小字是否在掩盖信息架构问题；该升层级就升，该删除就删。
- 对浏览器产品界面枚举最终文字角色：正文通常从 `16px` 起，持续辅助文字通常从 `14px` 起；`12–13px` 只保留少量、高对比且非关键的刻度、单位、时间戳。每个低于 `14px` 的保留项必须逐项有任务理由，不能以“紧凑”统称。

### 色彩与材质

- 列出画面实际使用的背景、文本、强调、状态和数据颜色，找出没有职责的颜色；
- 检查冷暖灰是否混用、黑色是否脏、白色是否被不必要的透明层污染；
- 检查渐变、阴影、描边、纹理和模糊是否表达层级或材质；
- 检查是否把细描边、浅色填充和圆角同时重复到容器、选中行、通知与状态区；一个表面只使用完成职责所需的最少信号，不把三种信号机械叠加；
- 在照片、图表和深浅背景上分别检查文字与控件对比；
- 用灰度或色觉模拟辅助检查层级，但不能以此代替实际颜色判断。

### 图像、图形与数据

- 每张图写一句“它证明/解释/建立什么”；写不出就删除；
- 检查裁切、清晰度、人物/物件异常、风格一致性和来源；
- 纯氛围／世界构建图是否只在 provenance 记录生成边界，没有把制作过程叠进成品；事实误认风险
  需要披露时，页面说明是否贴合内容语境，说明后仍会误认的资产是否已经移除；
- 图表检查尺度、单位、来源、图例、注释、极值和不确定性；
- 地图检查位置、投影、比例、方向、标签和图层冲突；
- 技术图检查拓扑、箭头、编号、局部放大和阅读顺序；
- 不允许氛围图看起来像事实证据，也不允许生成图承担精确数据职责。

### UI、交互与状态

- 对照组件库实际样张检查页面外壳与自定义区域，不只检查导入的按钮和输入框；它们的字体、密度、圆角、边界、图标、反馈与动效必须属于同一视觉语言；
- 品牌尚未定义时使用克制的文字标识，不把通用线性图标塞进彩色圆角方块冒充 logo；标题只在图标承担识别、状态或动作职责时配图标；
- 每个可见控件有明确 affordance、真实动作和反馈；反向检查所有按钮轮廓、链接样式、chevron、
  hover/focus、selected/current、可点击卡片、行高亮、标签页和 disclosure，首次使用者若会把它理解为
  可操作，就必须兑现行为，或改成明显的静态表达；
- 不按 DOM 类型抽样。真实浏览器中遍历每个可见实例，记录触发前状态、输入、可见结果和恢复／下一步；
  重复组件可共用视觉状态证据，但每个实例的目标、链接或数据结果仍须实际检查；
- hover 不是唯一入口；键盘焦点可见，弹层和菜单不截断；
- loading、empty、error、success 与最终布局同一视觉语言，不用通用插画填充；
- 高频任务减少视线和指针移动，危险动作与恢复路径清楚；
- 动效解释反馈、因果、空间或时间，零散 hover 动画不应比任务更活跃；
- 每个合同内目标环境都保留任务连续性，不把一个画幅中的并列关系拆成无上下文页面。

## 4. 常见 AI 症状与修复

本节症状的真实标本收录在图鉴 `anti-slop-gallery/` 中。先读索引，再按任务与代表画面的高／中风险
读取对应标本；终态对完整产物做一次全局扫描，新发现的风险补入 `ANTI-SLOP-CHECK.md`。命中用于
返回根因，不等于把同组所有合法能力删除。

| 可见症状 | 常见根因 | 优先修复 |
| --- | --- | --- |
| 首屏像任意 SaaS | 页面由组件或需求清单产生，没有由任务关系产生 | 重建主对象、证据、判断和命令的空间关系，让真实对象/数据/场景成为第一视觉 |
| 所有内容都是卡片 | 用组件容器代替信息关系 | 连续内容移出卡片，用分区、留白、对齐和分隔表达关系 |
| 灰色小字遍地 | 不敢决定信息优先级 | 提升必要信息，合并重复标签，删除无用元数据 |
| 组件本身精致，外围却粗糙或风格割裂 | 把组件库当控件仓库，项目外壳另造 token 与皮肤 | 以组件库真实样张建立系统风格合同，让导航、面板、工作面、列表和反馈全部继承或映射同一语言 |
| 细边框、浅填充、圆角到处成套出现 | 用三种弱信号反复包装内容 | 按职责只留边界、底色或间距中的必要信号，优先用排版、对齐和留白建立层级 |
| 彩色圆角图标被当作 logo，标题前也到处有图标 | 没有身份系统或信息层级，只能靠通用图标装饰 | 没有真实品牌时使用文字标识；只为需要识别、状态或动作的地方保留图标，并统一图标语言 |
| 标题或图标旁出现白条、强调轨、局部边框或角括号 | 用装饰假装层级或“品牌细节” | 若不编码选择、状态、进度、尺度或真实分组，全部删除并用对齐、尺度和留白重建层级 |
| 产品 UI 被题材固有色或材料联想染满 | 把行业/主题名词字面翻译成 chrome，缺少有证据的颜色角色 | 回到选定设计系统或标杆的颜色关系；题材色只留在有语义的对象，除非用户、品牌或同类生产标杆明确证明全局色域 |
| 蓝紫渐变或暗色霓虹显得“科技” | 没有技术对象和测量语言 | 展示真实结构、状态、尺度和仪器逻辑，删掉氛围效果 |
| 图片很好看但不相关 | 素材按氛围而非任务选择 | 改用能证明人物、地点、物件或过程的资产 |
| 一个目标环境成立，另一个退化成组件堆栈 | 只做等比缩放或机械单列 | 重新定义该目标环境中的任务、顺序、切换和可达动作 |
| 画面脏、元素很多 | 用添加解决每个问题 | 先删重复标签、容器、装饰、颜色和阴影，再重排 |

症状表用于定位根因，不是把一种固定极简风格强加给所有任务。高密、华丽、米色、霓虹和大量运动都可能成立，但必须由内容和领域证明。产品 UI 若偏离清洁中性色基线，还必须有用户/品牌明确要求或已检查的同类生产标杆；仅凭主题联想不算证明。

## 5. 高影响问题协议

Create/Edit 实际修改了可见产物、源文件或派生输出时，在最终交付前执行；Diagnose/Audit 只对现有证据记录高影响问题，不为执行本协议写入权威源或制造 finding：

1. 在整张渲染上指出所有会实质影响主任务、可信度、可读性或完成度的具体位置；若没有，记录同尺寸复验依据；
2. 每处只描述可见症状，例如“右侧图注像被遗忘的灰字”，不要先辩解设计意图；
3. 判断根因属于内容、层级、构图、字体、颜色、素材、组件、状态还是技术；
4. 优先做能同时改善多个症状的一组修改；
5. 修改后在同一视口和状态重渲染并对比；
6. 若修复让其他位置恶化，继续调整，不把局部截图当通过证据。

每项记录：`位置与症状 / 为何降低质量 / 根因 / 修改 / 重渲染证据 / 是否引入新问题`。

以下为跨视觉前端的 blocker；任一存在都返回修改，其他优点、功能数量和测试数量不能抵消：

- 第一视觉与用户主任务或主要内容对象无关；
- 内容型／营销型 Web 的主视觉在页面布局完成后才补入、可以任意拆换；页面族未声明视觉角色，
  `dominant_background` 退化成普通图卡，或其他角色被用作返回默认模板的借口；
- 页面通过反模式检查，但视觉命题只停留在首屏或少数亮点、没有逐区进入最终像素，或最终文档仍
  留有“待回填／待检查／计划规避”；
- 首屏或代表帧精致，但后续区块、长页下半部或次级页面仍是默认排版、模板余料、内容倾倒，或没有
  最后一次修改后的可读尺度证据；
- 任何元素借用按钮、链接、选择、展开、标签页或可点击卡片的视觉示能却没有相应行为，或真实动作
  没有可见反馈；
- 主要对象没有与重要性相称的面积，或整体只能靠局部放大才成立；
- 产品界面出现低对比微文案，或信息层级依赖微型灰字、重复眉题和无职责标签；
- 装饰轨、强调条、局部边框、角括号、图标外框、伪元素线段或标题旁竖线不编码选择、状态、进度、尺度或真实分组；
- 同一颜色承担互相冲突的交互、状态、数据或环境语义；
- 领域特异性主要来自题材色、行业图标和装饰文案；
- 成熟设计系统的基础组件被无能力缺口、无外部证据地系统性重画；
- 成熟控件与项目外壳分别使用两套字体、密度、灰阶、圆角、描边、阴影、图标或反馈语言，或项目 token 无法映射回选定设计系统；
- 用户已接受参考的受保护不变量发生无授权退化；
- 最终证据含测试命名、调试 UI、临时状态或早于最后一次修改。

## 6. 独立 review 输入

`review` 可用且当前运行配置允许时才调用。用户或运行配置明确给出的调用上限是客观边界；是否调用、何时复审和何时继续由模型根据任务风险与 reviewer 结果自主判断。Runner 不裁决视觉阶段，本参考也不得鼓励模型拆分 focus 绕过明确上限。

向独立 review 提供：

- 用户原始请求和不可变要求；
- 当前实际可查看的用户参考、外部标杆帧及只允许比较的机制；
- 从用户已接受参考提取的受保护不变量及对应证据；
- 最新完整渲染、关键状态和理解任务所必需的对象/交互事实；
- 已知硬限制，但不提供模型的视觉命题、设计理由、实现成本、测试数量、自我评分或暗示期望结论。

请求 reviewer 优先找可见缺陷、主题不匹配、信息错误和交互断点。`review` 被调用不等于通过；必须保存其 `pass / revise / blocked` 结果并执行后续动作。收到 `revise` 后先修改并重渲染；只有明确上限仍允许且模型判断尚有实质风险时才复审。

工具不可用时，不模拟调用或伪造 `pass`。从上述受限输入中按风险选取适用 focus，对最新渲染做隔离自检；每项记录 `问题 / 证据 / finding / 修改 / 重渲染`。方向与最终状态均写为 `SELF_REVIEW_ONLY`，交付说明“已完成像素自检，未完成独立 review”。

## 7. 最终通过条件

硬性条件全部满足：

- 无错误内容、失效操作、不可读文字、裁切、重叠、破图和虚假状态；
- 主要视口、关键状态、键盘和适用的 reduced-motion 有实际证据；
- 图像、数据、地图和技术关系的来源与语义可信；
- 最终证据生成于最后一次修改之后。

判断条件形成一致结论：

- 首屏清楚完成单一任务；
- 视觉方向来自用户任务、内容与有权限的外部证据，不由模型题材联想自行授权；
- 适用主视觉门槛时，母版在代码布局前真实完成；每个主要页面族都有经证据支持的视觉角色与同源
  资产关系，并已影响排印、结构或交互；
- 每个顶层区块和页面族均达到成品状态，并有可读尺度终态证据；完整页面没有“首屏之后自动完成”的
  默认区，也没有用长截图缩略图掩盖局部粗糙；
- 所有真实控件与视觉交互暗示均已逐个归类和实际操作；可交互者有行为、状态和反馈，静态者不伪装
  成控件；
- 识别、传播、叙事或玩乐任务有一处主题特异表达，其余部分克制；比较、治理和专业工具则由对象、工作面、命令、状态或输出形成领域辨识，不靠题材 skin；
- 字体、颜色、空间、资产、组件和运动属于同一世界；
- 替图测试、模板距离测试与正向细节检查已按最终像素结账；
- 与标杆相似的是机制与完成度，不是可识别的视觉复制；
- 所有实质问题已按影响发现、修复并重渲染，或有无实质问题的复验证据。

任何硬性条件或 blocker 失败都返回修改。判断条件无法达成一致时，不虚报“完美”；明确保留分歧并请求用户选择。只有独立 `review` 才可以报告其 `PASS`；无独立 reviewer 时，即使所有自检问题已经修正，最终审查来源仍保持 `SELF_REVIEW_ONLY`。
