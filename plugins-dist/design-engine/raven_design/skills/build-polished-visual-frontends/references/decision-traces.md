# Few Shot 决策轨迹

仅在需要观察“如何从 brief 走到实现”时读取。以下是经过匿名化和抽象化的决策示例，只示范判断顺序、证据类型与修正机制；它们不是 CSS、配色、字号、布局、组件树或技术栈模板。新任务必须重新研究标杆并从自身内容推导形态；若产物与示例的表面结构趋同，应视为路由失败。

## 目录

1. 产品工具：连续处理有状态对象
2. 编辑内容：以多类证据支撑论点
3. 数据故事：比较群组与时间变化
4. 交互解释器：用干预揭示动态规律
5. 跨示例规律

## 1. 产品工具：连续处理有状态对象

### Brief 读取

- 用户反复接收对象，检查与修改内容，添加结构化记录，交给他人确认，并导出可追溯结果；
- 主任务是持续推进对象生命周期，不是阅读主题知识，也不是查看一张概览；
- 自然形态通常是工作区，但工作流、对象尺度和使用频率决定构图，不能从“工具”直接推出固定应用壳。

### 否决的默认答案

- 用导航、指标和等量卡片先拼出通用后台，再把任务内容填进去；
- 用题材相关的装饰符号代替真正的工作对象；
- 把导入、确认、冲突、恢复和导出做成静态成功态。

### 标杆机制

- 从成熟生产力工具学习对象生命周期、队列分诊、批量操作，以及操作后保留上下文；
- 从相应领域的专业软件学习工作对象的视觉优先级、高低频属性的分配和高频动作的可达性；
- 只迁移信息与交互机制，不复制品牌外壳、栏目、快捷键、术语或构图。

### 审美与技术决策

- 第一视觉是当前工作对象与可采取的下一步，不是欢迎语或宣传指标；
- 信息按真实处理顺序建立连续关系，不预设栏数、侧边位置或面板比例；
- 通用框架管理对象和状态，成熟无障碍原语承担菜单、弹层和反馈，专业领域引擎承担难以可靠自制的核心能力；
- 界面材料保持清晰和克制，让工作对象、异常与少数状态角色成为重点；
- 不为追求“全自制”重写复杂选择器、对话框或领域编辑内核。

### 渲染发现与修改

- 发现：对象主键、状态、时间和帮助被统一降级，画面看似整洁但无法快速扫描；
- 根因：把低对比当作层级，并让所有元数据同时占据第一层；
- 修改：提升决定下一步的字段，合并重复说明，把低频帮助改为按需出现，并减少无职责容器；
- 复验：在最大信息密度、冲突、失败恢复和窄视口中检查任务是否仍连续。

### 可迁移结论

产品工具的完成度来自对象、状态、动作和恢复被清楚组织。成熟组件提供可靠行为，领域工作流决定构图。

## 2. 编辑内容：以多类证据支撑论点

### Brief 读取

- 产物要让读者通过叙述、人物或场所材料、数据和方法说明形成理解；
- 主任务是按作者组织的顺序阅读、比较证据并形成观点，不是操作内容管理界面；
- 自然形态是连续的编辑阅读体验，篇幅、证据类型和阅读环境决定分页或滚动方式。

### 否决的默认答案

- 把纸张色、超大衬线标题、细线和编号当作自动成立的“编辑感”；
- 用应用导航、控制面板或指标卡代替章节结构；
- 用与证据无关的抽象图像填补内容空缺。

### 标杆机制

- 从成熟编辑出版物学习章节语义优先、可容纳异质内容的网格，以及字体按信息角色分工；
- 从严谨纪实与研究交付学习图像、引语、数据和图注分别承担何种证据责任；
- 不复制栏目名、专有字体、品牌符号、封面构图或具体色彩答案。

### 审美与技术决策

- 第一视觉由一个明确论点与最有解释力的证据共同建立，不使用通用应用导航；
- 连续阅读、证据展开和短暂停顿形成节奏；具体比例与穿插方式由内容推导；
- 内容框架负责章节与合同内目标环境，成熟图表能力负责可核验数据，动效只在帮助理解顺序时使用；
- 缺少授权图像时，可以创作有清楚真实性边界的视觉重现；纯氛围资产只记 provenance，存在事实
  误认风险时才用内容语境说明，无法消除误认则不用；
- 色彩从题材、媒介和信息角色推导，不把某种惯用“高级色”当作默认。

### 渲染发现与修改

- 发现：开场同时争夺注意力的元素过多，没有稳定的第一视线；
- 根因：每项背景信息都被误判为必须在开场突出；
- 修改：只保留核心论点、关键证据和必要归属，把方法、日期与详细说明放回最相关的阅读位置；
- 复验：检查缩略图重心、正常行宽、图注归属、证据顺序和高约束目标环境中的阅读连续性。

### 可迁移结论

编辑产物的视觉品质来自内容顺序、证据角色和阅读节奏。“像某类杂志”不是视觉方向。

## 3. 数据故事：比较群组与时间变化

### Brief 读取

- 用户要比较多个群组或时期的速度、规模、差异与目标距离；
- 主任务是看见规律并理解证据，不是管理产生这些数据的业务对象；
- 自然形态可以是滚动叙事或探索视图，由比较任务、注释密度和读者自主性决定。

### 否决的默认答案

- 用固定数量的指标卡和一组常见图型拼成业务看板；
- 用题材惯用色和象征图标代替数据论点；
- 把单位、来源、关键值和不确定性都藏进悬浮提示。

### 标杆机制

- 从成熟公共数据产品学习完整统计语境、与任务匹配的编码、来源与单位，以及等价表格；
- 从严谨数据叙事学习一幅图只推动一个主要论点，注释与正文共同建立阅读顺序；
- 不复制任何机构的色板、字体或某张图的独特版式。

### 审美与技术决策

- 先写可被数据反驳的论点，再决定图型和交互；
- 让承担主要比较的图形成第一视觉，次级证据按论证关系出现，不机械均分容器；
- 选择能直接标注、保持统计语义并提供可访问输出的成熟可视化能力，只有交互复杂度确实需要时才升级引擎；
- 图、标签、摘要、筛选和替代表格来自同一数据源；
- 色彩编码类别、顺序、阈值或偏离，不为装饰增加随机色。

### 渲染发现与修改

- 发现：曲线或图形醒目，但统计语境被压成低对比小字，读者无法独立核验；
- 根因：把必要的单位、来源与关键值误判为次要元数据；
- 修改：把单位放进标题或坐标语境，直接标注关键值，把来源放在稳定可见的位置，并删除重复图例和装饰指标；
- 复验：覆盖极端值、最密标签、合同内高约束画幅、键盘探索和表格替代。

### 可迁移结论

数据产物的美首先是比较关系清楚、尺度诚实、注释精确。图表库默认主题和看板皮肤不能替代判断。

## 4. 交互解释器：用干预揭示动态规律

### Brief 读取

- 用户需要改变若干条件，观察系统随时间或状态变化，并区分不同参数的作用；
- 主任务是干预模型并形成因果理解，不是持续监控真实设备；
- 自然形态可以是连续微实验、分步叙事或单一互动舞台，由学习顺序决定，不预设控制台。

### 否决的默认答案

- 一次摆出完整示意、所有滑块、多个读数和完整曲线；
- 用科技感背景、粒子或仪表盘外观冒充模型深度；
- 同时开放全部参数，把发现规律的责任推给用户。

### 标杆机制

- 从优秀解释性作品学习从可观察现象进入、一次只增加一个变量或表示，并用文本触发有意义的预设状态；
- 从严谨模型展示学习公式、图形、状态与解释必须互相指向；
- 不复制标杆的题材、模型、配色、代码、着色器或控件样式。

### 审美与技术决策

- 把学习目标拆成一组因果递进的微实验，每段只开放当前问题所需的主干预；
- 动作、现象、关键读数和即时解释保持可互相核对，具体位置由媒介与内容决定；
- 应用状态由同一个模型驱动；图表、公式和动效仅在各自能澄清规律时出现，成熟控件原语承担输入行为；
- 专用视觉资产必须对应模型实体或过程，不能用无关特效制造复杂感；
- 先确保用户能描述观察，再逐步引入抽象表示。

### 渲染发现与修改

- 发现：功能完整但开场同时出现任务、公式、多个输入、读数与图线，体验像参数表单；
- 根因：按功能清单组织画面，而不是按理解顺序组织体验；
- 修改：冻结非当前变量，延后公式和完整历史，只让第一步呈现一个可观察、可解释的现象；
- 复验：先检查用户能否不用公式描述观察，再检查完成递进后能否区分不同参数对结果与变化速度的影响。

### 可迁移结论

解释器的视觉价值应集中在模型和理解路径，而不是控制面板的丰富程度。

## 5. 跨示例规律

四个示例的外观、题材和工具不应被复用，但决策方法一致：

1. 先按用户主任务选择领域，不按 HTML、框架或文件类型选择形态；
2. 标杆提供机制和质量高度，不提供可复制皮肤；
3. 成熟库负责通用能力，任务专属表达负责主题与内容；
4. 图像、图形和交互只有承担信息或操作工作才进入画面；
5. 首个纵切片先验证方向，避免把错误方向扩展成完整产物；
6. 渲染审查先指出可见症状，再回溯内容、构图、素材或技术根因；
7. “少”不是目标，“每项都有工作”才是目标；高密和丰富同样可以精致。
