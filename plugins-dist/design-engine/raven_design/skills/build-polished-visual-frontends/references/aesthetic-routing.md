# 审美路由

当新建、全面重做或用户明确重视视觉方向时读取本文件。目标不是选择一个流行风格标签，而是从主题、受众、媒介和真实标杆推导可执行的视觉系统。

## 1. 锁定证据权限

只记录会改变构图、字体、色域、材质、动效或基础组件语言的证据，每项一行：`evidence_id / source_type / observed_claim / artifact / supported_axes / unsupported_axes`。`source_type` 只用 `USER_CURRENT / USER_ACCEPTED_REFERENCE / BRAND_OR_SYSTEM / OBSERVED_PRODUCTION_REFERENCE / AUTHORITATIVE_CONSTRAINT / MODEL_HYPOTHESIS`。

模型生成的 brief、视觉命题、题材联想和决策卡属于 `MODEL_HYPOTHESIS`，只能形成候选和验证计划。任何证据都不能跨越 `supported_axes`：内容主题不自动决定全局颜色，平台规范不自动决定品牌语气。只有当前实际可查看的用户已接受参考才能形成链接证据帧的 `protected invariants`。

## 2. 读取任务与主题世界

先从用户原始请求、权威材料和真实内容中提取视觉材料，不从模型派生 brief 或“常用网页模板”中寻找授权：

- **人**：谁在使用、阅读、观看或被描绘；他们的视觉素养、年龄、语言和信任要求是什么；
- **动作**：主要行为是阅读、比较、编辑、导航、学习、判断、操作还是玩耍；
- **对象**：主题世界中真实存在的工具、材料、环境、符号、文档、测量和痕迹；
- **语境**：公共服务、消费、文化、科学、工业、教育或娱乐分别允许什么语气；
- **时间**：一次传播、连续阅读、每日工作、实时反馈或长期身份需要不同节奏；
- **限制**：品牌、语言、目标环境、观看距离、数据可信度、无障碍和离线要求会否决哪些方向。
- **审美记忆**：用户本轮给出的参考，以及此前明确接受、拒绝或反复指出的视觉特征；当前要求始终优先。

提取足以区分本项目的具体名词与动作；数量由题材广度、媒介跨度和错误风险决定，不为满足格式凑词。若留下的仍只有 `平台 / 数据 / 智能 / 高效 / 探索` 等通用词，或这些词不能影响构图、内容、素材与验收，说明主题理解仍不足。

重复合作时另写两行：`继续保留的机制` 与 `明确不要的惯性`。迁移偏好和判断，不机械复用上一件产物的配色、构图或组件。

## 3. 选择真实标杆

只在新建视觉方向、大改、方向仍不确定，或媒介/受众/专业能力风险无法由用户参考与本地证据判断时，选择能覆盖风险的最小标杆组。既有方向已获接受、低风险局部修改，或当前证据足以作出决定时，不为走流程增加外部研究。一个证据充分、高度同构且可实际体验的生产成品可以独立成立；任务跨越不同媒介、受众或专业能力时才增加标杆。每增加一个都必须承担新的校准职责，当新增案例不再改变决策便停止，而不是追求固定数量。

标杆可能承担：

1. **任务标杆**：解决相似用户任务；
2. **媒介标杆**：在相同画布、消费环境或发布渠道中成立；
3. **语气标杆**：面对相似受众和信任关系；
4. **能力标杆**：证明某种交互、图形或制作技术能够成熟落地。

研究被触发时不要求各类全部出现，但必须覆盖主任务；通常至少有一个任务标杆。优先级如下：

1. 可实际操作或阅读的成品；
2. 官方产品、品牌、设计系统或设计团队案例；
3. 有生产周期、迭代或用户使用证据的公开作品；
4. 仅在缺少成品时，才使用展示站、作品集单帧或社交灵感图。

无法联网或用户禁止浏览时，从用户提供、本地合法保存或可核验的既有资料中选择；无法覆盖关键风险时如实记录证据缺口。不要凭记忆编造 URL、年份、设计机制或生产验证。

拒绝以下选法：只看配色相似；只看获奖标签；只看一张 hero；只因“像 Apple / Linear / Stripe”便引用；选择与任务不同但外观流行的案例。

每个标杆记录：

```text
fact_id / reference_id / 名称 / 来源 / 年份或版本
frame_artifact / 视口 / 具体状态
相同点：任务、媒介、受众或密度
observed_relation：从实际画面观察到的结构、层级、密度、对象、图像、色彩或交互关系
protected_axis：当前关系锁定的决策轴
supported_axes：只允许迁移的决策轴
free_axes：当前任务仍可自行决定的内容、色相、资产、交互或局部表达
non_transferable：品牌、资产、文案和不适用机制
target_object：关系将在当前产物的哪个对象、区块或状态落实
representative_frame_evidence：代表画面中的实际位置；建立合同时先写 validation target
final_frame_evidence：最后一次可见修改后的截图位置与实现对象
deviation_constraint：若偏离，记录不可通过适配解决的用户、品牌、内容、功能、许可或环境硬约束
生产证据或证据缺口
```

没有实际画面就不算视觉标杆。对产品与专业工具优先记录真实工作态、编辑态、最高典型密度和合同内
任务转换，不用 marketing hero 代替工作区证据。比较机制时隐藏品牌光环；“Apple”“Linear”或设计
奖项不能替代观察。

当模板、标杆、品牌或用户参考成为主要视觉依据时，上述字段共同组成 `REFERENCE-CONTRACT`。
合同记录 3–6 条可观察关系，至少覆盖一条宏观结构或阅读顺序、一条层级或密度、一条主对象或
图像角色；只写色彩、形容词或品牌名称不算完成。迁移的是语义关系而非字面坐标：来源中的产品
演示区可以映射为当前任务的核心比较对象，但必须保持其在阅读顺序、面积和证据角色上的对应关系。
代表画面与终态画面各结账一次；事实行没有实际像素落点且没有硬约束偏离时，返回参考或构图阶段。
风格合同若在结构、密度、底色或主对象角色上与受保护关系相反，必须先记录不可通过适配解决的硬约束；
视觉命题、题材联想和模型偏好不能自行授权偏离。

## 4. 提炼机制

不要提炼表面结果，例如“黑白配色、超大标题、很多留白”。把观察写成因果关系：

- “首屏只出现一个主要行动，因此用户无需在品牌叙述和任务入口间选择”；
- “窄图注栏固定图文归属，长正文仍能保持连续行宽”；
- “同一对象在列表、图表和详情中使用同一颜色，减少重新辨认”；
- “每段微实验只开放一个变量，旧表示继续解释下一层抽象”；
- “摄影承担现场证据，图表承担比较，二者不争夺同一视觉角色”。

每个机制必须能转成代码、内容结构、资产要求或验收动作。无法执行的形容词不进入决策卡。

同时记录非迁移项：独特品牌符号、专有字体、摄影、文案、数据、交互资产和依赖特殊组织能力的流程。

## 5. 路由视觉家族

选择足以解释画面秩序的最小视觉家族组合。单一任务通常由一个主家族即可约束；真正跨越不同阅读或操作场景时才增加方向，并写清职责。产品与工具的具体形式优先来自对象、工作面、命令和状态，不要求题材 skin 或额外标志性表达；其他家族再按领域机制决定主题表达。

| 主家族 | 适用信号 | 视觉重点 | 常见误区 |
| --- | --- | --- | --- |
| 制度与信任 | 公共服务、医疗、金融、规范、无障碍关键 | 明确语言、稳定结构、高对比、证据和下一步 | 把“严肃”做成灰色小字和僵硬表格 |
| 产品与工具 | 重复任务、对象状态、速度、错误恢复 | 工作对象优先、密度分区、反馈和可发现动作 | 模仿 Linear 外壳或堆 dashboard 卡片 |
| 编辑与纪实 | 报告、专题、文化、研究、长内容 | 作者顺序、图文证据、阅读节奏、图注归属 | 米色纸张、衬线大标题和细线报纸套装 |
| 数据新闻与分析 | 比较、趋势、不确定性、公共解释 | 图形主导、注释、尺度、来源和叙事顺序 | 把每个数字放进 KPI 卡或追求炫技图形 |
| 技术与仪器 | 工程、科学、系统状态、空间关系 | 精确结构、测量、拓扑、状态和局部放大 | 用网格、扫描线和霓虹伪装精确性 |
| 品牌与文化 | 身份、活动、消费、音乐、艺术 | 独特语气、字体、图像、节奏和识别资产 | 用流行视觉趋势取代主体本身 |
| 教学与解释 | 概念、因果、步骤、微实验 | 单一问题、操作与反馈同屏、渐进抽象 | 做成表单控制面板或功能繁多的实验台 |
| 游戏与沉浸 | 规则、挑战、世界、视听玩耍 | 场景、输入、反馈、节奏和状态转换 | 先做菜单壳，再用装饰代替核心玩法 |

Apple、Linear、GOV.UK、纽约时报等名称只能表示具体可观察机制，不得成为笼统的风格指令。写出“学习它的什么”，不要写“做成它那样”。

## 6. 确定相关决策轴

以下是用于暴露取舍的问题，不是必须逐项填写的六格表。只记录会改变实现或验收的轴；若任务有更关键的领域轴，增加它而不是硬套本表。用文字选择，不使用固定数值旋钮：

- **秩序**：严格规则 / 有控制的不对称 / 自由场景；
- **密度**：稀疏聚焦 / 中等叙事 / 高密工作；
- **对比**：安静连续 / 层级鲜明 / 戏剧冲突；
- **材质**：平面排版 / 摄影纪实 / 触感物质 / 仪器图形 / 空间沉浸；
- **运动**：静态 / 操作反馈 / 叙事过渡 / 模型时间 / 持续世界；
- **语气**：制度、克制、亲近、编辑、技术、游戏或其他可解释方向。

每个选择附一句任务理由。若两个轴互相冲突，例如“极低密度”却要求首屏完成十个操作，先修正任务或形态，不靠缩小字号硬塞。

## 7. 字体与文字

先分配信息角色，再选字体：标题、正文、操作、数字、图注、代码或地图标签不必全部不同，但必须能被辨认。

- 选择与语言覆盖、语气、观看距离和渲染环境相符的字体；确认许可、字重与实际字符覆盖；
- 中文界面优先检查标点挤压、字重真假、数字与西文混排、行高、长标题断行和高约束目标画幅密度；
- 不把 Inter、Geist、衬线体、等宽体或任一“设计字体”当默认答案；
- 不为制造趣味在同一标题中随意混用字族；优先利用同一字族的字重、宽度、斜体和尺度；
- 正文行宽通常控制在舒适阅读范围，工具界面则按字段扫描与对齐需求规划；
- 关键日期、来源、状态、单位和错误不降为浅灰微型字；层级可低，清晰度不能低；
- 离线交付使用合法本地字体或稳健系统回退，不链接远程字体。

浏览器产品界面的常见起点是正文 `16px`、持续辅助文字 `14px`；`12–13px` 仅用于少量、高对比、非关键的刻度、单位和时间戳。这不是跨媒介硬阈值，但任何偏离都要由组件系统、观看距离、密度与最终像素共同证明，不能以“专业工具需要紧凑”概括授权。字体族、字重、行高和数字样式优先沿用选定组件系统；项目外壳不得再引入一套无证据的文字语言。

在真实内容上测试最短、最长、中英混排、数字密集和错误状态，不能只看 “Aa” 字体样张。

## 8. 色彩与材质

色彩方向从证据来：用户参考、品牌、模板与标杆的章法、数据语义、环境光线、领域规范都是
合法来源。本文不规定基底该浅该深、强调色该有几个——**这些由所选标杆与模板的章法决定**；
同一个任务，暗场电影感与纸面编辑感常常都成立，按主题世界与用户偏好选，
**不要默认最安全的那一个**。真实对象的固有色可以进入对象、数据和图像，不自动染遍产品 chrome。

- 为背景、文本、强调、交互、状态和数据分别定义职责，颜色承担的每份工作都能被指认；
- 层级优先用明暗、位置、留白和字体建立；
- 统一冷暖倾向和中性色逻辑，避免组件各自带入不同灰阶；
- 语义色（成功/警告/错误）只在对应状态出现，并配合文字或图标等非颜色冗余；
- 数据和地图颜色先满足区分、顺序和色觉安全，再考虑品牌感；
- 摄影、插画与 UI 的综合色域应协调，但不要用统一滤镜抹去证据真实性；
- 阴影、纹理、玻璃、渐变和噪点只有在表达层级、材质、空间或氛围时使用；
- 在实际背景上检查文本、控件、图例和图片叠字的对比度。

### 可执行颜色角色账本

在代表性视口和关键状态中，从样式 token 与实际渲染的 DOM/SVG 计算值建立账本；归一化颜色表示，并按真实合成背景处理透明色。Canvas、WebGL、图片和无法可靠枚举的区域记录像素审查，不伪装成自动测量。

```text
token / 实际值：定义名与归一化后的渲染值
出现位置：组件、数据系列或状态，以及代表性选择器/证据帧
职责：内容层级 / 交互 / 状态 / 数据 / 环境；只能写可验证语义
非颜色冗余：文字、图标、形状、位置或纹理如何共同传达
背景与对比：实际背景、测量或像素审查方法、结果
处置：保留 / 合并 / 替换 / 删除，以及理由
```

账本必须覆盖实际出现的非中性色；中性色按背景、正文、次级信息、边界等角色归组，但仍需检查灰阶是否冲突。出现以下任一情况即失败并修正：颜色没有职责；同一值承担冲突语义；同一语义无理由漂移；状态或类别只靠颜色区分；对比证据缺失或不合格；定义 token 与渲染结果不一致。最后一次视觉修改后重新生成账本或核对差异。

## 9. 构图与标志性表达

当构图存在实质不确定性时，画足以揭示不同取舍的构图骨架再选择；变化应来自阅读顺序、对象关系和媒介，不只交换左右位置。成熟媒介已有明确结构且替代方案不会改变任务时，可以直接采用并记录理由；新增骨架不再暴露新取舍时停止。

检查：

- 第一视线是否指向最重要的内容或动作；
- 大区块轮廓在缩略图中是否清楚；
- 负空间是否形成停顿，而不是遗留死角；
- 图像、图表、舞台或工作对象是否获得与其重要性相称的面积；
- 页面是否因组件容器过多而碎裂；
- 合同内不同目标环境是否重排关系，而不是等比缩放同一构图。

只有当识别、传播、叙事、解释或玩乐价值确实需要时，才设计主导性的标志性表达。它可以是专用图形、独特的内容切换、图文关系、类型动作、模型交互或空间构图；必须承载主题，且周围保持克制。

产品与专业工具不强加装饰性“记忆点”，但存在主要工作对象时，应选择一个任务原生的精致高点：例如可精确操纵的主工作面、可信的数据视图、清楚有触感的时间/版本导航，或令人安心的状态转换。它必须直接提高判断或操作质量，使用与组件系统一致的字体、颜色、几何和反馈，其余 chrome 保持安静。治理、比较或标准系统若没有合适高点，可以由准确对象结构与高效行为形成辨识，并记录 `N/A + 原因`。

## 10. 审美决策卡

编码前记录会改变实现或验收的字段；不适用项写明原因或省略，不为形成完整卡片填充固定数量：

```text
证据与假设：evidence_id、支持轴、受保护不变量、证据缺口和 MODEL_HYPOTHESIS
视觉命题与机制：第一视觉、最小视觉家族和可落到实现/验收的因果规则
系统：选定组件库的真实样张与受保护属性；字体、色彩、密度、圆角、边界、图标、反馈的 token 映射和必要例外
素材：主题材料、可迁移机制，以及不得复制的品牌和资产
表达：领域确需时的标志性表达；产品与工具的任务原生精致高点，或 `N/A + 原因`
舍弃与风险：主动删除的惯性方案，以及必须由渲染验证的取舍
```

## 11. 编码前反驳

像反对自己的提案一样问：

1. 是否把模型假设当成外部证据，或让证据越过其支持轴？
2. 是否复制标杆外观而非机制，或增加了不承担任务的元素？
3. 是否为了“项目个性”重画成熟基础组件？
4. 最醒目的视觉资产是否位于最重要的信息处？
5. 用户偏好、受保护不变量或领域约束是否被模型趣味覆盖？
