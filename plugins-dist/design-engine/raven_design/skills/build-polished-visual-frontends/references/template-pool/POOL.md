# 模板池(人工预筛,v7 主视觉先行,2026-08-26)

有网环境下,内容型/营销型 Web 任务优先从本池选真实模板作骨架,再深度定制。入池门槛是
已完成人工视觉筛选,且使用 MIT/Apache 系许可、活跃维护与可查看 demo。池表负责查找候选,
候选截图才是结构、层级、图像角色与色彩关系的事实源;名称、题材标签和本表短注不替代看图。

## 第零步:把任务翻译成形态(选模板前必做,不许跳过)

池表按**页面形态**组织,任务却按**题材**下达——"对比""档案""课程"这些任务词不会
原样出现在形态列里。**禁止拿任务字面词查不到就判"池内无匹配",也禁止凭感觉自创归类**。
翻译只回答两问:

1. **页面的主对象是什么?** 一个要说服人接受的东西 / 一批同构条目 / 一组要通读的文字 /
   一棵要查询的知识树 / 一个人或机构的身份 / 一次线下体验。
2. **读者带着什么目的来?** 做决定 / 浏览检索 / 沉浸阅读 / 带着问题查找 / 认识某人 / 感受气氛。

两个答案对进下表,任务就是那一行的形态;内容型 web 任务必落其一:

| 形态 | 判定(主对象 × 读者目的) | 题材落点(举例,开放式) | 池内选择 |
| --- | --- | --- | --- |
| **叙事落地页** | 主对象是**一个**要被接受的东西(产品、公司、活动、主张或一次明确决定);读者来**做决定**,页面一屏一幕推进到行动 | **产品主页/公司官网主页**、SaaS、开发者工具、API、App、硬件、开源项目主页、创业公司、功能特性页、活动/发布会、预售 waitlist、非营利/公益倡议；对比任务只有在读者意图确为 `decision_support` 时落入本行，neutral comparison、benchmark report 与 editorial analysis 按其真实主对象另行归类 | 科技暗色 Tailcast;数据浅色 DataNova;工业机械 ScrewFast |
| **编目页** | 主对象是**一批**同构条目(编号/字段/图位);读者来**浏览与检索**;单条目的详情页是它的详情面 | 档案馆、博物馆藏品、收藏库、名录、商品目录、单品详情页、展览、图库、播客/剧集列表、食谱集、职位列表 | Atelier Kō——条目语义随题材替换;条目缺的字段可裁版式,缺图则按真实性边界生成(禁止冒充档案照片,也禁止秃页) |
| **编辑页** | 主对象是要**从头读到尾**的文字;读者来**沉浸阅读** | 杂志、深度文章、随笔、评述、报道、图文专栏、客户案例/case study、时间线叙事、城市/旅行指南 | Quiet Pages(杂志感);Keel(单篇结构主义) |
| **文档/知识库** | 主对象是**一棵知识树**;读者**带着问题跳读**,靠侧栏与搜索 | 产品文档、手册、教程集、Wiki、FAQ/帮助中心、课程讲义 | Starlight |
| **人物/机构主页** | 主对象是**一个身份**及其产出列表 | 学者、研究组、实验室、课程主页、院系/机构门户;设计师/开发者作品集、个人简历页 | 学术侧 Scholar Pages;作品集 bento(个性) |
| **氛围体验页** | 主对象是**一次线下体验**;读者先**感受气氛**,再找动线(预约/地址/菜单) | 餐厅、酒吧、咖啡、工作室、诊所、民宿/酒店、婚礼/活动邀请、空间与室内设计 | Ombra |

两条边界:

- **交互应用不进池**:计算器、编辑器、游戏、数据浏览器、仪表盘——主对象是"操作"而非内容,
  模板池不适用,按 SKILL 常规选型。
- `observed_benchmark` 不是自由出口。只有池中没有该形态候选,或逐张查看后每个候选均违反
  已声明的用户、品牌、内容、功能、许可或环境硬约束,才可进入文末标杆路线。色相偏好、气质、
  实现便利、学习成本、clone 失败或想手写均不构成不匹配。

## 选型与使用规则

1. 完成第零步翻译后,按形态取 1-3 个候选;**用 read_file 看候选截图**(本目录 `<slug>.jpg`),凭真实观感定夺。
2. 获取:`git clone --depth 1 https://github.com/<repo>`(经环境 HTTP_PROXY;克隆后核对 LICENSE)。
   **环境的 toolchain/runtime 锁定指的是预装档位,不构成"禁止克隆模板";能出网即可外采。**
3. 翻译结论、`reference_route` 与 `implementation_base` 写进 DESIGN-BRIEF。选定模板后按
   `aesthetic-routing.md` 建立 `REFERENCE-CONTRACT`:3–6 条可观察关系至少覆盖宏观结构／阅读顺序、
   层级／密度、主对象／图像角色;每条写来源帧、允许迁移轴、实现落点、代表帧与终态证据。
   色彩只是其中一条,不能代替完整合同。手写骨架只改变实现方式,不产生新的视觉路线。
4. **图槽不是资产计划**：示例内容与占位图全清。锁定 `REFERENCE-CONTRACT` 后，按 SKILL 先写
   `VISUAL-THESIS`、`MASTER-VISUAL-CONTRACT` 与 `asset_family_plan`，取得并查看母版，再围绕成图
   改造模板；主要页面族默认由同一视觉家族的大背景主导开场。母版稳定后按需用 image edit 派生
   章节视觉、局部背景和表现型 icon。生成图承担世界、氛围与质感，真图、代码或专业图形承担事实
   与精度；真实性边界和页面说明仍按 SKILL 的图像来源纪律处理。
5. **色彩关系**:模板的强调色数量与出现位置、底/文对比、饱和色面积占比作为合同的一条关系
   继承,具体色相按任务重定。模板默认品牌色原样交付和铲平关系后自由配色都算失败。字体按
   SKILL「字体选型」显式选型,
   禁止裸用系统兜底链。图像档位纪律见 SKILL「图像来源纪律」。
6. 外采来源记入 THIRD_PARTY_NOTICES(URL + 许可)。

## `observed_benchmark` 路线

通过前述硬约束 gate 后,查看能覆盖主要任务风险的少量真实生产页面;一个高度同构且证据充分的
标杆可以独立成立,不同标杆只补主要参考未覆盖的风险,不得拼成多头视觉语法。每项保存实际来源帧,
按 `aesthetic-routing.md` 写同一份 `REFERENCE-CONTRACT`,再用最薄实现底座承载合同。只写
"参考 Apple/Stripe/MoMA/Tate"或"记录结构与气质"不算完成;每条关系必须在代表帧和终态帧有
实际像素证据。真实标杆只迁移任务关系与视觉机制,禁止复刻品牌、文案、专有资产和签名构图。
