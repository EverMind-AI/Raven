# 素材与图像生成

当产物需要照片、插画、纹理、图标、字体、音频、视频、三维模型或生成图像时读取本文件。目标是让素材承担内容工作，并保证来源、许可、离线和视觉一致性。

## 1. 先写素材任务

先定义整页的图像角色，再列出素材槽位，不先搜“好看的图”。主视觉、证据图、章节图、转场图、表现型
icon 和精确图形的职责不同；不得先从模板图槽反推页面需要什么资产：

| 角色／槽位 | `semantic_job` | 与哪两个非图像系统关联 | 尺寸/裁切 | 真实性要求 | 生产路线 |
| --- | --- | --- | --- | --- | --- |
| 例如主视觉 | 建立具体场所并说明人物关系 | 标题构图 + 导航／运动 | 目标画幅，有文字安全区与稳定焦点 | 不作为事实证据 | `generated_visual` |

素材可承担：

- 证明人物、地点、物件或事件；
- 解释结构、关系、尺度或时间；
- 让用户识别对象、状态或行动；
- 建立品牌身份或领域语气；
- 控制阅读节奏和情绪转场；
- 构成游戏、仿真或沉浸场景的核心世界。

如果一项素材只用于“填空、显得高级、增加科技感”，删除它。不要让同一画面中的照片、插画、图标、图表和纹理同时争夺主角。

## 2. 真实性优先与生产路线

真实对象、品牌、人物、档案、产品界面或事件有合法真实资产时，在同一 `semantic_job` 内按以下顺序采用。
事实证据图不会自动取消主视觉、转场图或表现型 icon 的独立语义工作：

1. 用户提供且授权使用的资产；
2. 官方品牌、机构、产品或数据源提供的合法资产；
3. 有明确许可和作者信息的照片、插画、图标、字体或模型。

需要新建资产时，不再用一条来源阶梯混淆审美绘制与精确绘制；每个槽位只选一个 route：

| route | 适用对象 | 默认生产方式 |
| --- | --- | --- |
| `truth_asset` | 真实产品、品牌、人物、档案、界面与事件 | 上述合法资产或真实截图 |
| `standard_symbol` | 搜索、关闭、菜单等标准操作 icon | 既有设计系统或一个成熟 icon 家族 |
| `generated_visual` | hero、场景、插画、纹理、物件、表现型 icon 与 feature pictogram | `image_generate`，系列变体用 image edit |
| `exact_graphic` | 数据、文字、坐标、拓扑与操作状态决定的图表、地图、技术图形 | 专业库、数据驱动 HTML/Canvas/SVG renderer |

成功依赖构图、画风、材质、光影、有机形体或系列一致性的资产，必须走 `generated_visual`；
成功依赖字符、数字、坐标、拓扑、操作语义或多尺寸精确复用的对象，走真实资产、成熟库或专业
工具。不存在 `manual_svg`、`decorative_css` 或 `placeholder_as_final` 路线。

不要从搜索结果、社交媒体、设计案例或标杆网站直接下载素材进入交付。用于内部研究的局部帧与最终产物资产必须分开存放。

保存第三方资产前确认：作者/机构、来源 URL、许可证、允许的修改与发布方式、署名要求、获取日期。证据不足时视为不可交付。

## 3. 何时使用图像生成

满足以下条件时优先考虑：

- brief 的核心需要具体人物、场所、物件、氛围或原创视觉世界；
- 用户没有可用资产，授权素材又无法准确表达；
- 结果能够以目标比例生成并接受人工像素检查。

无真图可用时，**真实性边界清楚并完成 provenance 的生成图是内容型页面的默认选择**——“怕不
真实”不是留白的理由，生成图随时可以被更好的图替换。具体页面处理只按下表决定，不用制作过程
标签证明诚实：

| 图像职责与风险 | 成品页面处理 |
| --- | --- |
| 纯氛围、世界构建或视觉身份，不邻接事实 claim | 只记录 provenance，不展示制作过程 |
| 邻接真实人物、档案、事件、客户或产品状态，普通读者可能把它当作证据 | 用内容语境说明其性质与边界 |
| 说明后仍会造成事实误认 | 不使用该生成图 |
| 真实或官方资产 | 按内容需要显示来源、权利或图注，不混入生成说明 |

**质感门槛(这一类必须用生成,手写模拟即违规)**:

判据一句话:**如果描述这张图离不开材质与光影的词——金属、玻璃、雾、体积光、景深、反射、颗粒、渲染——或者它在真实世界里要靠摄影或三维渲染才能得到,这张图就必须用图像生成工具产出。**CSS 渐变、发光弧线、`box-shadow` 光晕、抽象几何 SVG 手写模拟不了这一档质感,做出来就是图鉴 D 组(发光暗卡)的病体。

典型场景:

- 硬件/芯片/设备的渲染感 hero 背景(体积光+金属材质那一档);
- 产品效果大图（旗舰硬件发布页那种摄影级渲染）；
- 品牌标识的**质感呈现稿**——金属拉丝、玻璃、浮雕、刻字上墙的效果图(logo 本体仍必须矢量精确,遵守第 6 节图标纪律;质感 mock 是生成的正当用途);
- 氛围图、场景图、材质纹理。

反向自检:手指落到 `radial-gradient`/`blur`/发光滤镜去"营造高级感"之前停一下——你是不是在手写模拟一张本该生成的图?是,就去调图像生成工具;工具不可用或调用失败是能力缺口,不授权改用手写 SVG、CSS 或 Canvas 装饰。

**主则：内容型／营销型 Web 先取得主视觉，再围绕真实成图排版**。“有一张生成图”只是能力送达证据，
不是视觉质量证据。代码绘制只承担需要精确数据与精确文字的图表；主视觉与配图不冒充证据。

### 主视觉母版与页面族角色

在写页面 DOM、布局 CSS 或改造模板版式前，从 `VISUAL-THESIS` 写一张主视觉素材 brief，调用
`image_generate`，再以原尺寸查看成图。母版成图先于页面版式，模板图槽不是母版。每个主要页面族
在布局前填写 `page_family / opening_job / visual_role / asset_lineage / reason / final_evidence`；
`visual_role` 只用 `dominant_background / integrated_visual_field / content_first`，默认第一种。
`integrated_visual_field` 与 `content_first` 只对当前页面族成立；文字多、包含事实、没有真图、担心误认或担心可读性
不能单独构成选择它们的理由，也不能批量取消其他页面族的大背景。如果最终像素表明大背景妨碍了阅读，调整文字大小或
位置，或重新生成背景，而不是放弃大背景。页面族可复用有意义的裁切或用 image edit 派生，不要求每个内容实体重新生成。

主视觉必须：

- 承担 `world_builder / identity_carrier / narrative_stage` 之一，并写明它独自建立的语义；
- 选择 `dominant_background` 时，在无需滚动的开场画面可见，是最大的非文字视觉场，不被装入普通
  卡片或孤立图槽；其他角色必须与结构或主要内容形成不可随意拆换的关系；
- 在生成前指定视觉中心、空间层次、文字安全区、对比、各目标画幅的裁切锚点和真实性边界；
- 不烘焙关键文字、logo、数据、产品界面或事实证据；
- 盲裁会破坏焦点、人物或文字安全区时，以主视觉为输入用 image edit 派生专用画幅，不靠 `object-fit`
  硬裁挽救；
- 成图中的色域、光线、边缘、材质和空间节奏至少映射进排印／规则、内容结构、交互／运动中的两类，
  不让项目身份只存在于一张图。

主视觉进入代表画面并稳定后，才生成章节题图、spot illustration、纹理、key visual 和表现型
icon。同系列子素材默认把主视觉或家族母图作为 image edit 输入，继承形体、视角、光线、材质、色域与背景处理。
若直接编辑会破坏小尺寸语义，先产出同命题的家族母图再派生；不用互不相关的新 prompt 分别抽卡。

**正当用途谱系（内容型页面按需取用，不限于此）：**

- 氛围与场景：hero 背景、章节题图、题材配图（菜品/空间/商品/藏品等）——视觉语言按主题世界与标杆章法定，本表只列用途；
- 质感与底纹：纸纹、噪点、布纹、石材等材质底，替代平色与 CSS 渐变；
- 插画：spot 插画（空状态、404、onboarding、feature 区）、年代感与历史题材画面——画风
  为任务重定，不用图鉴 D 组默认插画腔；
- 图标与图形：装饰性质感 icon、插画式 pictogram、品牌 key visual 与 pattern 纹样走生成；
  标准 UI 功能小图标走一个成熟家族；正式 logo、公共／安全符号与品牌母版走权威资产或对应
  专业工具，生成只可用于草图和质感 mockup；
- 人物：虚构角色与示例头像——在 provenance 记录虚构边界；若所在内容可能被理解为真实客户或
  真实背书，再在页面用内容语境内的短说明消除误认；
- 周边：OG/社交分享图、设备场景底图（屏幕区留空或叠真截图）；
- 编辑与变体：`image_generate` 传入 `images` 即编辑已有图——真图的扩图/清理背景/统一
  色调影调，生成图的迭代修改与同风格变体（一批卡片图用同一底图变体保持家族感）。

**纪律（不是禁区，是做对的方式）：**

- 唯一红线是冒充：每张生成图都在来源清单记录 route、lineage、生成／编辑范围和真实性边界，
  不冒充实拍、截图、档案照片、真实人物或真实背书；成品页面按第 3 节决策表处理；
- 生成图上的文字字符可靠性有上限：关键文字由代码重排或逐字核对（见第 8 节）；
- 数据精度归代码：图表、地图边界、可核验数据由代码从真实数据绘制，生成图承担氛围与
  质感底，不承担数据。
- 每项 `generated_visual` 必须有成功工具调用、原图查看、最终文件引用和生成／编辑范围记录；
  文件只生成未上页、只在 brief 声称使用或用占位图完成代表画面均不算送达。

若用户明确要求生成或编辑图片，遵循环境中的图像生成工具流程。不要用 CSS 形状或临时 SVG 冒充用户要求的图像生成结果。

## 4. 生成前的艺术指导

先写一张素材 brief：

```text
作用：该图帮助用户理解或感受什么
主体：具体人物、物件、动作与关系
场景：地点、时代、天气、环境细节
视角：机位、焦段感、距离、构图重心
光线：方向、时间、硬软、动态范围
材质：画面里真实存在的表面与物件
视觉语言：纪实摄影、编辑插画、模型、拼贴等
版面接口：比例、留白方向、安全裁切、叠字区域
真实性边界：哪些细节不能伪造或夸张
排除项：最可能出现的俗套、错误与无关元素
```

让艺术指导来自 `VISUAL-THESIS` 和已查看的参考画面，而不是在提示词中堆叠“8K、award-winning、cinematic、premium”。质量形容词不能替代主体、动作、光线和版面用途。**档次锚点用真实参考图**：传入真截图或标杆画面并写明其角色（仅作设计语言参考 / 忠实复刻蓝本），一张对的参考图胜过十条风格形容。

需要同系列多图时，先确定一致的镜头、光线、材质、人物或插画规则，再逐张生成。不同章节可以改变距离和构图，但不能像来自不同素材网站。

至少按最终槽位比例生成，不依赖大幅裁切挽救构图。合同内目标画幅需要差异明显的裁切时，优先
生成或编辑独立版本，不自行扩张目标环境。

## 5. 生成后的像素检查

使用图像查看工具检查原始分辨率，而不是只看页面缩略图：

- 人脸、手、牙齿、眼镜、首饰、肢体连接和人物数量；
- 文字、品牌、仪表、屏幕、标牌和数字是否出现乱码或虚假信息；
- 透视、阴影、反射、物件连接、重复纹理和背景人物；
- 边缘、发丝、透明物、景深和不自然锐化；
- 主题是否准确，是否落入泛化的“科技城市、几何人物、豪华办公、漂浮设备”；
- 目标裁切中焦点、留白和叠字区域是否成立；
- 与其他素材、字体、页面颜色和实际内容是否协调。

发现结构错误时重新生成或局部编辑，不用缩小、模糊、遮罩和深色叠层掩盖。只有色温、裁切或轻微灰度问题才适合后期统一。

将图片放入最终页面后再次检查：页面上的缩放、`object-fit`、遮罩、目标画幅裁切和对比可能制造新的缺陷。
主视觉还必须完成两项页面级检查：

- **替图测试**：若换成任意同题图库图后，版式、token、边界和细节都无需变化，返回主视觉母版；
- **家族测试**：主视觉、章节图、纹理和表现型 icon 在缩略图下仍像同一项目；只靠相同色相不算家族。

## 6. 不同素材类型

### 摄影

- 纪实任务优先真实授权照片；生成照片不得被描述为真实现场；
- 选择能证明人物、地点、过程或尺度的瞬间，不用泛化握手与办公照；
- provenance 说明图像角色和来源；页面图注只在内容需要或为避免事实误认时出现，不能让氛围图
  看似数据证据，也不能把制作过程印进成品。

### 插画与场景

- 先定义形体、空间、光线和叙事动作，再定义风格；
- 角色、笔触、线宽、材质和透视形成统一系统；
- 不用简单几何人物替代需要真实情绪或文化语境的场景。

### 图标

- 一个项目只使用一个主图标家族；标准功能 icon 优先复用既有系统，没有时选择一个成熟家族，
  不得自行补画近似 SVG；
- 领域独有、插画式、空间化或有材质表现的 icon 整组使用 `image_generate`：先生成家族母图，
  再以 image edit 派生变体，保持视角、形体、光线、材质和背景处理一致；
- 生成 icon 不烘焙关键文字、logo 或数字，语义名称与无障碍文本由宿主代码提供；若合同必须
  交付矢量，只能使用专业矢量化／图标工具从已生成母版转换，不得由模型手工描 path；每个变体在
  最终显示尺寸检查轮廓、透明背景与家族一致性；
- 不把 emoji 当正式控件图标；不混合实心、线性和不同透视体系。

### 图表、地图和技术图形

- 由真实数据、坐标或关系生成，保持可编辑结构；
- 数据证据、地图边界与电气/机械连接由代码从真实数据绘制；生成图可作其氛围底与配图，
  不承担数据精度；
- 输出 SVG/Canvas 时仍提供必要文本替代、来源、单位和说明。

### 字体

- 验证许可、中文/多语言字符、数字、标点、字重和可变轴；
- 离线自托管时保留许可文件或来源记录，并用 `font-display` 与系统回退；
- 不从标杆网站提取专有字体，也不把字库子集错误当完整字体。

### 动画、音频与三维模型

- 确认许可、解码格式、加载体积、循环边界和降级策略；
- 动画必须有静态或 reduced-motion 表达；音频必须可暂停并有状态提示；
- 三维模型检查拓扑、材质、光照、相机、加载失败和无 WebGL 回退。

## 7. 整页蓝本与界面展示图

图像生成可以产出整页设计蓝本（landing、报告页、海报的完整视觉稿）与产品界面展示图。这类产出的价值在已锁定参考合同内探索布局、媒介与节奏——不在文字；它不能覆盖 `REFERENCE-CONTRACT` 或成为绕过模板／标杆路线的第三条视觉来源。规则：

**Brief 写法：四定四放。** 锁死模型会编错的，放开模型比你强的。

- **定档次**：给一个具体参照（真实标杆截图当参考图，其次是公认标杆的名字与气质词展开）；
- **定事实**：产品一句话 + 事实白名单（放权写作的部分只许提及白名单内的事实，禁数字、价格、专名编造）；
- **定食材**：必备元素清单（标语、截图、CTA），每项只说 what，呈现方式交给模型；
- **定底线**：不超过三条硬约束（文字正确、内容不编、禁真人图库照）；
- **放**仅限 `REFERENCE-CONTRACT.free_axes` 中明确列出的布局局部、媒介、色相、光影或节奏；
  宏观结构、主对象角色与阅读顺序已被合同锁定时不得重新放权，沉默不等于放权。

**界面展示图走三层锁**：画布 = 真截图；组件样式 = 真图中可指认的词汇表；唯一可理想化的层 = 数据（把空态填成理想工作态）。禁止发明画布里不存在的面板、控件与布局。

**蓝本审美，代码正字**：蓝本上的文字一律视为不可信（长专名与时间戳是高发错位区），最终页面的每个字由代码从事实源逐字重排；蓝本直接上页时必须逐字核对全部文字并把核对记录写入图像来源清单。

**生成即核对**：整页蓝本生成后按第 5 节做像素检查，另加逐字扫描（品牌名、数字、标点、简繁体）；发现错字，蓝本用途降级为布局参考。
