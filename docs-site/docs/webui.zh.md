# 启动 WebUI

通过 Raven WebUI，你可以在浏览器中与 Agent 对话、协同处理任务并管理工作区。
在同一界面中跟踪任务进度、查看文件和输出，以及浏览记忆与技能。

```bash
raven web
```

该命令会在浏览器中打开 WebUI，并在后台启动 Raven。关闭浏览器后，Raven 仍会继续运行。
如需停止服务，请运行 `raven web --stop`。

## 轨迹视图 { #trajectory-view }

当会话有内容后，聊天页头部工作区面板按钮的左侧会出现轨迹切换按钮。轨迹视图按时间列出该会话的每一步
（输入、模型调用、工具调用、回复）及其耗时，可打开任意一步的详情，并在列表上方绘制耗时构成条。

## 导出与问题报告 { #export-and-report-a-problem }

聊天页头部右上角的三点菜单（desk 启动器在它左侧）作用于当前打开的会话。还没有任何内容的新任务上，菜单不可用。

**导出**：把你选中的轮次打成一个 `.tar.gz`，由浏览器下载。一轮会连同它派发的子代理一起导出；仍在进行的轮次不能选。导出前可以修改文件名。

!!! warning
    导出的是原始轨迹，没有脱敏，可能含密钥、令牌等敏感信息，请妥善保管。

**问题报告**：只有 Raven 有可发送的问题报告服务器时才出现（`RAVEN_BUGREPORT_URL`，或内置的默认地址）。它是
`raven trajectory report-bug` 的网页版本：选轮次、填写问题、对脱敏扫描不确定的值逐一决定（脱敏历史已全部决定时跳过这一页），
然后上传并拿到回执号。这一页上的所有决定，包括"全部保持"和批量按钮，都会以 `web` 为来源记入脱敏历史。
在开始上传之前关闭向导，会丢弃正在准备的报告。一旦开始上传，报告就会保存到本机：上传失败时，被标为可重试的失败会提供"重试"；
无论哪种情况，都可以用页面上显示的报告编号，稍后通过 `raven trajectory upload-bug-report <id>` 发送已保存的报告。背后的流程见
[轨迹调试](trajectory-debugging.md#produce-a-reviewed-report)。

## 导入会话 { #import-a-conversation }

左侧菜单"新任务""连接"之下的**导入会话**，用来打开从另一台机器（或另一个 Raven home）带来的包并查看。
在浏览器里选择文件后，文件会上传给 Raven，所以本机和远程打开 WebUI 都能用。单个文件上限 100 MiB；
同一时刻只进行一个导入，导入进行中再发起会提示稍后再试。

可以导入三种包：三点菜单"导出"得到的包；问题报告包（来自**问题报告**或 `raven trajectory report-bug`）；
`raven trajectory report` 生成的轨迹报告。其他文件会被拒绝并给出提示。损坏或不安全的包（路径跑出包外、链接、
解压后超过上限等）会被拒绝，不留下任何文件；会话记录过大、无法打开的包（超过 32 MiB 或 5 万条）同样会被拒绝。
由更新版本的 Raven 生成的包会提示先升级。

导入的包保存在 Raven home 下的 `imports/` 目录，重启后仍在，不会进入工作区的会话目录。再次导入同一个包时，
会提示它已导入为当前的标题，并提供**打开已有**和**仍然导入一份**两个选项。

导入的会话列在"最近"之下的**导入**分组中，没有导入时不显示这一组。导出包以原会话的标题命名（原会话没有标题时用第一条用户输入），
问题报告包以问题描述的第一行命名（没有时用报告编号），轨迹报告以原会话的标题命名（没有时用报告自身的编号）。
悬停在条目上会显示它来自哪个文件。悬停或右键只有**重命名**和**删除**两项；删除会同时删掉本机保存的那一份。

导入的会话是只读的：阅读方式与普通会话相同，轨迹视图照常可用，长对话的模型输入也能完整查看。不同之处在于：
没有输入区；不能在聊天页头部修改标题（请在侧栏重命名）；回复没有"分叉"；不显示三点菜单和工作目录标签。
包里没有的内容（子代理自己的会话记录、附件与交付文件、任务编排记录、生成的图片）显示为不可用，而不是报错。
问题报告包中的 `[REDACTED:...]` 占位按原样显示。

导出包没有脱敏，导入别人的导出包就等于拿到了它的原始内容，请同样妥善保管。

安装及模型服务商配置请参阅[快速开始](quick-start.md)；Docker 和源码部署请参阅
[自托管](self-hosting.md)。
