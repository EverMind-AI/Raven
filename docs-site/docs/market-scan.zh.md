# 市场扫描

回答「这个市场里有哪些玩家、各自怎么收费」的研究轮次，困难的部分已经做完了：它读了
各家厂商的页面，并写出了对比表。但它**没有核对**过——没有核对每个价格是否来自本次
运行真正打开过的页面，没有核对这些页面的条款是否允许这样的用途，也没有核对表里断言
的事实是否就是页面上写着的。

市场扫描就是那一步核对，而它产出的东西：一张每一项事实都能追溯到本次运行真正打开过
的页面的表。

本页描述 `research_flow/market/` 包与 `research_flow/gates/market_scan.py` 闸门。
以下均为经过验证的行为。

## 一次扫描由什么构成 { #what-a-scan-is-made-of }

一行是一家厂商，一个单元格是一项事实，一个页面是这项事实的出处：

```
| 公司 | 做什么 | 价格 | 读自 |
|---|---|---|---|
| Acme | 按席位销售的可观测性平台 | 每席位每月 $49 | [acme.example](https://acme.example/pricing) |
```

字段名会被规范化（`做什么` 变成 `what_it_does`），这样同一张表在扫描自己的准则眼里读
起来是一样的——准则写的是 `price` 这样的名字，并不关心报告印的是「价格」。

**来源没有说明的事实是「没有」，而不是「有但为空」。** 有但为空的字段是一次没有出处
的主张，扫描会拒绝它。引用了**两个**页面的事实单元格没有唯一的页面，扫描同样拒绝，
而不是替它挑一个。自身不带页面的单元格会退回该行的来源列；若那一列也没有，它就被
丢弃。

## 六种拒绝 { #the-refusals }

六种，全部是机械的：

| 拒绝 | 含义 |
| --- | --- |
| 字段没有出处 | 这项事实背后什么都没有 |
| 来源条款不允许该用途 | 注册表没有为这个来源放行这个用途 |
| 运行从未打开过的页面 | 主张引用了本次没有读过的东西 |
| 无法标注日期的字段 | 有出处但没有取回时间的事实无法被复查 |
| 为别的用途放行的字段 | 条款问的是另一个问题 |
| 没有写明来源的出处行 | 谁的条款管辖这个字段，并不知道 |

条款是查**与记录库和 Web 工具同一份注册表**，用的是运维人员真实的 opt-in 记录——
因此为一个来源记录过的许可，在各处都是同一份许可，而不是每个调用方各持一份副本。

## 三道闸门 { #the-three-gates }

每一道都可以单独关闭，因此一次对比可以把差异归因到被改动的那一道，而不是没动的那些。

**机械闸**只判通过与否，且不花模型调用。它复查扫描本身，并在报告里找仓库自己的审计
所指出的那四个机械缺陷。它沿用那份审计的严重度划分：硬缺陷让它失败，软缺陷被记录但
不阻塞。

**充分性闸**拿扫描去对照**取数之前就声明**的准则。准则是运维人员的配置，在闸门构建
的那一刻读取——也就是在本轮取任何东西之前。该闸门把这份声明的时间戳与运行的第一次
取数做比较，并**拒绝在页面读完之后才写下的准则**：事后写下的准则描述的是答案，而不是
对搜索的要求。

**裁判**最后运行，用的是便宜模型（`claude-haiku-4-5`），因为它只是读一份报告、回答一个
问题，贵模型该用在正事上。它会与第二次阅读做对照——那一次把厂商的顺序倒过来：
**裁判的裁决若随顺序改变，它反应的是呈现方式而不是内容，闸门会因此失败。**

裁判失败时放行——没有裁决的扫描，读者照样拿得到。另外两道不放行，因为没能执行的
检查不是通过。

## 停止策略的三个数字 { #the-stop-policy-s-numbers }

说出「够了」的那条规则，用三个数字汇报，彼此分开：

| 数字 | 含义 |
| --- | --- |
| 准确率 | 停止决策中正确的比例 |
| 精确率 | 在它说「停」的时候，正确的比例 |
| 期望校准误差 | 它的自信与它正确的频率之间差多远 |

**闸门盯的不是准确率。** 抬高准确率最省事的办法是多喊停，而那会拿精确率去换——所以
精确率或校准误差一旦回退，闸门就失败，哪怕准确率持平甚至更好。从不喊停的策略没有
精确率可报，而说「没有」与报「零」不是一回事。

## 什么会发出，什么不会 { #what-ships-and-what-does-not }

闸门通过时，扫描**替换掉答案**。否则本轮自己的答案仍然成立，而备注会写明是哪一道闸
门说了不——于是「这一臂没有发出市场扫描」与「这一臂的市场扫描被拒绝」始终是两回事。

随包发布的配置档标签带着这一级：
`dr@3.7-filetools-askuser-derive-numeric-cite-rank-tiers-plain-high-reader-market`。
前一个标签已在本产品自己的后继表里退役，而它正是去掉市场这一级的那一臂——做消融的
运维人员会被指向那里。

**尚未测量的部分。** 写下这一级时依据的准则，要求与基线做一次配对比较并通过 2σ 闸门。
目前没有可供配对的基线，也没有哪一批实况运行跑过这道新的闸门：链路上已有的证据是测试
harness，而不是一次实跑。**已被验证**的是能力本身——这些拒绝在测试下站得住，而仓库
自己的审计对一次真实研究运行构建出的扫描，没有报出任何硬缺陷，也没有报出任何软缺陷。

## 配置 { #configuration }

```json
"market": {
  "enabled": true,
  "use": "competitive_brief",
  "minEntities": 3,
  "minSourceHosts": 2,
  "requirePriceForAll": false,
  "mechanical": true,
  "sufficiency": true,
  "judge": true,
  "positionSwap": true
}
```

`minEntities` 与 `minSourceHosts` 是要求而不是偏好：后者存在，是为了让只扫一家厂商自家
站点的结果不会被误当成一个市场。发布切片里 `requirePriceForAll` 是关的，因为某家厂商
不公布价格，是关于这个市场的事实，而不是调研没做完。
